# 정보관리기술사 학습 로드맵과 일별 체크리스트

**상태: 계획만 준비됨 · 실제 수업 시작 전.** 1일차는 첫 실제 수업을 시작하는 날입니다. 아직 시작일, 수행 시간, 제출 답안, 회상 결과는 확인되지 않았으며 아래 체크는 모두 미완료입니다.

- 진행: Codex의 설명·힌트·첨삭과 학습자의 직접 회상·답안 작성을 병행합니다. 하루 계획은 실제 학습 3시간이며 중간 휴식은 별도입니다.
- 표기: 1일차부터 **휴식일을 포함한 경과일**입니다. 매주 5일 학습하고 이어서 2일 쉽니다. 실제 시작일은 첫 수업에서 [진도 기록](progress.md)에 남기되 시간표에는 특정 날짜를 미리 넣지 않습니다.
- 근거: [사용자 요청과 선택](../raw/requests/2026-11-09-roadmap-timetable.md), [기존 학습 전략](../wiki/comparisons/study-strategy.md), [정규화 파일럿 수업안](lessons/normalization-pilot.md). 아래 주제의 순서는 초기 진단을 위한 강사 계획이며 출제 빈도 순위가 아닙니다.

## 체크하고 다음 활동으로 가는 방법

1. 학습자는 “1일차 시작해줘”라고 말합니다. Codex는 이 문서와 진도 기록을 읽고, 실제 경과일·미완료 활동을 확인한 뒤 현재 활동을 안내합니다. 첫 수업에는 목표 회차·응시자격 확인 여부·주력 분야·경력 연수 등 아직 모르는 사항을 확인하되 답을 수업 시작의 조건으로 삼지 않습니다.
2. 활동을 실제로 마치면 학습자가 대화로 알려 주거나 답안을 제출합니다. Codex는 확인 가능한 제출물 또는 **사용자 수행 보고**를 구분해 해당 `- [ ]`를 `- [x]`로 바꾸고 다음 활동을 안내합니다. 사용자가 실제로 보고하지 않은 시간과 결과는 적지 않습니다.
3. 체크는 **수행 여부**입니다. 정확성·숙련도·점수와 별개이며, 오답은 첨삭과 복습에 남깁니다. 작성만 보고된 미제출 답안에는 채점하지 않고, 실제 제출과 첨삭이 필요한 항목은 처리될 때까지 미완료로 둡니다. 평가할 문제는 답안 제출 전에 훈련용 기준을 공개합니다: 요구 충족 25점, 기술 정확성 30점, 논리·구조 20점, 적용·판단 15점, 표현·도식 10점. 공식 채점 기준이 아닙니다.
4. 그날 필수 체크를 모두 마치면 해당 계획을 완료로 표시합니다. 막히면 언제든 설명이나 힌트를 요청할 수 있습니다. 사용자가 보류를 원하면 미완료 체크를 유지하고 보류 사유를 남긴 뒤 선택한 다음 활동을 안내합니다. 보류한 날을 모두 완료한 것으로 표시하지 않습니다.
5. 체크만으로 시간이 지난 것으로 처리하지 않습니다. 다음 날 계획은 미리 볼 수 있지만 경과일과 예정된 휴식일은 유지합니다. 못 마친 활동은 다음 학습일에 먼저 이어가고 그날 3시간 안에서 새 진도를 미룹니다. 예를 들어 2일차 과제를 3일차에 마쳤다면 실제 수행은 3일차에 기록합니다. 휴식일 자체에는 필수 체크가 없습니다.
6. 이 문서는 대화에서 확인한 내용을 기록하는 체크리스트입니다. 클릭 감지·자동 타이머·앱 종료 후 알림은 실행되지 않습니다. 완료를 알려 주시면 Codex가 기록합니다.

### 복습과 주간 점검

- 각 수업을 **실제로 마친 날**부터 1·3·7·14일 뒤를 초기 복습 목표로 잡고 수행 결과에 따라 조정합니다. 휴식일에 걸린 복습은 다음 학습일로 옮깁니다. 여러 복습이 같은 날로 이동하면 하나의 실제 회상으로 기록하고 두 번 수행한 것처럼 세지 않습니다.
- 회상 시간에는 그날 예정된 복습과 해당 주의 실제 학습 주제를 우선합니다. 3시간을 넘겨 밀어 넣지 않고, 필요한 경우 신규량을 줄이거나 다음 학습일로 이월합니다. 예정된 복습의 실제 수행 여부는 별도로 기록합니다.
- 주 1회 해당 주에 학습한 주제 10개를 자료 없이 점검하고, 10개 미만이면 전부 점검합니다. 주제마다 핵심 질문과 통과 기준을 미리 밝히며, 요구한 핵심을 충족하고 중대한 개념 오류가 없으면 통과로 봅니다. 정해진 대상의 확인이 끝나기 전에는 주간 비율을 만들지 않습니다. 80% 미달이면 신규량을 줄이고 취약점을 복습합니다.
- 주 1회 본인이 이해한 내용을 구술로 설명합니다. 구술 결과를 실제 확인할 수 없다면 사용자 수행 보고로만 남깁니다. 확인된 실무 사례가 있다면 출처를 구분해 축적합니다.

## 48주 로드맵

| 계획 경과일 | 단계 | 운영 |
|---|---|---|
| 1~14일차 · 1~2주 | 진단 | 정규화 파일럿과 다섯 분야의 기초·회상·답안을 확인합니다. |
| 15~84일차 · 3~12주 | 기본기 | 진단 결과에 맞춰 전 분야를 순환하고, 주당 단답 4개·논술 1개부터 시작합니다. |
| 85~168일차 · 13~24주 | 적용·시간 관리 | 변형 기출을 풀고 주 1회 100분 훈련을 기존 답안 시간에 넣습니다. |
| 169~336일차 · 25~48주 | 취약점 반복 | 4주마다 전 교시 훈련을 기존 과제 대신 수행하고 취약점을 보완합니다. |

4주마다 처음 보는 변형 문제로 점검합니다. 24주부터 최근 3회의 시간제한 평가가 각각 훈련용 70점 이상이고 요구한 답안을 완성했으며 중대한 개념 오류가 없는 상태가 유지되면, 응시 가능한 가까운 회차를 집중 목표로 검토합니다. 공식 합격권 판정이 아닙니다. 48주는 초기 학습 예산일 뿐 합격기간 예측이 아니며, 실제 진도에 따라 재조정합니다.

## 첫째 주

### 1일차 — 정규화 파일럿 시작

**목표:** 별도 예제로 중복·이상현상을 이해하고 정규화 기출에 처음 답합니다. [129회 4교시 2번](../wiki/questions/qnet-129-p4.md#q2)을 이미 보거나 풀이를 본 적이 있다면 알리고, [파일럿 수업안](lessons/normalization-pilot.md)의 강사 생성 변형으로 별도 확인합니다. 두 문제를 모두 보았다면 새 변형을 요청합니다.

- [ ] 개념·기출 45분: 첫 진단에서 아직 확인되지 않은 목표·경력·응시자격을 확인하고, 릴레이션·속성·기본키·복합키의 기초 설명을 듣습니다. 미답변 정보가 있어도 수업을 진행합니다.
- [ ] 개념·기출 15분: 기출과 다른 주문 예제로 함수종속·중복·이상현상 설명을 듣고, 답안 작성 전에 위 훈련용 첨삭 기준을 확인합니다.
- [ ] 답안 25분: 위 기출 또는 대체 훈련 문제의 요구를 나누어 타이핑하고 제출합니다. 시간은 참고값이며 막히면 한 단계씩 힌트를 요청합니다.
- [ ] 첨삭 15분: 제출한 답안에 대한 훈련용 기준과 감점 근거·우선 수정점을 확인합니다. 기출 답안 제출 뒤 [정규화 인쇄 노트](../output/pdf/subnotes/topics/relational-normalization.pdf)를 열 수 있습니다.
- [ ] 회상 30분: 자료를 가리고 이상현상 세 가지와 중복이 생긴 이유를 자기 말로 설명합니다. 막힌 부분을 적습니다.
- [ ] 답안 20분: 기출과 다른 설명 예제를 사용해 이상현상 한 가지와 이유를 손글씨로 씁니다. 사진을 제출하면 판독 가능한 부분을 확인받을 수 있습니다.
- [ ] 첨삭 15분: 실제로 확인받은 교정 내용 중 우선할 것을 정리합니다. 손글씨를 제출하지 않았다면 자체 점검으로 표시합니다.
- [ ] 동향·점검 15분: 실제 수행과 남은 질문을 확인하고, 목표 회차의 응시자격·출제기준 확인이 필요한 항목을 기록합니다.

주문 예제 설명 15분 → 타이핑 답안 25분 → 첨삭 15분이 연속된 **55분 파일럿**입니다. 실제 시간이 보고되지 않았다면 위 참고 시간을 수행 시간으로 기록하지 않습니다.

### 2일차 — 정규화 복습과 적용

**목표:** 1일차 교정을 반영해 다른 데이터에 적용합니다. 기출을 다시 보는 것은 복습이며 처음 보는 독립 평가가 아닙니다.

- [ ] 개념·기출 60분: 함수종속·키·이상현상·분해 이유를 설명받고 1일차에서 부족했던 전제를 확인합니다. [정규화 노트](../wiki/concepts/relational-normalization.md)는 첫 기출 답안 제출 또는 사용자의 풀이 공개 요청 이후에 확인합니다.
- [ ] 회상 45분: 예정된 1일차 복습을 자료 없이 수행하고, 이상현상과 분해의 목적을 설명합니다. 실제 결과와 미확인 부분을 구분합니다.
- [ ] 답안 45분: 아래 **강사 생성 훈련 문제**의 이상현상, 분해한 관계의 키와 연결 방법, 원래 행의 복원 가능성을 설명합니다.

  `사원역할(사번, 사원명, 역할코드, 역할명)`의 기본키는 `(사번, 역할코드)`입니다. 사번 하나에 사원명 하나, 역할코드 하나에 역할명 하나가 대응합니다. 이름과 역할명은 여러 사번·코드에서 중복될 수 있고 모든 값은 원자값이라고 가정합니다. 예시 행은 `(E01, 이도, R1, 운영)`, `(E01, 이도, R2, 분석)`, `(E02, 민지, R1, 운영)`입니다. 삽입·갱신·삭제 이상과 이를 줄일 분해를 제시하세요.

- [ ] 첨삭 15분: 제출한 훈련 답안에서 가정과 분해 근거를 검토하고 가장 중요한 교정점을 반영합니다.
- [ ] 동향·점검 15분: 복습 결과와 미완료 사항을 정리합니다. 기준과 법령의 최신성은 필요할 때 원문에서 확인할 항목으로 남깁니다.

### 3일차 — 소프트웨어 테스트 비교

**목표:** 서로 다른 테스트 설계 관점을 이해하고 [129회 1교시 8번](../wiki/questions/qnet-129-p1.md#q8)의 비교 요구를 다룹니다.

- [ ] 개념·기출 60분: 강사가 기출과 다른 입력 검증 예제로 블랙박스·화이트박스의 설계 근거와 비교 관점을 설명합니다.
- [ ] 회상 30분: 예정된 정규화 복습을 수행하고, 오늘 배운 두 테스트 관점의 차이를 자료 없이 말합니다.
- [ ] 답안 60분: 129회 문제의 비교 기준과 예시를 구성해 직접 작성하고 제출합니다. 이미 풀이를 본 적이 있으면 강사에게 알리고 별도 훈련 문제로 확인합니다.
- [ ] 첨삭 15분: 제출한 답안의 누락·오류를 확인하고, 답안 제출 뒤 [테스트 인쇄 노트](../output/pdf/subnotes/topics/software-testing-principles-techniques.pdf)와 비교합니다.
- [ ] 동향·점검 15분: 비교하기 어려웠던 용어와 다음 복습 항목을 적습니다.

### 4일차 — 테스트 기법 적용

**목표:** 명세와 코드 구조를 각각 근거로 테스트를 설계합니다. 관련 기출은 [129회 1교시 8번](../wiki/questions/qnet-129-p1.md#q8)입니다.

- [ ] 개념·기출 60분: [테스트 노트](../wiki/concepts/software-testing-principles-techniques.md)로 비교 기준과 경계·분기 관점을 복습합니다.
- [ ] 회상 30분: 예정된 복습을 수행하고 두 테스트 관점과 적용 예를 말합니다.
- [ ] 답안 45분: 다음 **강사 생성 훈련 문제**를 풉니다. 한도는 양수, 결제액은 정수라고 가정합니다. 명세에 근거한 경계 사례와 아래 코드의 분기를 살피는 사례를 제안하고 설계 근거를 비교하세요.

  ```text
  결제액이 0 이하이면 '금액 오류'를 반환한다.
  그렇지 않고 결제액이 한도보다 크면 '한도 초과'를 반환한다.
  그 밖에는 '승인'을 반환한다.
  ```

- [ ] 첨삭 30분: 제출한 사례에서 선택 근거와 빠진 분기를 확인하고 수정합니다.
- [ ] 동향·점검 15분: 실제 수행·미수행과 이해가 불확실한 사항을 정리합니다.

### 5일차 — TCP 연결과 종료

**목표:** [133회 1교시 13번](../wiki/questions/qnet-133-p1.md#q13)의 연결·종료 설명 요구를 다룹니다.

- [ ] 개념·기출 60분: 강사가 별도 통신 예제로 연결과 종료의 흐름·표현 방법을 설명합니다. 필요하면 개념 그래프에서 관련 개념을 살펴보되 연결 수를 중요도로 해석하지 않습니다.
- [ ] 회상 45분: 예정된 복습과 첫 주에 실제 학습한 주제 전체의 주간 점검을 합니다. 자료를 가리고 주제별 핵심 질문에 답하며 구술 설명 한 번을 포함합니다.
- [ ] 답안 45분: 133회 문제의 연결·종료 순서와 설명을 작성해 제출합니다. 이미 풀이를 본 적이 있으면 별도 훈련 문제를 요청합니다.
- [ ] 첨삭 30분: 제출한 흐름도나 문장의 오류를 확인하고 수정합니다. 답안 제출 뒤 [TCP 인쇄 노트](../output/pdf/subnotes/topics/tcp-control.pdf)와 비교합니다.

### 6~7일차 — 휴식

필수 수업과 체크는 없습니다. 예정된 복습이 겹치면 8일차로 옮깁니다. 실제로 쉬었는지 임의로 기록하지 않습니다.

## 둘째 주

### 8일차 — TCP 적용과 첫 주 보완

**목표:** 5일차 연결·종료 설명을 다른 상황에 적용합니다. 관련 기출은 [133회 1교시 13번](../wiki/questions/qnet-133-p1.md#q13)입니다.

- [ ] 개념·기출 60분: [TCP 노트](../wiki/concepts/tcp-control.md)로 연결·종료와 각 방향 종료를 복습합니다. 미완료 활동이 있다면 먼저 이어가고 새 활동을 조정합니다.
- [ ] 회상 30분: 휴식일에서 이동한 복습과 오늘 예정된 복습을 점검합니다. 같은 주제가 겹치면 실제 회상 한 번으로 기록합니다.
- [ ] 답안 45분: **강사 생성 훈련 문제** — 클라이언트와 서버가 정상 연결한 뒤 클라이언트부터 연결을 종료합니다. 동시 종료와 손실은 없고 종료 시 ACK와 FIN이 각각 전송된다고 가정합니다. 연결·종료의 흐름을 각각 그리고 두 방향의 종료를 설명하세요.
- [ ] 첨삭 30분: 제출한 순서와 설명의 근거를 점검하고 부족한 부분을 다시 씁니다.
- [ ] 동향·점검 15분: 실제 수행과 다음 복습을 확인합니다. 한 주의 회상 확인 결과가 80% 미달이었다면 신규량을 줄여 취약점을 우선합니다.

### 9일차 — 대칭·비대칭 암호 비교

**목표:** [132회 1교시 4번](../wiki/questions/qnet-132-p1.md#q4)의 두 암호 방식 비교를 다룹니다.

- [ ] 개념·기출 60분: 강사가 기출과 다른 파일 전달 예제로 두 방식의 키 사용과 적용 맥락을 설명합니다.
- [ ] 회상 45분: 예정된 정규화·테스트·TCP 복습을 확인하고, 오늘 배운 두 암호 방식의 차이를 자료 없이 말합니다.
- [ ] 답안 45분: 132회 문제의 비교 기준과 적용상 고려점을 작성해 제출합니다. 이미 풀이를 본 적이 있으면 별도 훈련 문제를 요청합니다.
- [ ] 첨삭 15분: 제출한 비교를 검토하고, 제출 뒤 [암호 인쇄 노트](../output/pdf/subnotes/topics/symmetric-asymmetric-aes.pdf)와 대조합니다.
- [ ] 동향·점검 15분: 실제 수행과 모호했던 용어를 기록합니다.

### 10일차 — 암호 방식의 조합

**목표:** 기밀성과 발신자 확인을 분리해 적용합니다. 관련 기출은 [132회 1교시 4번](../wiki/questions/qnet-132-p1.md#q4)입니다.

- [ ] 개념·기출 60분: [암호 노트](../wiki/concepts/symmetric-asymmetric-aes.md)로 암호화·키 전달·서명의 목적을 비교합니다.
- [ ] 회상 30분: 예정된 복습을 수행하고 대칭키·공개키 방식의 쓰임과 한계를 설명합니다.
- [ ] 답안 60분: **강사 생성 훈련 문제** — A가 B에게 파일을 기밀로 전달하면서 B가 발신자를 확인해야 합니다. 양측의 공개키는 이미 검증되었다고 가정합니다. 대칭키, 공개키 방식, 전자서명 중 필요한 수단을 선택해 송신·수신 순서와 각 수단의 목적을 설명하세요.
- [ ] 첨삭 15분: 제출한 답안에서 기밀성·발신자 확인과 키 역할을 구분했는지 점검합니다.
- [ ] 동향·점검 15분: 추가 근거가 필요한 키 관리·적용 조건을 적습니다.

### 11일차 — IT 거버넌스 구성과 측정

**목표:** [134회 2교시 3번](../wiki/questions/qnet-134-p2.md#q3)의 구성요소·효과 지표·측정 방법론을 구분합니다.

- [ ] 개념·기출 60분: 강사가 별도 조직 의사결정 예제로 거버넌스와 관리, 성과 확인의 관점을 설명합니다.
- [ ] 회상 30분: 예정된 복습을 수행하고 오늘 학습한 결정·책임·성과 확인의 관계를 설명합니다.
- [ ] 답안 45분: 134회 문제의 가·나·다 요구를 나누어 작성하고 제출합니다. 이미 풀이를 본 적이 있으면 별도 훈련 문제를 요청합니다.
- [ ] 첨삭 30분: 제출한 답안의 요구 충족과 적용 근거를 점검합니다. 제출 뒤 [IT 거버넌스 인쇄 노트](../output/pdf/subnotes/topics/it-governance-enterprise-architecture.pdf)를 참고합니다. 이 노트는 **부분 확인**이며 기준 위키의 문서 상태는 **미검증**입니다. 확인되지 않은 원문·판본은 추가 확인 전 확정하지 않습니다.
- [ ] 동향·점검 15분: 최신 기준과 공식 원문 확인이 필요한 사항을 기록합니다.

### 12일차 — IT 거버넌스 적용과 2주 점검

**목표:** 주어진 조직 상황에 측정 계획을 적용하고 초기 진단 결과를 정리합니다. 관련 기출은 [134회 2교시 3번](../wiki/questions/qnet-134-p2.md#q3)입니다.

- [ ] 개념·기출 60분: [IT 거버넌스 노트](../wiki/concepts/it-governance-enterprise-architecture.md)의 확인 범위와 한계를 확인하고 구성·지표·측정 방법의 차이를 검토합니다.
- [ ] 회상 45분: 예정된 복습과 둘째 주에 실제 학습한 주제 전체의 주간 점검을 합니다. 자료를 가리고 주제별 핵심 질문에 답하며 구술 설명 한 번을 포함합니다.
- [ ] 답안 45분: **강사 생성 훈련 문제** — 한 온라인 유통 조직이 서비스 안정성, 개인정보 보호와 IT 투자 효율을 함께 관리하려 합니다. 거버넌스 구성요소, 확인할 효과 지표, 측정 방법을 각각 제안하세요. 실제 측정값이나 성과를 만들어 내지 말고 필요한 자료와 가정을 밝히세요.
- [ ] 첨삭 30분: 제출한 답안과 2주간 실제 수행 근거를 검토하고, 지식 부족·회상 실패·질문 오독·구조 부족·시간 부족 중 확인된 보완점을 정합니다. 15일차 이후 주제는 이 결과와 사용자의 실무 분야를 반영해 조정합니다.

### 13~14일차 — 휴식

필수 수업과 체크는 없습니다. 예정된 복습은 15일차 이후 실제 다음 학습일에 옮깁니다. 이후 계획도 같은 주간 시간 배분을 기본으로 하되 실제 수행 결과에 따라 세부 주제를 정합니다.
