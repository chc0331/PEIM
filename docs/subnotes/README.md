## 원고와 산출물

기준 원고는 기존 `wiki/concepts/`의 개념 문서다. `## 서브노트` 절만 인쇄하며, 이전 문서 기록·개인 답안·점수·브레인스토밍 대화 전체를 책에 섞지 않는다. `catalog.json`은 토픽 목록·출처·기출 요구사항 대응을 관리한다. 연구 기록은 강사 생성 요약과 실제 열람 범위를 구분해 추가 전용 원자료로 보관한다.

PDF의 검토 상태는 실제 연구의 범위를 표시한다. 기출이 요구한 용어가 연결됐다는 이유만으로 모든 소문항을 설명·검증했다고 표시하지 않는다. 확인하지 못한 과거 판본·폐쇄 표준 조항·현행 수치는 확인 필요로 남긴다. 인쇄 참고문헌에는 제목·기관·판본/날짜·확인일을 간결하게 표시하며, 실제 열람 절·페이지·첨부 실패 등 상세 범위는 위키의 출처 기록과 추가 전용 연구 기록에 보존한다.

토픽 검토 상태는 출처 확인 120개·부분 확인 103개·확인 필요 1개다. 문항 대응은 수록 연결 306개·부분 확인 158개·확인 필요 1개다. ‘수록 연결’도 공식 해설이나 모든 요구의 전수 검증을 뜻하지 않는다.

## 인쇄와 읽기

- A4, 실제 크기(100%), 흑백, 양면, 긴 쪽으로 넘김을 사용한다.
- 토픽별 PDF는 2쪽 또는 4쪽이다. 통합본에서도 각 토픽이 홀수 쪽에서 시작한다.
- 첫 부분은 쉬운 설명·정의·원리·비교, 다음 부분은 예제·답안 골격·회상·근거다.
- 먼저 설명을 읽고 예제를 직접 따라 계산한다. 이후 내용을 가리고 회상 질문에 답한 뒤 해당 절로 돌아가 교정한다.
- 읽은 날과 1·3·7·14일 뒤를 초기 복습 간격으로 삼고, 틀린 정의·비교·계산을 우선 다시 회상한다. 첫 주부터 선택한 기출 한 문항의 손글씨 답안을 병행한다.
- 통합본 목차와 문항별 찾아보기에서 필요한 토픽을 찾는다. 회차-교시-문항 번호는 공식 원문의 위치와 연결된다.
- PDF는 읽기 자료다. 생성·열람으로 학습 상태를 승급하지 않는다.

## PDF 재생성

프로젝트 위키 관리에는 기존 `.venv/bin/python`을 사용한다. PDF 출력에는 Codex의 번들 Python(ReportLab·pypdf·pdfplumber)을 사용한다. 번들 위치는 `load_workspace_dependencies` 도구로 확인한다. 전역 환경을 변경하지 않는다.

번들 Python으로 다음을 실행한다.

```sh
python scripts/render_subnotes.py
python scripts/render_subnotes.py --topic ipv4-subnetting-vlsm
python scripts/check_subnotes.py
```

출력은 `output/pdf/subnotes/`에 생성한다. 개별본은 `topics/`, 통합본은 `정보관리기술사_기출서브노트_통합.pdf`, ZIP은 `정보관리기술사_토픽별서브노트.zip`이다. 전체 명령은 한글 목록·문항 대응·ZIP도 갱신한다. 쪽수와 목차 위치는 `manifest.json`, 자동 검사 범위와 결과는 `checks.json`에 기록한다.

`--topic`은 선택한 개별 PDF와 `manifest-selected.json`만 갱신한다. 통합본·쪽수 색인·ZIP을 함께 갱신할 때는 전체 명령을 실행한다.

`publish_subnotes.py`는 세션에서 작성·확인한 연구 결과를 처음 위키로 반영하는 도구다. 기술 지식을 자동 조사하거나 출처를 검증하는 도구가 아니다. 기존 개념 ID를 재사용하고 이전 원고를 문서 안에 보존한다. 독립 교정 기록이 연결된 원고의 재반영은 쓰기 전에 거부한다. 이후 설명을 교정할 때는 위키를 수정하고 PDF를 다시 생성한다.

## 검수와 갱신

자동 검사는 기출 ID·참조, A4 크기, 2/4쪽, 텍스트 경계, 홀수 쪽 시작, 목차 링크를 검사한다. 기술 정확성·계산의 전제·소문항 충족 여부·도식의 의미는 내용 검수로 따로 확인한다. PDF를 이미지로 렌더링하고 잘림·겹침·깨진 문자·표 분할을 살핀다.

2026-11-10에는 224개 원고를 읽고 한국어 표현과 예제의 전제·계산을 다듬었다. 출처는 수정이 필요한 항목을 중심으로 원문과 대조했다. 개별 PDF 224개와 통합본 472쪽을 다시 생성하고, 465문항의 연결과 ZIP 파일의 해시를 검사했다. [내용 정정 기록](../../raw/corrections/2026-11-10-learning-doc-review.md) · [최신 검수 범위와 산출물 해시](verification.json)

2026-11-05 검증: 기존 테스트 13개, 개별 PDF 224개 구조 검사, 통합본 472쪽 축소 전체보기·8쪽 상세 검토, ZIP의 224개 PDF 해시 대조를 통과했다. 위키 667문서와 방향 그래프 3,857노드·5,349엣지는 `ready`, 의미 추출 대기는 0이다. [실제 검증 범위와 산출물 해시](verification.json)에 종이 인쇄·독자 이해도·외부 원문 재열람의 한계를 함께 기록했다.

위키 내용 변경 후 프로젝트의 prepare → 세션 의미 추출 → accept → build를 수행한다. 인쇄 PDF·임시 이미지·연구 원자료는 그래프 입력에 넣지 않는다. 생성물의 페이지 수나 그래프 중심성을 출제 중요도나 숙련도로 해석하지 않는다.

독립 검수는 [데이터·AI](review-data-ai.md), [시스템·보안](review-systems.md), [소프트웨어·사업·경영](review-software-business.md)에 범위·계산·필수 수정과 미확인을 구분해 기록했다. 정정 전 연구 원고는 보존하고 [교정 전후 값](../../raw/corrections/2026-11-05-subnotes-review.md) 및 [후속 교정](../../raw/corrections/2026-11-05-subnotes-review-followup.md)을 추가 보관했다. 이 보고서를 외부 출처 전권의 재열람이나 실제 학습자 이해도 시험으로 해석하지 않는다.
