# 빅데이터 사업 분석·설계 감리

## 서브노트

### 한눈에 이해

분석 단계의 합의가 설계의 수집·저장·분석·시각화와 실제 확보 가능한 데이터로 이어졌는지 확인합니다.

### 정의와 핵심 원리

NIA2023 지능정보기술 감리 실무가이드는 빅데이터 정보화사업의 단계·영역별 요구·설계·구현·운영 위험과 점검 항목을 제시합니다. 분석단계와 데이터 분석 알고리즘 수행 단계는 다른 분류입니다.

- 분석단계 응용시스템 영역은 사업목표·구현방안 이해, 목표 달성을 위한 분석항목과 상관관계·결과품질, 분석가/사용자 인터페이스, 시각화 유형·도구, 운영·관리 기능, 기능·성능·품질 요구 도출을 점검합니다.
- 분석단계 데이터 영역은 목적에 맞는 종류·양·보관·수집/분석 주기와 백업 요구, 원시데이터 확보 가능성을 확인합니다. 내·외부 데이터를 활용한 서비스와 운영 환경·연계 요건도 검토하여 나중에 데이터가 없거나 권한이 없어 구축이 막히는 위험을 줄입니다.
- 설계단계 응용은 수집대상·정제기준·개인정보 처리, ETL·주기적 연계와 품질관리, 요구에 맞는 분석대상·범위·모델·알고리즘과 타당성, 화면·시각화·서비스 기능을 점검합니다.
- 설계단계 데이터는 속성·형식·길이·필수여부·명명/용어/도메인·코드 표준, 유형·변환·유효성 규칙·융합을 확인합니다. 시스템 구조는 수집·저장·분석·시각화 아키텍처와 외부연계·접근제어·보안의 상세설계가 요구와 연결되는지 검토합니다. 자료의 버전과 실제 산출물·실증 증거를 함께 기록합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 분석 | 목표·사용·데이터 요구와 확보 | 요구의 적정성·실현성 |
| 설계-응용/데이터 | 처리·모델·시각화·표준화 | 요구와 상세 설계의 일치 |
| 설계-시스템 | 아키텍처·연계·보안 | 수집부터 활용까지 실행 가능성 |

### 적용 예제

**강사 창작 적용 예시: 민원 수요 분석 사업 감리**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 목표는 지역별 수요 예측이나 외부 데이터 이용권이 미정입니다.

1. 분석에서 데이터 보유기관·비용·제공주기·이용 근거를 확인합니다.
2. 설계에서 지역코드 변환·결측처리·모델·시각화 요구를 추적합니다.
3. 샘플 수집과 변환·모델 입력을 실증해 누락과 불일치를 기록합니다.

**결과·해석:** 알고리즘 이름만 있는 사업의 실현 위험을 조기에 드러냅니다.

**전제·주의:** 가이드의 “자료에 명시”와 해당 데이터·모델의 실제 타당성 검증을 구분합니다.

### 답안 골격과 혼동 방지

가이드 목적·영역·감리 단계 → 분석단계 응용/데이터 점검 → 설계단계 시스템/응용/데이터와 증거

- 분석단계를 모델 학습 단계만으로 축소하지 않습니다.
- 품질 기준이 있다는 서류만 보고 실제 품질 충족으로 표시하지 않습니다.
