# 대칭·비대칭 암호와 AES

## 서브노트

### 한눈에 이해

큰 파일은 대칭 암호로 빠르게 보호하고, 공개 키 기법으로 수신자와 파일을 열 키를 설정할 수 있습니다.

### 정의와 핵심 원리

대칭 암호는 암호화와 복호에 같은 비밀 키를 사용합니다. 공개 키 암호는 공개 키와 개인 키의 관계를 이용합니다. AES는 128비트 블록을 128·192·256비트 키 중 하나로 처리하는 대칭 블록 암호입니다.

- AES는 SubBytes·ShiftRows·MixColumns·AddRoundKey와 키 스케줄로 구성합니다. 128·192·256비트 키는 각각 10·12·14라운드를 사용합니다. 최종 라운드에서는 MixColumns를 생략합니다.
- 공개 키 기법은 키 설정·암호화·서명으로 용도를 구분합니다. 하이브리드 방식에서는 큰 데이터를 대칭 암호로 처리하고, 세션 키를 공개 키 기법으로 설정합니다. 인증서와 검증 경로로 상대 공개 키의 진위를 확인해야 중간자 공격의 위험을 줄일 수 있습니다.
- 안전성은 알고리즘 이름뿐 아니라 키 생성·저장·폐기·nonce/IV·패딩·모드·오류 반응·부채널·프로토콜 결합에 좌우됩니다. 암호화만으로 송신자 진위·무결성·부인 방지가 동시에 보장되지는 않습니다. 인증 암호와 키 분리를 검토합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 대칭 암호 | 공유 비밀 키·빠른 대량 처리 | 키 분배와 공유 범위 관리 |
| 공개 키 암호 | 키 쌍·서명·키 설정 | 계산 비용·키 진위 확인 |
| AES | 128비트 블록·세 가지 키 길이 | 모드·nonce·키 관리 |

### 적용 예제

**하이브리드 파일 전달**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 1GB 파일을 지정된 수신자 한 명만 읽을 수 있게 전달합니다.

1. 난수로 대칭 데이터 키를 만듭니다.
2. 인증 암호로 파일을 암호화하고 수신자 공개 키를 이용해 데이터 키를 보호합니다.
3. 수신자는 개인 키로 데이터 키를 복구합니다. 인증 태그를 검증한 뒤 평문을 사용합니다.
4. 송신자를 확인해야 한다면 별도로 서명을 사용합니다.

**결과·해석:** 대칭 암호로 큰 파일을 효율적으로 처리하고 공개 키 방식으로 데이터 키를 보호합니다.

**전제·주의:** 이 예제는 동작 원리를 설명합니다. 구현에는 검증된 표준 프로토콜과 라이브러리를 사용합니다.

### 답안 골격과 혼동 방지

암호 분류와 보안 목표 → AES 구조와 라운드 → 대칭·공개 키 방식 비교 → 하이브리드 예제 → 키와 모드 관리

- AES-256의 256은 키 길이입니다. 블록 크기는 128비트입니다.
- 공개 키 암호를 모두 개인 키 암호화로 설명하지 않습니다.
