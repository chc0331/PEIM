# 대칭·비대칭 암호와 AES

## 서브노트

### 한눈에 이해

많은 데이터를 빠르게 잠그는 열쇠와 낯선 상대에게 안전하게 열쇠·서명을 전달하는 수단을 조합합니다.

### 정의와 핵심 원리

대칭암호는 암·복호에 공유 비밀키를 사용하고 공개 키 암호는 공개 키와 개인키 관계를 이용합니다. 블록 암호는 고정 크기블록변환이며 AES는 128비트블록과 128/192/256비트키를 갖는대칭블록 암호입니다.

- AES는 SubBytes·ShiftRows·MixColumns·AddRoundKey등상태변환과키스케줄을라운드로 결합합니다. 키 길이에따라 10/12/14라운드를 사용하고 최종라운드는 구성차이가있습니다. 블록 크기와키 길이를혼동하지 않습니다.
- 공개 키 기법은 키 설정·암호화·서명등용도를구분합니다. 큰데이터는 대칭암호로 처리하고 세션 키를 공개 키스킴으로설정하는하이브리드구조가 일반적입니다. 공개 키의 정당성을 인증서·검증 경로등으로확인하지 않으면중간자위험이 남습니다.
- 안전성은 알고리즘 이름뿐 아니라키 생성·저장·폐기·nonce/IV·패딩·모드·오류반응·부채널·프로토콜결합에좌우됩니다. 암호화만 으로송신자 진위·무결성·부인 방지가동시에보장되지는않습니다. 인증 암호와 키 분리를 검토합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 대칭암호 | 공유키·고속대량처리 | 키분배·공유범위 |
| 공개 키 암호 | 키쌍·서명·키 설정 | 계산 비용·키 진위 |
| AES | 128비트블록·3키 길이 | 모드·nonce·키 관리필요 |

### 적용 예제

**하이브리드 파일 전달**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 큰파일1GB를 수신자한명에게기밀전달

1. 난수로대칭데이터 키를 만듭니다.
2. 인증 암호로 파일을암호화하고 수신자 공개 키스킴으로데이터 키를 보호합니다.
3. 수신자는 개인키로 키를 복구하고 태그검증뒤평문을 사용합니다.
4. 필요한 송신자증명은별도 서명정책으로 추가 합니다.

**결과·해석:** 대량처리효율과공개 키 기반 키 전달의 장점을연결합니다.

**전제·주의:** 교육개념이며 직접 설계한암호포맷대신 검증된표준 프로토콜과 라이브러리를 사용합니다.

### 답안 골격과 혼동 방지

분류·보안목표 → AES 구조·라운드 → 대칭/비대칭비교 → 하이브리드예 → 키·모드 관리

- AES256의블록이 256비트라고쓰지않습니다.
- 공개 키 암호를 모두개인키 암호화로 설명하지 않습니다.
