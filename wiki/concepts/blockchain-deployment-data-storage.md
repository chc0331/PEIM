# 블록체인 유형·파일/DB와 저장 방식 비교

## 서브노트

### 한눈에 이해

여러 기관이 공동 기록을 관리할 때 어떤 거래를 받아들이고 어느 순서로 기록할지 규칙을 정합니다.

### 정의와 핵심 원리

블록체인은 암호학적 연결과 분산 합의 등으로 거래 기록의 일관된 원장을 유지하는 기술입니다. 저장 데이터의 진실성이나 외부 사실을 자동 보증하지 않으며 권한·합의·운영 거버넌스에 따라 성질이 달라집니다.

- 퍼블릭은 대체로 누구나 열람·참여 가능한 네트워크에서 검증 권한을 프로토콜로 조정합니다. 검열 저항·공개 검증을 추구하지만 지연·수수료·프라이버시·키 분실·합의 공격의 비용을 평가해야 합니다. 공개 여부와 검증 참여 허가 여부는 별도 축입니다.
- 허가형에서는 승인받은 참여자만 새 블록을 추가할 수 있습니다. 거래 제출과 원장 열람 권한은 별도로 정하며, 프라이빗 구성에서는 열람 범위도 제한합니다. 권한 제한은 처리량과 기밀성에 도움이 될 수 있지만 담합, 키 관리, 복구 책임은 별도로 검토합니다. 컨소시엄은 여러 기관이 함께 운영 규칙을 정하는 방식입니다.
- 하이브리드는 공개망의 증명/검증과 허가망의 기밀 데이터·업무를 조합하는 설계로 설명할 수 있습니다. 비공개 거래의 해시를 공개망에 앵커링하는 예가 있으나 업계에서 단일하게 합의된 제3유형 표준은 아닙니다. 연결 경계·동기화·권한·외부 데이터의 진위를 검증합니다.
- 파일은 응용이 구조·검색·중복/동시성·복구를 주로 책임지고, DB는 스키마·질의·트랜잭션·제약/권한·백업을 관리합니다. 블록체인은 여러 주체의 기록 순서·상태에 대한 합의를 추가하며 대용량 원본·개인정보는 별도 저장하고 해시/참조만 기록할 수 있습니다. 삭제·정정·비용 요구가 강하면 일반 DB가 더 적절할 수 있습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 파일 | 응용 중심의 단순 저장·교환 | 구조/동시성·정합성 별도 구현 |
| DB | 관리된 질의·트랜잭션·무결성 | 단일/통제된 운영주체의 신뢰 |
| 블록체인 | 공동 원장·암호 연결·합의 | 신뢰경계·권한·처리비용 검토 |

### 적용 예제

**강사 창작 적용 예시: 기관 공동 자격 증명 기록**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 발급기관들은 원본 명부를 외부에 공개할 수 없습니다.

1. 각 기관 DB에 원본·개인정보를 보관하고 공동 검증할 항목을 정의합니다.
2. 허가형망에 발급/취소 상태, 필요 시 공개망에 묶음 해시를 기록하는 대안을 비교합니다.
3. 키 회전·취소·오류 정정·발급 권한과 검증절차를 시험합니다.

**결과·해석:** 공개성·기밀성·합의 비용을 목적에 맞게 조합하는 근거가 됩니다.

**전제·주의:** 창작 구조이며 해시가 원본 내용의 사실성·적법성까지 보증하지 않습니다.

### 답안 골격과 혼동 방지

원장·합의·권한 정의 → 퍼블릭/프라이빗/하이브리드 비교 → 파일/DB/블록체인과 적용판단

- 블록체인을 절대 수정 불가능·해킹 불가능하다고 설명하지 않습니다.
- permissioned와 private를 모든 문맥에서 완전한 동의어로 통합하지 않습니다.

### 적용 기준과 근거

NISTIR 8202 §2.2는 블록 추가 권한과 원장 열람·거래 제출 권한을 구분합니다. 하이브리드 구성은 이 노트의 설계 예시입니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [Blockchain Technology Overview (NISTIR 8202)](https://www.nist.gov/publications/blockchain-technology-overview) — Dylan Yaga 외 / NIST; 2018-10; 확인 2026-11-05. 확인 범위: 본문 또는 해당 절을 실제 열람했습니다. 자체 요약만 저장하며 외부 원문 전체는 보관하지 않습니다.
