# 임베디드·신뢰성·이식성 테스트

## 서브노트

### 한눈에 이해

기능이 맞아도 실제 장치의 시간·자원 제약에서 실패하거나 새 환경에서 설치되지 않으면 제품 품질은 부족합니다.

### 정의와 핵심 원리

임베디드 테스트는 하드웨어와 상호작용하며 제약된 환경에서 실행되는 소프트웨어를 검증합니다. 신뢰성 테스트는 정해진 조건·시간에 기능을 지속할 능력을, 이식성 테스트는 다른 환경으로 이전·설치·대체할 능력을 평가합니다.

- 임베디드는 센서·구동기·인터럽트·실시간 응답·제한 메모리/전력·통신·안전 상태를 고려합니다. 호스트 단위시험과 시뮬레이션을 거쳐 타깃 장치에서 실제 타이밍과 자원 사용, HW-SW 통합·오류 입력·복구를 확인합니다.
- MIL은 모델 자체, SIL은 소프트웨어 실행, PIL은 목표 프로세서, HIL은 실제 제어기와 모사된 물리환경의 연결로 추상 수준을 달리합니다. 위험과 재현성·장비 비용에 맞춰 조합하며 HIL이 실제 현장시험을 항상 대체하지는 않습니다.
- 신뢰성의 세부 활동은 장시간 안정성/부하, 고장 주입과 결함허용, 장애·전원·통신 단절 뒤 회복, 가용성·복구 시간 측정입니다. 실패의 정의·관찰시간·운영 프로파일이 없으면 고장률을 의미 있게 비교할 수 없습니다.
- 2011 품질모델의 이식성은 적응성·설치성·대체성으로 나누어 OS/CPU/브라우저/런타임 조합, 설치·업그레이드·제거·롤백, 데이터·설정 이전과 대체품 호환을 시험합니다. 기능·성능·보안·신뢰성 등 시험 유형은 단위·통합·시스템·인수 수준에서 함께 적용될 수 있습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 신뢰성 | 시간 경과와 고장·회복 | 장시간·고장주입·복구 시험 |
| 이식성 | 환경 이전·설치·대체 | 호환 매트릭스·업그레이드/롤백 |
| 임베디드 | 실제 장치 제약·물리 인터페이스 | SIL/PIL/HIL과 타깃 검증 |

### 적용 예제

**강사 창작 적용 예시: 온도 제어기 검증**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 센서 입력 10ms 주기, 통신 단절 시 안전 출력을 요구한다고 가정합니다.

1. SIL에서 경계 온도·비정상 센서값의 논리를 시험합니다.
2. HIL이나 대상 장치에서 주기를 지연시키고 인터럽트와 통신 단절을 일으켜 안전 상태로 전환하는지 확인합니다.
3. MCU나 RTOS를 바꾼 뒤 설치 가능 여부와 자원 사용량을 점검하고, 기존 기능과 복구 동작을 다시 시험합니다.

**결과·해석:** 논리 정확성과 실제 실행 환경의 제약을 함께 평가합니다.

**전제·주의:** 시간·안전 상태는 창작 가정입니다. 산업별 안전 인증 기준은 별도 확인해야 합니다.

### 답안 골격과 혼동 방지

시험 수준·유형 분류 → 임베디드 환경과 시험 단계 → 신뢰성·이식성 세부 활동·증거

- PC 시뮬레이션의 성공을 타깃 타이밍 성공으로 간주하지 않습니다.
- 이식성 용어는 2023모델 유연성과 판본을 구분합니다.

### 내용을 가리고 회상

1. HIL에서 실제인 부분과 모사되는 부분은 무엇입니까?
2. 가용성과 고장률의 측정에 필요한 조건은 무엇입니까?
3. 설치·롤백 시험에 어떤 데이터를 포함합니까?

### 적용 기준과 근거

테스트 수준·비기능 원리는 확인했습니다. MIL/SIL/PIL/HIL의 산업별 세부 표준·구성 요건은 해당 제품 공식 문서 추가 확인 대상입니다.
