# 공공 DB 표준화와 예방적 품질관리

## 서브노트

### 한눈에 이해

고객번호를 시스템마다 다른 이름·길이·코드로 저장하면 연결할 때마다 변환해야 합니다. 표준화는 같은 의미를 일관된 이름과 값의 규칙으로 저장하게 하고, 예방적 관리는 그 요구를 발주 때부터 넣습니다.

### 정의와 핵심 원리

데이터의 단어·용어·도메인·코드와 구조 산출물의 규칙을 정의·적용·변경 관리하여 상호 이해와 연계를 확보하는 활동입니다.

- 2023.4 매뉴얼의 예방적 진단 4영역/9항목은 표준 2개(표준화·상위표준 준수, 표준 관리), 구조 3개(설계, 검증, 관리), 값 2개(값 검증, 이관 값 검증), 관리체계 2개(품질관리 체계, 개방·메타데이터 체계)입니다. 총 18기준이며 검증 방식까지 요구사항에 포함합니다.
- 사업계획/RFP에서 누락을 자체 진단하고 해당 사전협의 검토를 거칩니다. 구축 중에는 설계·구현·변경 이력을 관리하며, 완료 검사와 감리에서 요구 이행·산출물을 확인합니다. 표준화는 영문 컬럼명을 바꾸는 일만이 아니라 의미·값 범위·변경 책임을 맞추는 일입니다.
- 126회 당시 2021 지침 별지10호 테이블정의서는 물리DB명, 테이블 소유자, 영문명/한글명, 유형, 관련엔터티명, 설명, 업무분류체계, 보존기간, 데이터 볼륨, 발생주기, 공개 여부/사유를 기록합니다. 명명규칙 준수, 여러 엔터티 통합 시 모두 기재, 보존기간의 월/년도 단위와 현재 저장 건수를 구별합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 표준·구조 | 뜻·형식·모델·변경이력 | 설계/RFP부터 검증 |
| 값 | 원본·연계·이관의 정확성 | 검증 계획과 개선 결과 |
| 관리체계 | 정책·조직·산출물·개방·메타데이터 | 지속 관리 책임 |

### 적용 예제

**주문테이블 정의**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** ORDER_BASE에 주문 기본정보를 보존합니다.

1. 물리DB/소유자와 영문·한글명을 적고 관련 엔터티를 주문으로 연결합니다.
2. 보존기간은 발생 시점 기준 기간으로, 볼륨은 현재 저장 행 수로 별도 적습니다.
3. RFP에 표준사전 준수·논리/물리 모델 검증·이관 대사·변경이력과 메타데이터 현행화를 요구하고 완료 때 증거를 검사합니다.

**결과·해석:** 정의서와 예방적 요구사항이 설계·검증의 연결 고리가 됩니다.

**전제·주의:** 2021 서식·2023 매뉴얼을 과거 문항 근거로 사용하며 2025 개정 서식의 동일성까지 확정하지 않습니다.

### 답안 골격과 혼동 방지

표준화 필요성·기대효과 → 4영역·9항목 → 사업 단계별 예방 활동 → 테이블 항목·작성 지침 → 현행판/기출판 구분

- 보존기간과 데이터 볼륨을 혼동하지 않습니다.
- 2023 매뉴얼을 최신 시행 고시로 표시하지 않습니다.

### 내용을 가리고 회상

1. 표준화의 단어·용어·도메인·코드는 어떻게 다릅니까?
2. 4영역과 9항목을 묶어서 회상할 수 있습니까?
3. 테이블 볼륨은 누적 거래량입니까, 보유 행 수입니까?
