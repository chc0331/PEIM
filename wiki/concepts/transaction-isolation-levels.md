# 네 격리 수준과 팬텀·직렬화 이상

## 서브노트

### 한눈에 이해

같은 거래 안에서 두 번 조회했는데 값이나 행 수가 달라질 수 있습니다. 격리 수준은 이런 변화를 어디까지 허용할지를 정하며 제품마다 최소 기준보다 더 강하게 구현하기도 합니다.

### 정의와 핵심 원리

동시에 실행되는 트랜잭션 사이에서 관찰 가능한 간섭과 이상 현상을 제한하는 보장 수준입니다.

- 더티 리드(dirty read)는 다른 트랜잭션이 커밋하지 않은 값을 읽는 현상입니다. 반복 불가능 읽기(nonrepeatable read)는 같은 행을 다시 읽을 때 커밋된 값이 달라지는 현상입니다. 팬텀 읽기(phantom read)는 같은 조건을 다시 조회했을 때 조건에 맞는 행 집합이 달라지는 현상입니다. 여러 거래가 커밋한 결과를 어떤 직렬 실행 순서로도 설명할 수 없다면 직렬화 이상입니다.
- SQL 표준의 최소 보장은 Read Uncommitted(RU)에서 세 읽기 이상을 허용합니다. Read Committed(RC)는 더티 리드를, Repeatable Read(RR)는 더티 리드와 반복 불가능 읽기를 막습니다. Serializable은 직렬화 이상까지 막습니다. 세 읽기 이상을 막았다는 사실만으로 직렬 실행과 같은 결과를 보장할 수는 없습니다.
- PostgreSQL 16에서 RU는 RC처럼 동작합니다. RR은 같은 스냅샷으로 읽기 때문에 팬텀 읽기도 막지만 쓰기 왜곡(write skew)은 생길 수 있습니다. Serializable은 직렬화할 수 없는 실행을 감지해 한 트랜잭션을 중단할 수 있습니다. 이 경우 트랜잭션 전체를 재시도하고 외부 요청의 중복 실행도 막아야 합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| Read Committed | 문장별 커밋 snapshot | 재조회 시 값·행 집합 변화 가능 |
| Repeatable Read | 표준상 반복행 안정; 제품별 강화 | PG는 팬텀도 방지하나 직렬화 이상 가능 |
| Serializable | 결과가 직렬 실행과 동등 | 대기 또는 충돌 중단·재시도 |

### 적용 예제

**당직자 write skew**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** A·B 둘 중 최소 한 명은 당직이어야 하며 둘 다 당직인 상태입니다.

1. T1·T2가 각 snapshot에서 다른 사람이 당직인 것을 확인합니다.
2. T1은 A를, T2는 B를 퇴근 처리하면 서로 다른 행이므로 단순 행 쓰기 충돌 없이 둘 다 퇴근할 수 있습니다.
3. Serializable 또는 업무 규칙을 보호하는 명시적 잠금/제약 설계로 한쪽을 대기·실패시키고 다시 판단합니다.

**결과·해석:** 같은 행 반복 읽기만 안정적이어도 업무 불변식은 깨질 수 있습니다.

**전제·주의:** 팬텀 충돌은 조건/범위 의존성을 직렬화 검출기가 충돌로 보는 문맥을 밝혀 설명합니다.

### 답안 골격과 혼동 방지

정의 → 4단계 최소 보장 표 → 행 변화/집합 변화 예시 → PG 구현 예외 → 충돌 재시도와 성능 절충

- RR이면 모든 DB에서 팬텀을 허용한다고 쓰지 않습니다.
- Serializable을 오류 없이 무조건 커밋하는 수준이라고 쓰지 않습니다.

### 내용을 가리고 회상

2. 팬텀을 막은 RR에서도 어떤 이상이 가능합니까?
3. 직렬화 실패 뒤 재시도할 업무 경계는 어디입니까?

### 적용 기준과 근거

SQL의 격리 수준과 PostgreSQL 16의 구현 차이는 공식 문서를 확인했습니다. 135회 팬텀충돌의 정확한 용어 범위는 별도 원문 교재 확인이 필요하여 해당 소요구를 부분 충족으로 표시합니다.
