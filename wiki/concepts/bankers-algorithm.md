# 은행가 알고리즘과 안전 상태

## 서브노트

### 한눈에 이해

지금 자원이 남았다는 이유만으로 빌려주지 않고, 모든 고객이 끝낼 수 있는 순서가 남는지 먼저 계산합니다.

### 정의와 핵심 원리

은행가 알고리즘은 최대 자원 요구를 사전에 알고 요청을 가상 배정한 상태가 안전한 경우에만 허용하는 교착 회피 기법입니다. 안전 상태는 각 작업이 남은 요구를 받아 완료할 수 있는 안전 순서가 존재하는 상태입니다.

- Allocation은 현재 할당량, Max는 선언한 최대 요구량, Available은 미할당량입니다. 남은 요구량은 Need = Max − Allocation으로 계산합니다. 자원 종류가 여러 개라면 종류마다 비교합니다.
- 안전성 검사는 Work = Available로 시작합니다. Need ≤ Work인 미완료 작업이 끝날 수 있다고 가정하고 그 작업의 Allocation을 Work에 더합니다. 이 과정을 반복해 모든 작업이 끝날 수 있다면 안전 순서가 있습니다. 새 요청은 Need와 Available 이하인지 먼저 확인한 뒤 임시로 배정해 안전성을 검사합니다.
- 안전하지 않은 상태에서는 최대 요구가 실제로 들어왔을 때 모든 작업이 끝날 수 있다는 보장이 없습니다. 최대 요구량을 예측하기 어렵거나 작업과 자원 종류가 늘어나는 환경에서는 배정이 보수적이거나 관리 부담이 커질 수 있습니다.

### 적용 예제

**단일 자원 안전 순서 직접 검산**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 총 자원은 10이고 남은 자원(Available)은 3입니다. 현재 보유량과 최대 요구량은 각각 A가 3과 7, B가 2와 4, C가 2와 3입니다.

1. 남은 요구량(Need)은 A = 4, B = 2, C = 1입니다.
2. Work = 3에서 B를 완료할 수 있습니다. B가 자원 2를 돌려주면 Work = 3 + 2 = 5입니다.
3. 이제 A를 완료할 수 있습니다. A가 자원 3을 돌려주면 Work = 5 + 3 = 8입니다.
4. C도 완료할 수 있습니다. Work = 8 + 2 = 10이므로 B → A → C는 안전 순서입니다.
5. A에 자원 3을 먼저 배정하면 Available = 0이고, 남은 요구량은 A = 1, B = 2, C = 1입니다. 어느 작업도 완료할 수 없어 요청을 보류합니다.

**결과·해석:** 남은 자원보다 작은 요청이라도 배정한 뒤 안전 순서가 사라지면 보류합니다.

**전제·주의:** 작업이 완료된다고 가정할 때 Work에 더하는 값은 그 작업의 현재 할당량(Allocation)입니다.

### 답안 골격과 혼동 방지

교착회피 정의 → 네 자료 구조 → 요청 검사·가상할당·안전성 → 표 계산 → 한계

- 불안전과 교착을 동일시하지 않습니다.
- 행·열을 바꾸거나 자원벡터를 합산 비교하지 않습니다.

3. 안전 순서 하나가 실제 실행 순서를 강제합니까?
