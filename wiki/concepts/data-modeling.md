# 데이터 모델링

## 서브노트

### 정의

데이터 모델링은 업무 규칙과 데이터 의미·구조·관계를 개념·논리·물리 수준으로 표현해 공유 가능한 데이터 구조로 만드는 활동이다. 데이터 항목의 식별·명명·정의·분류·매핑은 모델의 해석과 재사용을 돕는다.

### 핵심 구조·도식

`업무 규칙 → 개념 모델(엔터티·관계) → 논리 모델(속성·정규화) → 물리 모델(테이블·인덱스) → 구현·품질 점검`

### 답안 키워드·비교·적용

| 수준 | 목적 |
| --- | --- |
| 개념 | 업무 용어와 핵심 객체의 합의 |
| 논리 | 속성·식별자·관계·정규화 설계 |
| 물리 | DBMS 특성과 성능을 반영한 구현 |
| 메타데이터 | 정의·명명·소유자·변경 이력 관리 |
| 품질 | 완전성·일관성·무결성 검증 |

정규화는 갱신 이상을 줄이는 데 유용하지만, 조회 성능·분석 요구에는 비정규화가 필요할 수 있다. 비정규화는 목적·영향·동기화 규칙을 함께 기록한다.

### 한계·리스크

기술팀만 모델을 만들면 업무 의미가 틀어진다. 지나친 물리 최적화는 데이터 중복과 정합성 문제를 만들 수 있다.

### 답안 골격

- **1교시:** 정의 → 3단계 모델 도식 → 핵심 산출물 → 정규화·비정규화 비교 → 품질 효과.
- **논술형:** 업무 규칙·용어 → 모델링 절차 → 표준·메타데이터 → 품질·성능 검증 → 변경관리.

### 회상 확인

1. 개념·논리·물리 데이터 모델의 차이를 설명하라.
2. 정규화와 비정규화의 목적·위험을 비교하라.
3. 데이터 정의의 불일치를 예방할 관리 항목은 무엇인가?
