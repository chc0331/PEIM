# 전사 아키텍처(EA)

## 서브노트

### 정의

EA는 업무·데이터·응용·기술 등 전사 정보자원의 현재와 목표 구조를 일관된 관점으로 표현하고, 변화와 투자를 관리하는 체계다. 개별 시스템 최적화보다 중복 제거, 상호운용성, 변화 영향 분석을 지원한다.

### 핵심 구조·도식

`업무(Business) ↔ 데이터(Data) ↔ 응용(Application) ↔ 기술(Technology) → 표준·원칙·전환계획`

### 답안 키워드·비교·적용

| 요소 | 관리 대상 |
| --- | --- |
| 현행/목표 | As-Is와 To-Be의 갭 |
| 참조모델 | 공통 구조·재사용 기준 |
| 표준 | 데이터·인터페이스·기술 선택 기준 |
| 이행 | 우선순위·의존성·전환 로드맵 |
| 현행화 | 사업 변화에 따른 산출물 갱신 |

EA는 ISP의 전략 의사결정 근거가 될 수 있지만 ISP 전체를 대체하지 않는다. 조직 규모와 변경 빈도에 맞춰 최소 핵심 산출물부터 관리한다.

### 한계·리스크

완벽한 모델을 먼저 만들려 하면 최신성이 사라진다. 현업·개발 프로젝트가 아키텍처 원칙을 따를 유인과 변경 절차가 없으면 문서 저장소가 된다.

### 답안 골격

- **1교시:** 정의 → 4개 아키텍처 도식 → 구성요소 → ISP와 차이 → 활용 효과.
- **논술형:** 현황 진단 → 목표 원칙·참조모델 → 표준·거버넌스 → 전환 로드맵 → 현행화 지표.

### 회상 확인

1. EA의 네 관점과 각 관점의 산출물 예를 말하라.
2. EA 현행화가 필요한 사건 세 가지를 제시하라.
3. EA가 문서화로만 끝나는 원인과 개선책은 무엇인가?
