# 마이크로서비스 아키텍처(MSA)

## 서브노트

### 정의

MSA는 업무 기능을 독립적으로 개발·배포·확장할 수 있는 작은 서비스로 나누고, API 기반 통신으로 전체 시스템을 구성하는 아키텍처 방식이다. 서비스 분할만으로 성공하지 않으며 운영 자동화와 분산 환경 통제가 함께 필요하다.

### 핵심 구조·도식

`클라이언트 → API Gateway → 서비스 A/B/C ↔ 각 서비스 데이터 → 관측성·보안·배포 플랫폼`

### 답안 키워드·비교·적용

| 요소 | 답안 포인트 |
| --- | --- |
| 서비스 경계 | 업무 도메인·변경 주기 중심 분할 |
| 독립 배포 | 팀·파이프라인·버전 호환성 확보 |
| 통신 | API 계약·서비스 탐색·보안 통신 |
| 회복성 | 타임아웃·재시도·차단기·부하분산 |
| 관측성 | 로그·메트릭·추적으로 분산 장애 분석 |

모놀리식은 단순한 배포·트랜잭션 관리에 유리할 수 있고, MSA는 독립 배포·확장 요구가 크고 운영 역량이 갖춰진 경우에 적합하다.

### 한계·리스크

서비스를 너무 잘게 나누면 네트워크·데이터 정합성·장애 분석 복잡도가 증가한다. 중앙 표준 없이 자율성만 주면 API·보안·운영 방식이 분열된다.

### 답안 골격

- **1교시:** 정의 → 구성 도식 → 핵심 특성 → 모놀리식 비교 → 적용·보안 유의사항.
- **논술형:** 분할 기준 → API·데이터 전략 → 배포·관측성·보안 → 회복성 → 전환 단계·측정 지표.

### 회상 확인

1. MSA와 모놀리식의 장단점을 비교하라.
2. 서비스 간 통신에서 필요한 보안·운영 요소를 제시하라.
3. MSA 전환을 보류해야 하는 조건은 무엇인가?
