# 오류 검출·정정과 Stop-and-Wait·Go-Back-N

## 서브노트

### 한눈에 이해

잘못 온 것을 알아내는 것과 원래 값을 복원하는 것은 다르며, 복원 대신 다시 보내 달라고 할 수도 있습니다.

### 정의와 핵심 원리

오류 검출은 중복 정보를 통해 수신 데이터의 손상을 찾아내는 기능이고 오류 정정은 재전송 없이 일정 범위의 오류를 복원하는 기능입니다. ARQ는 검출·순서 번호·ACK·타이머와 재전송을 결합합니다.

- 패리티는 단순하지만 짝수 개 비트가 뒤집히는 오류를 놓칩니다. CRC는 생성 다항식에 대한 이진 다항식 나머지로 오류를 검출하며, 검출할 수 있는 범위는 생성 다항식과 오류 유형에 따라 달라집니다. FEC는 Hamming·Reed-Solomon·LDPC처럼 정해진 부호로 수신자가 오류를 고칠 수 있게 합니다.
- Stop-and-Wait는 프레임 하나를 보낸 뒤 ACK를 기다리고 timeout이면 재전송합니다. 교대 순서 번호로 ACK 손실 뒤의 중복을 구별합니다. 전파 지연이 긴 경로에서는 한 번에 하나라는 제약으로 이용률이 낮습니다.
- Go-Back-N은 송신 윈도우 내 여러 프레임을 연속 전송하고 누적 ACK를 사용합니다. 수신기가 다음 기대 프레임만 받아들이는 기본형에서 중간 프레임 손실 시 해당 프레임부터 뒤의 미확인 프레임을 재전송합니다. 순서 번호 공간·윈도우 크기·타이머 규칙을 명시해야 합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| Stop-and-Wait | 1개 전송 후 대기 | 단순·긴 RTT에서 비효율 |
| Go-Back-N | 윈도우·누적 ACK | 손실 뒤 정상 프레임도 재전송 |
| Selective Repeat | 선택 재전송·버퍼 | 복잡도·순서 번호 공간 증가 |

### 적용 예제

**이용률과 손실 복구**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 프레임 송신에 1 ms, 편도 전파에 4 ms가 걸립니다. ACK 송신 시간과 오류는 이용률 계산에서 생략합니다.

1. Stop-and-Wait의 한 주기는 1 + 2×4 = 9 ms입니다. 송신 이용률은 1/9, 약 11.1%입니다.
2. 송신 윈도우가 9프레임이면 이상적인 조건에서 송신이 끊기지 않습니다.
3. 별도 손실 예에서 Go-Back-N이 0, 1, 2, 3번 프레임을 보냈는데 1번을 잃었다고 가정합니다. 기본 수신기는 2번과 3번을 버리고 1번을 기다립니다.
4. 타이머가 만료되면 송신기는 1번부터 확인을 받지 못한 프레임을 다시 보냅니다.

**결과·해석:** 대역폭과 지연의 곱이 클수록 여러 프레임을 연달아 보내는 방식이 유리합니다.

**전제·주의:** 계산은 처리·ACK 송신·큐잉 시간을 생략했습니다. 실제 동작은 링크 규격에 따라 다릅니다.

### 답안 골격과 혼동 방지

검출·정정·ARQ 관계 → 두 절차 시간축 → 윈도우 비교 → 이용률 계산 → 번호·타이머 고려

- CRC를 암호학적 무결성으로 보지 않습니다.
- 누적 ACK를 프레임별 ACK와 혼동하지 않습니다.

3. RTT가 10배이면 정지 대기 효율은 어떻게 됩니까?

### 적용 기준과 근거

TCP 자료로 ARQ의 일반 원리를 대조하고 예제 계산을 직접 검산했습니다. Go-Back-N의 링크 규격과 오류정정부호 표준 원문은 확인이 남아 있습니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.
