# 오류 검출·정정과 Stop-and-Wait·Go-Back-N

## 서브노트

### 한눈에 이해

잘못 온 것을 알아내는 것과 원래 값을 복원하는 것은 다르며, 복원 대신 다시 보내 달라고 할 수도 있습니다.

### 정의와 핵심 원리

오류 검출은 중복 정보를 통해 수신 데이터의 손상을 찾아내는 기능이고 오류 정정은 재전송 없이 일정 범위의 오류를 복원하는 기능입니다. ARQ는 검출·순서 번호·ACK·타이머와 재전송을 결합합니다.

- 패리티는 단순 하지만 짝수 개 비트 반전 등을 놓칩니다. CRC는 생성다항식에 대한 이진 다항식 나머지로 검출하며 모든 손상을 확률0으로 잡는 기능은 아닙니다. FEC는 Hamming·Reed-Solomon·LDPC등 부호의 거리와 복잡도에 따라 정정능력이 정해집니다.
- Stop-and-Wait는 프레임 하나를 보낸 뒤 ACK를 기다리고 timeout이면 재전송합니다. 교대 순서 번호로 ACK손실 뒤의 중복을 구별합니다. 전파지연이 긴 경로에 서 는 한 번에 하나라는 제약으로 이용률이 낮습니다.
- Go-Back-N은 송신윈도우내 여러 프레임을 연속 전송하고 누적ACK를 사용합니다. 수신기가 다음 기대 프레임만 받아들이는 기본형에서 중간 프레임 손실 시 해당프레임부터 뒤의 미확인 프레임을 재전송합니다. 순서 번호 공간·윈도우크기·타이머 규칙을 명시해야 합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| Stop-and-Wait | 1개 전송 후대기 | 단순·긴RTT에서 비효율 |
| Go-Back-N | 윈도우·누적ACK | 손실 뒤 정상프레임도 재전송 |
| Selective Repeat | 선택 재전송·버퍼 | 복잡도·순서 번호 공간 증가 |

### 적용 예제

**이용률과 손실 복구**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 프레임송신1ms, 편도전파4ms, ACK시간무시;오류없음

1. Stop-and-Wait 주기는 1+2×4=9ms이 므로 이용률은1/9≈11.1%입니다.
2. 윈도우W=9이면 이상적 파이프라인에 서 경로를 채울 수 있습니다.
3. GBN에서0, 1, 2, 3전송중1손실이면 기본 수신기는 2·3을 버리고1을 기대합니다.
4. 타이머 만료 후1부터 미확인 프레임을 재전송합니다.

**결과·해석:** 대역·지연곱이 커질수록 파이프라인의 효과가 커집니다.

**전제·주의:** 계산은 처리·ACK전송·큐잉을 무시한 가정입니다. 링크규격별 실제 동작은 다를 수 있습니다.

### 답안 골격과 혼동 방지

검출·정정·ARQ 관계 → 두 절차 시간축 → 윈도우 비교 → 이용률 계산 → 번호·타이머 고려

- CRC를 암호학적 무결성으로 보지 않습니다.
- 누적ACK를 각프레임 개별ACK와 혼동하지 않습니다.

ARQ일반 원리를 TCP 자료로 교차확인했으나GBN링크규격·부호원표준은 직접 미열람. 계산은 자체검산.
