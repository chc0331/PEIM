# 블록·파일·오브젝트 스토리지와 가상화

## 서브노트

### 한눈에 이해

작은 주소 단위로 읽고 쓸지, 폴더와 파일로 공유할지, 메타데이터를 가진 객체로 저장할지 업무 접근 방식에 맞춥니다.

### 정의와 핵심 원리

블록 스토리지는 주소가 있는 고정 크기 단위로 데이터를 읽고 씁니다. 파일 스토리지는 계층형 경로와 파일 공유 기능을 제공합니다. 오브젝트 스토리지는 식별자·본문·메타데이터로 구성된 객체를 API로 다룹니다. 스토리지 가상화는 여러 물리 저장 자원을 논리 볼륨이나 풀로 묶어 제공합니다.

- 블록은 호스트 파일 시스템이나 DB가 구조를 관리하고 임의 입출력의 지연이 짧아야 할 때 사용합니다. 파일은 NFS·SMB 등으로 여러 사용자가 경로·권한·잠금을 공유합니다. 오브젝트는 대규모 비정형 데이터, 버전과 수명 주기를 API로 관리하기 쉽습니다. 블록 장치의 제자리 수정이나 POSIX 파일과 같은 방식으로 작동하지는 않습니다.
- 초당 입출력 횟수(IOPS), 처리량, p95 지연, 객체·파일 크기, 동시성, 일관성, 권한, 내구성, 복구와 비용을 비교합니다. 오브젝트 스토리지의 일관성은 제품별로 확인합니다.
- 가상화 계층은 호스트·스토리지 컨트롤러·네트워크 등에 주소 매핑을 두어 자원을 묶거나 필요에 따라 할당하고 옮길 수 있게 합니다. 인밴드는 제어와 데이터가 모두 가상화 장치를 지나고, 아웃오브밴드는 메타데이터 제어 경로와 실제 입출력 경로를 나눕니다. 메타데이터와 가상화 계층에도 장애 대비가 필요합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 블록 | 주소와 임의 입출력 | DB·가상 머신 디스크 |
| 파일 | 경로·공유·파일 권한 | 공동 작업·POSIX 작업 |
| 오브젝트 | 객체 ID·API·메타데이터 | 학습 원본·백업·대규모 비정형 데이터 |

### 적용 예제

**AI 학습 저장 계층**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 원본 영상 100 TB를 보관하고, 공동 라벨링 도구와 학습용 캐시, 메타데이터 DB를 운영합니다.

1. 원본 영상과 버전을 오브젝트 스토리지에 두고 보관 기간을 정합니다.
2. 공동 라벨링 도구가 파일 경로·공유 기능을 필요로 하면 파일 스토리지를 사용합니다.
3. 학습 중 자주 읽는 데이터는 로컬 또는 병렬 캐시에 둡니다.
4. 메타데이터 DB에는 지연과 복구 요구를 만족하는 블록 스토리지를 검토합니다.

**결과·해석:** 원본 보관, 협업, 반복 읽기, 트랜잭션은 접근 방식이 다르므로 저장소를 조합합니다.

**전제·주의:** 분류 기준은 데이터를 다루는 방식입니다. 실제 성능과 일관성·비용은 제품을 측정하고 계약을 확인합니다.

### 답안 골격과 혼동 방지

세 접근 방식 도식 → 비교표 → 입출력 요구 → 가상화 위치와 유형 → AI 학습 사례

- 오브젝트를 폴더 없는 파일 시스템 하나로만 설명하지 않습니다.
- 가상화 계층의 장애와 저장소 풀의 용량 고갈도 검토합니다.

### 내용을 가리고 회상

1. DB에 블록 스토리지를 쓰는 경우가 많은 이유는 무엇입니까?
2. 오브젝트와 POSIX 파일은 어떤 연산에서 다르게 동작합니까?
3. 필요할 때마다 실제 공간을 할당하는 방식(씬 프로비저닝)은 어떤 경우에 용량이 모자랄 수 있습니까?
