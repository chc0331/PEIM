# 로우코드·노코드 플랫폼

## 서브노트

### 한눈에 이해

화면을 끌어다 만드는 속도뿐 아니라, 만들어진 앱의 권한·데이터·변경을 누가 관리하는지도 설계해야 합니다.

### 정의와 핵심 원리

로우코드는 시각 모델·템플릿·연결자와 필요한 코드를 결합하여 앱 개발을 단순화하고, 노코드는 정해진 기능과 설정 중심으로 프로그래밍 부담을 더 줄이는 플랫폼 접근입니다.

- 주요 특징은 모델 기반 화면·업무흐름, 데이터 연결자, 재사용 컴포넌트, 자동 생성/실행, 통합 배포·모니터링입니다. 로우코드는 전문 개발자의 확장 코드를 허용하는 경우가 많고 노코드는 업무 사용자의 구성 범위 안 해결을 지향하지만 제품별 경계는 연속적입니다.
- 적용 전 업무 복잡성, 사용자 규모, 지연·가용성, 연계 API, 데이터 위치·분류, 모바일·접근성, 배포와 버전·시험 가능성을 평가합니다. 간단한 승인·조회 앱은 적합할 수 있으나 복잡한 최적화·실시간 제어는 별도 기술이 필요할 수 있습니다.
- 한계는 공급자 종속·이식성, 라이선스와 호출비용, 성능/확장 제약, 디버깅·자동시험의 제약, 시민개발자의 보안 실수와 그림자 IT입니다. 생성된 코드가 보이지 않아도 책임이 사라지지 않습니다.
- CoE가 환경·계정·연결자·데이터 손실방지 정책·소유자·폐기 규칙·승인 게이트·교육을 운영하고 전문 개발자는 공통 API·배포 자동화·복잡한 확장을 지원합니다. PoC로 요구 적합성과 총비용을 검증한 뒤 범위를 확장합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 노코드 | 기성 기능과 설정 중심 | 빠른 소규모 업무 앱, 확장 제한 |
| 로우코드 | 시각모델+선택적 코드 | 개발자 확장과 복잡 연계 가능 |
| 일반 개발 | 코드로 세밀한 제어 | 자유도와 구축·운영 책임 증가 |

### 적용 예제

**강사 창작 적용 예시: 휴가 승인 앱**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 사내 직원 200명의 휴가 신청·승인을 자동화합니다.

1. 신청폼·승인흐름을 시각 모델로 만들고 인사 API 연결 권한을 제한합니다.
2. 관리 환경에만 배포하고 소유자·감사로그·퇴사자 권한 회수를 정합니다.
3. API 지연과 호출비용, 데이터 내보내기·플랫폼 종료 절차를 시험합니다.

**결과·해석:** 개발 속도와 조직 통제를 함께 검증한 적용안을 얻습니다.

**전제·주의:** 직원 수와 도구 구성은 창작 예시이며 특정 제품의 성능 보장이 아닙니다.

### 답안 골격과 혼동 방지

특징 및 no-code 비교 → 적용조건·한계 → CoE·ALM·PoC 대응 사례

- 노코드는 데이터·권한 설계까지 필요 없다는 뜻이 아닙니다.
- 플랫폼 제품마다 확장과 코드 추출 범위가 다릅니다.

### 내용을 가리고 회상

1. 노코드로 만들기 어려운 요구를 하나 제시하십시오.
2. CoE가 최소한 관리할 세 가지는 무엇입니까?
3. 구독료 외의 총비용 항목은 무엇입니까?

### 적용 기준과 근거

Microsoft 공식 CoE 문서를 실제 열람했습니다. 로우코드/노코드는 제품별 용어 경계가 다르므로 일반화된 비교로 제시했습니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [Power Platform Center of Excellence Starter Kit overview](https://learn.microsoft.com/en-us/power-platform/guidance/coe/overview) — Microsoft; 지속 갱신 문서; 확인 2026-11-05. 확인 범위: 공식 제품 문서의 CoE 개념·거버넌스·활성화 범위 열람. 특정 제품 구현 예이지 일반 조직의 의무모델이 아닙니다.
