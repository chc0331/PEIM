# IPsec·TLS VPN과 Tor

## 서브노트

### 한눈에 이해

VPN은 터널의 두 종단 사이를 보호합니다. Tor는 출발지와 목적지의 관계가 한곳에서 드러나기 어렵게 중계 경로를 구성합니다.

### 정의와 핵심 원리

VPN은 공용망 위에 논리적 사설 연결을 만들고 정책에 따라 트래픽을 보호합니다. IPsec은 IP 계층에서 보호하고 TLS VPN은 TLS 기반 원격 접속·응용 터널을 제공합니다. Tor는 여러 중계 노드를 통한 계층 암호화로 출발지와 목적지 관계의 노출을 줄이는 익명 통신망입니다.

- IPsec에서 SA는 알고리즘·키·시퀀스 번호 등 보안 연결의 상태를 정의합니다. SPD는 보호 정책, SAD는 SA 상태를 관리합니다. ESP는 기밀성·무결성 등을 제공할 수 있습니다. 전송 모드와 터널 모드의 보호 범위, 키 협상·상대 인증·재전송 공격 방지를 구분합니다.
- TLS VPN은 브라우저 포털 또는 에이전트 등을 통해 접속하고 사용자·단말·응용 수준 정책과 연결할 수 있습니다. 실제 보호 범위는 구현·split tunneling·DNS·로컬 경로에 따라 달라집니다. 터널 종단·인증서·취약한 게이트웨이도 보호해야 합니다.
- Tor의 각 중계 노드는 경로 일부만 알기 때문에 한 관측점에서 출발지와 목적지를 연결하기 어렵습니다. VPN은 주로 게이트웨이와 제공자를 신뢰해야 합니다. Tor에서도 지연, 출구 관측, 종단 식별, 트래픽 상관 분석 위험은 남습니다. 출구 이후 구간의 기밀성을 보호하는 데 HTTPS가 중요합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| IPsec VPN | IP 계층·SA·터널 | 사이트 간 연결·원격 접속 |
| TLS VPN | TLS 기반 응용·네트워크 접속 | 구현에 따라 접근 범위가 다름 |
| Tor | 계층 암호화·다중 중계 | 익명성 한계·지연 |

### 적용 예제

**원격 업무 접속**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 직원 단말 → VPN 게이트웨이 → 업무 서버

1. 상대 장비와 사용자를 인증하고 단말 상태를 확인합니다.
2. 업무에 필요한 응용에만 접속하도록 권한을 제한합니다.
3. 터널 밖에서 쓰는 DNS와 트래픽 경로를 확인하고 로그의 민감 정보를 살핍니다.
4. 게이트웨이를 주기적으로 패치하고 세션을 회수할 기준과 감사 절차를 마련합니다.

**결과·해석:** 터널 암호화와 함께 접근 권한 및 단말 보호를 점검합니다.

**전제·주의:** Tor 사용자라는 사실이나 VPN 사용만으로 추적 불가능·불법성·합법성을 단정하지 않습니다.

### 답안 골격과 혼동 방지

VPN 정의 → IPsec 구조 → TLS VPN과 비교 → Tor 경로와 신뢰 → 적용 제약

- 단말의 악성 코드 감염은 터널 암호화와 별도로 대응합니다.
- Tor 출구 이후 구간도 암호화되는지, HTTPS 사용 여부를 확인합니다.

### 적용 기준과 근거

명시한 출처 판본의 원리를 설명하며 제품별 구현 차이는 별도 확인합니다.

**내용 검토 상태: 출처 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [RFC4301: Security Architecture for IP](https://www.rfc-editor.org/rfc/rfc4301.html) — S. Kent; K. Seo / IETF; 2005-12; 확인 2026-11-05. 확인 범위: IPsec·SA·SPD/SAD 및 transport/tunnel 개요 열람.
- [About Tor](https://support.torproject.org/about-tor/) — Tor Project; 상시 문서; 확인 2026-11-05. 확인 범위: 공식 소개·설계·보안 보호와 한계 목록 열람. 모든 트래픽 익명성 보장이라고 쓰지 않음.
- [RFC8446: TLS1.3](https://www.rfc-editor.org/rfc/rfc8446.html) — Eric Rescorla / IETF; 2018-08; 확인 2026-11-05. 확인 범위: 핸드셰이크·구형 알고리즘 제거·0-RTT 재전송 위험 설명 열람.
