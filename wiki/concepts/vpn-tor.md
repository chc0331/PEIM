# IPsec·TLS VPN과 Tor

## 서브노트

### 한눈에 이해

터널이 보호하는 두 끝과, 익명 경로가 숨기는 관계를 구별하고 종단과 제공자에 남는 신뢰를 봅니다.

### 정의와 핵심 원리

VPN은 공용망위에논리적사설연결을 만들고정책에 따라 트래픽을보호합니다. IPsec은IP계층에서 보호하고 TLS VPN은 TLS 기반원격접속·응용터널을제공합니다. Tor는 여러 중계노드를 통한계층 암호화로 출발지와목적지관계의 노출을 줄이는익명통신망입니다.

- IPsec은SA로보안관계·알고리즘·키·시퀀스등을 관리하고 SPD는 보호 정책, SAD는SA상태를 관리합니다. ESP는 기밀성·무결성등을 제공할 수 있으며전송 모드와 터널모드의 보호 범위를 구분합니다. 키협상과피어인증·재전송방지도중요합니다.
- TLS VPN은 브라우저포털또는에이전트등을 통해 접속하고 사용자·단말·응용수준정책과 연결할 수 있습니다. 실제 보호 범위는 구현·split tunneling·DNS·로컬경로에 따라 달라집니다. 터널종단·인증서·취약한게이트웨이도 보호해야합니다.
- Tor는 각중계가일부경로 정보만 알게하여 단일관측점의연계를 어렵게합니다. VPN은 주로단일제공자·게이트웨이에 신뢰를 모으는반면Tor는 다중중계를활용하지만지연·출구관측·종단식별·트래픽상관위험이 남습니다. HTTPS는 출구이후 기밀성에도 중요합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| IPsecVPN | IP계층·SA·터널 | 사이트간·원격접속 |
| TLS VPN | TLS 기반 응용/네트워크접속 | 구현별접근 범위 |
| Tor | 계층 암호화·다중중계 | 익명성 한계·지연 |

### 적용 예제

**원격 업무 접속**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 직원단말 → VPN 게이트웨이 → 업무 서버

1. 강한피어·사용자 인증과 단말 상태를 검증합니다.
2. 전체 내부망대신 필요응용만 허용합니다.
3. 터널밖DNS·트래픽경로와 로그의 민감정보를 확인합니다.
4. 게이트웨이패치와세션 회수·감사를정기운영합니다.

**결과·해석:** 터널암호화·인가·종단보호를 함께 다룹니다.

**전제·주의:** Tor 사용자라는사실이나VPN사용만으로추적불가능·불법성·합법성을단정하지 않습니다.

### 답안 골격과 혼동 방지

VPN정의 → IPsec구조 → TLS VPN비교 → Tor 경로·신뢰 → 실무제약

- VPN이 종단악성코드까지 치료한다고쓰지않습니다.
- Tor출구부터목적지까지항상 암호화됐다고가정하지 않습니다.

### 적용 기준과 근거

명시한 출처 판본의 원리를 설명하며 제품별 구현 차이는 별도 확인합니다.

**내용 검토 상태: 출처 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [RFC4301: Security Architecture for IP](https://www.rfc-editor.org/rfc/rfc4301.html) — S. Kent; K. Seo / IETF; 2005-12; 확인 2026-11-05. 확인 범위: IPsec·SA·SPD/SAD 및 transport/tunnel 개요 열람.
- [About Tor](https://support.torproject.org/about-tor/) — Tor Project; 상시 문서; 확인 2026-11-05. 확인 범위: 공식 소개·설계·보안 보호와 한계 목록 열람. 모든 트래픽 익명성 보장이라고 쓰지 않음.
- [RFC8446: TLS1.3](https://www.rfc-editor.org/rfc/rfc8446.html) — Eric Rescorla / IETF; 2018-08; 확인 2026-11-05. 확인 범위: 핸드셰이크·구형 알고리즘 제거·0-RTT 재전송 위험 설명 열람.
