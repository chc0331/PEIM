# 리버스 프록시·로드밸런싱·DDoS 대피

## 서브노트

### 한눈에 이해

사용자 앞에서 요청을 받아 안전한 서버로 전달하되, 회선 자체가 막히는 공격은 더 앞단에서 흡수해야 합니다.

### 정의와 핵심 원리

리버스프록시는클라이언트가 접속하는대표종단점으로서백엔드서버에 요청을 전달하고 응답을 중계합니다. 로드밸런싱은여러 대상으로 부하를분배하는기능이며 DDoS대피는대규모 공격트래픽을외부 보호망으로우회·정제하는대응입니다.

- 주요 기능은 TLS종단·캐시·압축·접근 정책·WAF연계·백엔드은닉·라우팅입니다. 단일프록시가새장애점이되지않도록다중화·상태 검사·용량·보안패치를설계합니다. Host·전달IP·프로토콜헤더를신뢰할범위와 직접 백엔드접근 차단을 정합니다.
- 동작은 클라이언트 요청 → 프록시인증·정책 → 대상 선택 → 백엔드요청 → 응답입니다. 설정에 는 upstream대상·timeout·최대본문·재시도·세션·로그를 포함합니다. 이미처리된비멱등요청을 무조건 재시도하면 중복거래위험이 있습니다.
- DDoS는 볼륨·프로토콜·응용 공격을 구분하고 회선 용량을 초과하면 서버안의방어만으로부족합니다. CDN·Anycast·대피소·ISP와 의우회·속도제한·캐시·원본 보호를 사전 준비하고 DNS·라우팅·전환조건·연락망·실전훈련을갖춥니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 리버스프록시 | 서버앞요청중계 | TLS·정책·캐시·집중점 |
| 로드밸런서 | 대상간분배·헬스체크 | 세션·용량·전환 |
| DDoS대피 | 상위망우회·정제 | 사전가입·경로·원본 보호 |

### 적용 예제

**웹사이트 공격 시 전환**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 업링크1Gbps;공격이 수Gbps로유입되는가정

1. 서비스내속도제한만으로회선고갈을해결할 수 없음을확인합니다.
2. 상위보호 서비스로 트래픽을우회하고 정상요청만 원본으로 전달합니다.
3. 원본직접 주소 노출과 우회경로를 차단합니다.
4. 정상사용자의 지연·오차단·복귀절차를 감시합니다.

**결과·해석:** 대응지점을공격 병목보다 앞으로옮기고업무 품질을 검증합니다.

**전제·주의:** 국내 DDoS 사이버대피소의현행 대상·용량·가입절차 원문은 이번조사에서미확인입니다.

### 답안 골격과 혼동 방지

정의·전달도 식 → 주요 설정 → LB차이 → 공격층별대응 → 대피소운영

- 프록시설정만 으로대역폭고갈을항상 막는다고쓰지않습니다.
- 재시도를 모든 HTTP요청에 동일적용하지 않습니다.
