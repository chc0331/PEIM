# 리버스 프록시·로드밸런싱·DDoS 대피

## 서브노트

### 한눈에 이해

리버스 프록시는 서버 앞에서 사용자 요청을 받습니다. 회선 용량을 넘는 공격은 더 앞단에서 걸러야 합니다.

### 정의와 핵심 원리

리버스 프록시는 클라이언트가 접속하는 대표 종단점으로서 백엔드 서버에 요청을 전달하고 응답을 중계합니다. 로드밸런싱은 여러 대상으로 부하를 분배하는 기능이며 DDoS 대피는 대규모 공격 트래픽을 외부 보호망으로 우회·정제하는 대응입니다.

- 주요 기능은 TLS 종단·캐시·압축·접근 정책·WAF 연계·백엔드 은닉·라우팅입니다. 프록시 한 대가 단일 장애 지점이 되지 않도록 다중화·상태 검사·용량·보안 패치를 설계합니다. Host·전달 IP·프로토콜 헤더를 신뢰할 범위와 직접 백엔드 접근 차단을 정합니다.
- 동작은 클라이언트 요청 → 프록시 인증·정책 → 대상 선택 → 백엔드 요청 → 응답입니다. 설정에는 요청을 전달할 서버·시간 제한·최대 본문 크기·재시도·세션·로그를 포함합니다. 이미 처리한 비멱등 요청을 무조건 재시도하면 중복 거래 위험이 있습니다.
- DDoS는 볼륨·프로토콜·응용 공격을 구분하고 회선 용량을 초과하면 서버 안의 방어만으로 부족합니다. CDN·Anycast·대피소·ISP와의 우회·속도 제한·캐시·원본 보호를 사전 준비하고 DNS·라우팅·전환 조건·연락망·실전 훈련을 갖춥니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 리버스 프록시 | 서버 앞에서 요청 중계 | TLS·정책·캐시·트래픽 집중 지점 |
| 로드밸런서 | 서버 간 부하 분배·상태 확인 | 세션·용량·전환 |
| DDoS 대피 | 상위망으로 우회해 공격 트래픽 제거 | 사전 가입·경로·원본 보호 |

### 적용 예제

**웹사이트 공격 시 전환**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 업링크 1 Gbps인 회선에 수 Gbps의 공격 트래픽이 들어온다고 가정합니다.

1. 서비스 내 속도 제한만으로 회선 고갈을 해결할 수 없음을 확인합니다.
2. 상위 보호 서비스로 트래픽을 우회하고 정상 요청만 원본으로 전달합니다.
3. 원본 서버의 주소가 노출되지 않도록 하고 보호망을 거치지 않는 직접 접속을 차단합니다.
4. 정상 사용자의 응답 지연과 오차단을 확인하고 원래 경로로 복귀하는 절차를 점검합니다.

**결과·해석:** 대응 지점을 공격 병목보다 앞으로 옮기고 업무 품질을 검증합니다.

**전제·주의:** 국내 DDoS 사이버 대피소의 현행 대상·용량·가입 절차 원문은 이번 조사에서 미확인입니다.

### 답안 골격과 혼동 방지

정의·전달 도식 → 주요 설정 → 로드밸런서와의 차이 → 공격 계층별 대응 → 대피소 운영

- 프록시 설정만으로 대역폭 고갈을 항상 막는다고 쓰지 않습니다.
- HTTP 요청을 재시도하기 전에 같은 요청을 다시 처리해도 되는지 확인합니다.
