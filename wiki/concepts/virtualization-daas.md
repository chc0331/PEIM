# 가상화·응용 가상화·DaaS

## 서브노트

### 한눈에 이해

실제 장비·실행 환경을 추상화해 나눠 쓰거나, 화면만 전달해 다른 장소의 프로그램을 사용하게 합니다.

### 정의와 핵심 원리

가상화는 물리 자원의 구체 구현을 감추고 논리 자원·실행 환경을 제공하는 기법입니다. 서버 VM·응용 가상화·원격 데스크톱은 격리하는 대상과 실행 위치가 다르며 DaaS는 데스크톱을 서비스로 제공하는 방식입니다.

- 일반 응용은 OS의 시스템콜·라이브러리·파일·레지스트리 등 환경에 의존합니다. 응용가 상화는 이 의존성을 패키징·리다이렉트·격리하여 충돌과 설치 부담을 줄이거나 서버에 서 실행한 응용 화면을 전달할 수 있습니다. 구현 방식을 먼저 구별합니다.
- VM은 하이퍼바이저가 가상하드웨어를 제공하고 각각 게스트OS를 실행합니다. 컨테이너는 주로 호스트커널을 공유하는 격리된 프로세스이 므로 가벼운 배포에 유리하되 보안경계와 OS호환성의 전제가 다릅니다.
- 원격데스크톱은 입력을 원격으로 보내고 화면·오디오 등을 전달합니다. RDP·ICA/HDX·PCoIP·VNC등은 압축·전송·장치리다이렉션·보안 기능이 다릅니다. DaaS는 사용자 프로필·접속인증·세션·라이선스·망지연·데이터 반출을 함께 운영해야 합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 서버 VM | 게스트OS별실행 | 격리·무게·라이선스 |
| 컨테이너 | 커널공유프로세스 | 이식·배포·커널경계 |
| DaaS | 데스크톱서비스·원격표시 | 세션·프로필·반출통제 |

### 적용 예제

**외주 개발자의 원격 작업**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 중요소스는 내부보관;개발자는 원격접속

1. 개인 단말에 서 강한 인증 후 제한된 데스크톱을 제공합니다.
2. 클립보드·드라이브·프린터 리다이렉션 필요성을 승인합니다.
3. 사용자 프로필과 작업 데이터의 수명·백업을 분리합니다.
4. 지연·동시접속·빌드부하를 측정해 자원을 산정합니다.

**결과·해석:** 데이터 보관 위치와 실제 반출 경로를 함께 관리합니다.

**전제·주의:** 화면전달만 으로촬영·악성단말·권한오용위험이 사라지지는않습니다.

### 답안 골격과 혼동 방지

일반 실행 흐름 → 응용가 상화유형 → VM·컨테이너비교 → 원격프로토콜 → DaaS운영

- 가상화와클라우드를 동의어로쓰지않습니다.
- 컨테이너마다게스트OS가 필요하다고설명하지 않습니다.
