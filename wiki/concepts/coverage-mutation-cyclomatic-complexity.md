# 커버리지·뮤테이션·순환복잡도

## 서브노트

### 한눈에 이해

커버리지를 보면 테스트가 어느 코드를 실행했는지 알 수 있습니다. 변이 시험은 테스트가 코드에 심은 작은 오류를 발견하는지 확인합니다.

### 정의와 핵심 원리

테스트 커버리지는 정한 시험 기준 항목 중 실행한 비율이며 코드 커버리지는 그 기준이 문장·분기·조건 같은 코드 구조인 경우입니다. 변이시험은 코드를 작은 오류로 바꾼 변이가 기존 시험에서 검출되는지 확인합니다.

- 커버리지=실행된 기준 항목 수/전체 기준 항목 수×100입니다. 요구·위험·플랫폼·데이터 분할 커버리지도 가능하므로 테스트 커버리지가 코드 커버리지보다 넓습니다. 문장 100%가 분기 100%를 뜻하지 않고, 분기 100%도 모든 조건 조합·경로를 보장하지 않습니다.
- McCabe V(G)=E−N+2P이며 P는 독립 연결 성분 수입니다. 단일 연결 제어 흐름에서는 단순한 이진 결정 노드 수+1과 일치하는 경우가 많으나 switch·복합논리·예외를 어떻게 CFG로 구성했는지 밝힙니다. 값은 독립 경로 기저의 크기이지 입력값 전체 수가 아닙니다.
- 변이 연산자는 >를≥로, +를−로, 반환값·조건을 바꾸는 작은 변경입니다. 원본을 통과하던 시험이 변이에서 실패하면 kill, 살아남으면 survive입니다. 변이점수는 검출 가능한 변이 중 killed의 비율로 정의하되 동등변이·타임아웃·오류생성 변이 처리 규칙을 적습니다.
- 복잡한 모듈은 분기 경계·예외·상태 조합을 집중 시험하고 의미 있는 assertion을 확인합니다. 커버리지는 시험 누락을 찾는 지표, 변이는 판정의 민감도를 점검하는 보조 수단이며 어느 것도 무결점 인증은 아닙니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 코드 커버리지 | 무엇을 실행했는가 | 실행 누락 구조 탐지 |
| 변이점수 | 작은 잘못을 시험이 잡는가 | assertion·입력의 약점 탐지 |
| 순환복잡도 | 독립 제어경로 수 | 시험 계획·구조 개선 우선순위 참고 |

### 적용 예제

**강사 창작 적용 예시: 경계 판정 변이**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** f(x)는 x>=10이면 Pass, 아니면 Fail을 반환합니다.

1. x=20만 시험하면 두 분기는 덮지 못합니다.
2. x=9와 x=20으로 두 분기를 모두 실행해도 `>=`를 `>`로 바꾸면 두 테스트의 출력은 달라지지 않습니다.
3. x=10의 기대값 Pass를 추가하면 해당 경계 변이를 검출합니다.

**결과·해석:** 실행 커버리지와 검출력의 차이를 구체적으로 설명합니다.

**전제·주의:** 원본과 동작이 같은 동등 변이는 검출할 수 없습니다. 변이 점수의 분모에서 제외하는 규칙을 밝힙니다. 복잡도만으로 코드 품질을 단정하지 않습니다.

### 답안 골격과 혼동 방지

테스트/코드 커버리지 비교 → V(G) 공식과 해석 → 변이 생성→시험→kill/survive 및 사례

- 분기 100%를 경로 100%라고 쓰지 않습니다.
- 변이점수 분모의 제외 규칙을 숨기지 않습니다.

### 내용을 가리고 회상

1. V(G)=E−N+2P에서 P는 무엇입니까?
2. 분기 커버리지가 높아도 경계 결함이 남는 이유는 무엇입니까?
3. 동등 변이는 무엇이며 점수에 어떤 영향을 줍니까?
