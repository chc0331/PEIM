# IPC와 공유 메모리 동기화

## 서브노트

### 한눈에 이해

서로 분리된 프로세스가 메시지를 보내거나 공동 공간을 열어 협력하되, 공동 공간의 갱신 순서를 따로 지킵니다.

### 정의와 핵심 원리

IPC는 프로세스 사이에 데이터·이벤트·상태를 교환하는 운영체제의 통신 메커니즘입니다. 프로세스 격리를 유지하면 서 협력·병렬처리·서비스 분리를 가능하게 합니다.

- 파이프는바이트흐름을 전달하며 익명파이프는주로관계있는 프로세스사이에서, 이름있는 FIFO는 경로를 통해 접속합니다.메시지큐는메시지 경계를 유지하고 우선순위·비동기교환에유리하지만복사와큐용량 관리가 필요합니다.
- 공유 메모리는 여러 프로세스 주소 공간에동일한 영역을 매핑하여 대용량복사를줄입니다.POSIX에서는shm_open → ftruncate → mmap후사용하고 수명에 맞춰해제합니다.데이터가 공유된다는사실이원자성·가시성·순서보장을자동제공하지 않으므로세마포어·프로세스공유뮤텍스등을 결합합니다.
- 소켓은로컬UNIX도 메인또는네트워크를 통한통신을 제공합니다.시그널은이벤트통지에적합하며 복잡한데이터 전달에 는 제약이있습니다.기법 선택은 전달량·지연·메시지 경계·생산자/소비자관계·권한·오류 복구로 판단합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 파이프·큐 | 커널이전달·버퍼관리 | 프레이밍·역압·용량 |
| 공유 메모리 | 같은 페이지매핑 | 별도 동기화·수명 관리 |
| 소켓 | 로컬·원격종단점 | 직렬화·접속·부분전송 |

### 적용 예제

**유한 버퍼 생산자·소비자**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** N=4칸;empty4, full0, mutex1

1. 생산자는P(empty) → P(mutex) → 쓰기 → V(mutex) → V(full)입니다.
2. 소비자는P(full) → P(mutex) → 읽기 → V(mutex) → V(empty)입니다.
3. 버퍼가비면소비자는full에서대기하고 가득차면생산자는empty에서대기합니다.
4. mutex를 잡은채empty를 기다리면상대의반환작업을 막을수 있어잠금 순서를 검토합니다.

**결과·해석:** 상호배제와빈칸·데이터존재순서를 분리하여 오버런·언더런을방지합니다.

**전제·주의:** 개념적의사코드이며 취소·프로세스죽음·복구 정책은 운영 요구에 맞춰보완합니다.

### 답안 골격과 혼동 방지

IPC필요성 → 기법별구조 → 통신과 동기화분리 → P/V버퍼예 → 성능·복구판단

- 공유 메모리는 네트워크공유파일과같은 개념이 아닙니다.
- 메시지큐가애플리케이션트랜잭션을자동보장하지 않습니다.
