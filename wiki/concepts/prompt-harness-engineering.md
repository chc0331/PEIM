# 프롬프트와 하네스 엔지니어링

## 서브노트

### 한눈에 이해

프롬프트는 모델에 할 일과 답변 형식을 알려 줍니다. 하네스는 모델 호출을 관리하는 프로그램입니다. 실행 도구를 연결하고, 진행 상태를 저장하고, 결과를 검사하거나 실패한 단계를 다시 실행합니다.

### 정의와 핵심 원리

프롬프트 엔지니어링은 입력 지시·문맥·예시·출력 제약을 설계하는 활동이며 하네스는 모델 호출을 둘러싼 실행 환경과 상태·도구·검증 흐름을 설계하는 활동입니다.

- 프롬프트는 목적·대상·완료 조건·입력 자료의 경계·출력 schema·예시·불확실성 처리 기준을 명확히 합니다. zero/few-shot·역할/제약·근거 제공·분해·검증 단계를 필요에 맞게 쓰며 특정 문구가 모든 모델·버전에서 같은 효과를 낸다고 가정하지 않습니다.
- 하네스는 도구 사용과 권한, 환경 초기화, 모델에 보낼 문맥, 진행 기록, 종료 조건, 재시도, 평가를 관리합니다. 긴 작업이라면 세션이 바뀌어도 다음 실행이 결과와 실패 지점을 읽을 수 있게 기록을 남깁니다. 완료 여부는 모델의 말이 아니라 검사 결과로 판단합니다.
- 둘은 대체가 아니라 결합 관계입니다. 입력/출력 예시를 고치면 모델 행동이 바뀌고 실행 policy·도구·평가를 고치면 시스템 행동이 바뀝니다. 고정 평가셋·실제 과업 성공률·근거 오류·재시도 수·지연/비용으로 변경을 비교하며 사소한 작업에 복잡한 loop를 불필요하게 만들지 않습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| Prompt | 모델 한 호출의 목표·문맥·출력 | 명확성·예시·제약 |
| Harness | 호출 주변의 상태·도구·검증 | 지속 실행·인계·복구 |
| 평가 | 실제 성공·정확도·비용 | 모델 발화만으로 완료 판정 금지 |

### 적용 예제

**계약서 항목 추출**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 계약서에서 기간·금액·해지 조건을 JSON으로 만들고 검토자에게 넘깁니다.

1. 프롬프트에 원문 근거의 위치를 함께 답하도록 적습니다. 값이 없으면 `null`로 쓰게 하고, 항목별 자료형과 출력 예시를 줍니다.
2. 하네스는 파일 로딩·문서별 상태·schema 검사·누락 검사·실패 재시도·검토 큐를 관리합니다.
3. 평가셋에서 누락/환각·schema 오류·처리 비용을 비교하고 실패한 문서를 성공으로 기록하지 않습니다.

**결과·해석:** 지시 설계와 실행 관리의 책임을 구분하면 문제 원인을 찾기 쉽습니다.

**전제·주의:** 법률 판단의 자동 확정 예시가 아니라 텍스트 추출 workflow를 설명하는 가상 사례입니다.

### 답안 골격과 혼동 방지

정의·범위 → prompt 기술요소 → harness 구성·상태 인계 → 같은 과업 비교 → 평가·비용·완료 조건

- 하네스를 더 긴 프롬프트의 동의어로 쓰지 않습니다.
- 모델 버전 변경 후 기존 평가 없이 같은 동작을 기대하지 않습니다.

### 내용을 가리고 회상

1. 출력 JSON schema는 prompt와 harness 양쪽에서 어떻게 쓰입니까?
2. 세션이 바뀔 때 무엇을 남겨야 합니까?
3. 모델의 완료 선언과 실제 성공을 어떻게 구분합니까?
