# 파일·데이터베이스·블록체인의 데이터 저장 비교

## 서브노트

### 한눈에 이해

문서를 보관할 때는 파일이 간단하고, 수많은 주문을 함께 고칠 때는 DB의 질의·트랜잭션 기능이 유용합니다. 서로 다른 조직이 같은 거래 이력을 합의해야 한다면 분산 원장을 검토합니다. 하나가 다른 둘을 모두 대체하는 발전 순서는 아닙니다.

### 정의와 핵심 원리

파일은 이름·경로와 바이트/레코드 단위로 내용을 저장하는 방식이고, DBMS는 구조·질의·무결성·동시 처리 기능으로 데이터를 관리합니다. 블록체인은 여러 참여자가 공유하는 거래 기록을 분산 원장으로 유지하는 구조입니다.

- 파일 저장에서는 해석할 형식·스키마·검증·중복 관리·동시 수정 규칙을 응용이 맡는 범위가 큽니다. 파일 시스템에도 권한·저널·잠금 기능은 있으므로 파일 저장에 무결성이나 복구가 전혀 없다고 단정하지 않습니다. 대용량 원본·문서·단순 교환에 적합한 사례가 있습니다.
- DBMS는 논리 데이터와 프로그램을 분리하고 질의·색인·제약·트랜잭션·복구로 공유 데이터를 관리합니다. 관계형/문서형 등 모델과 제품마다 제공 기능·격리·확장 제약이 다르며, DB를 쓴다고 중복·오류가 저절로 제거되지는 않습니다. 운영 책임·스키마·권한 설계가 필요합니다.
- 블록체인은 단일 관리 주체를 그대로 신뢰하기 어려운 참여자 간 거래 기록 공유·합의가 핵심입니다. 정상 네트워크 동작 조건에서 게시 기록의 변조를 탐지/억제하지만 입력의 현실 진실성을 보장하지 않습니다. 복제·검증의 비용, 공개 범위·삭제 요구·처리 지연을 따져 원본 데이터는 외부 저장소에 두고 이력만 연결할 수도 있습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 파일 | 이름·경로/형식으로 저장·읽기 | 원본 보관·교환; 응용의 해석·일관성 책임 |
| 데이터베이스 | 질의·제약·트랜잭션으로 관리 | 공유 업무 데이터; 운영·설계 비용 |
| 블록체인 | 참여자 간 공유 원장·합의 | 조직 간 이력; 비용·거버넌스·입력 검증 |

### 적용 예제

**품질검사 자료를 저장하는 선택**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 한 공장의 검사 사진과 수치 결과를 여러 회사가 검토하려고 합니다.

1. 사진 원본은 파일/객체 저장소에 보관하고 식별자·버전·권한을 정합니다.
2. 검사 결과·제품·검토 상태는 DB에 저장하여 조회·제약·동시 수정을 관리합니다.
3. 여러 회사가 승인 이력을 공동 검증할 필요가 실제 있는지 확인한 뒤 공유 원장에 승인·참조 이력을 남기는 구조를 비교합니다.

**결과·해석:** 데이터 크기·질의·변경·신뢰 경계에 따라 저장 방식을 결합할 수 있습니다.

**전제·주의:** 원장에 사진의 해시를 남겨도 촬영 대상과 검사 내용이 사실이라는 점까지 증명하지는 않습니다.

### 답안 골격과 혼동 방지

저장/관리 단위 정의 → 구조·처리·무결성·신뢰 비교 → 일관성·복구·비용 → 검사 자료 결합 예 → 선정 조건·한계

- DBMS와 파일 시스템, 그 위의 응용 기능을 같은 계층으로 비교하지 않습니다.
- 블록체인을 무조건 불변·무결한 사실 저장소로 표현하지 않습니다.

### 내용을 가리고 회상

1. 파일과 DB에서 일관성 규칙의 관리 책임은 어떻게 다릅니까?
2. 여러 조직의 승인 이력에 분산 원장을 검토하는 이유는 무엇입니까?
3. 데이터 해시가 현실 입력의 진실을 보장하지 못하는 이유는 무엇입니까?

### 적용 기준과 근거

NIST 공식 초록과 DBMS 공식 문서의 확인 범위를 결합한 강사 비교입니다. 파일 시스템 상세·블록체인 합의 알고리즘 본문·제품별 삭제/지연 특성은 추가 확인 범위입니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [Blockchain Technology Overview, NIST IR 8202](https://csrc.nist.gov/pubs/ir/8202/final) — Dylan Yaga, Peter Mell, Nik Roby, Karen Scarfone / NIST; 2018-10-03 최종판; October 2018; 확인 2026-11-05. 확인 범위: 실제 열람: 공식 게시 페이지의 저자·발행 이력·초록. 분산 원장, 변경 탐지/저항성, 정상 동작 조건의 게시 거래 유지라는 범위입니다. 첨부 PDF 전체는 시간 초과로 읽지 못했으므로 합의 알고리즘 세부 근거로 쓰지 않습니다.
- [PostgreSQL 18: Constraints](https://www.postgresql.org/docs/18/ddl-constraints.html) — PostgreSQL Global Development Group; PostgreSQL 18; 확인 2026-11-05. 확인 범위: 실제 열람: CHECK·NOT NULL·UNIQUE·PRIMARY KEY·FOREIGN KEY 절 목록과 예시. SQL 제약은 DB 내 규칙 강제이며 현실 사실의 진실성까지 자동 검증하지 않습니다.
- [PostgreSQL 18: Concurrency Control](https://www.postgresql.org/docs/18/mvcc.html) — PostgreSQL Global Development Group; PostgreSQL 18; 확인 2026-11-05. 확인 범위: 실제 열람: 동시 접근 목적, MVCC·격리·명시적 잠금·교착·직렬화 실패 처리 구성. 잠금/타임스탬프/낙관 검증 일반 분류 중 제품 구현 범위를 넘는 부분은 교재와 구분합니다.
