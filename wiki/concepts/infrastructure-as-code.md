# 코드형 인프라 IaC

## 서브노트

### 한눈에 이해

서버·망을 클릭한 기억에 의존하지 않고, 원하는 구성을 코드로 검토·재현합니다.

### 정의와 핵심 원리

IaC는 인프라 자원을 기계가 읽을 수 있는 정의로 관리하여 버전 관리·검토·자동배포·재현을 가능하게 하는 접근입니다. 선언형은 원하는 상태를, 명령형은 수행 절차를 중심으로 기술합니다.

- 일반 흐름은 정의작성 → 검증·계획 → 차이검토 → 적용 → 관측입니다. Terraform의 plan은 현재 상태와 구성의차이를계산하고 apply는 변경을 수행합니다. 코드 검토에 생성뿐 아니라삭제·대체·의존순서·장애 영향을 포함합니다.
- 상태파일은관리 자원과 실제 자원의 연결 정보를 보유하므로 잠금·접근 통제·암호화·버전 보호가 필요합니다. 비밀값이 코드또는상태에 남을수 있어비밀관리체계와분리해야합니다. 수동변경으로 인한drift는 정기계획·정책 검사로 찾습니다.
- 모듈·템플릿은검증된반복단위를 만들되과도한추상화는검토를 어렵게합니다. 정책 코드·승인·최소 권한 실행 주체·공급망서명·롤백또는복원 절차를 CI/CD에연결합니다. IaC가 모든 작업의 원자성·자동롤백을보장하는것은아닙니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 수동관리 | 콘솔·문서 절차 | 변경누락·재현어려움 |
| 선언형IaC | 원하는상태와 차이계산 | 상태·provider관리 |
| 명령형자동화 | 작업 순서명시 | 중간실패·반복안전성 |

### 적용 예제

**운영 DB의 의도치 않은 대체 방지**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 스토리지설정 변경 계획에 DB replacement표시

1. plan에서삭제·대체 자원과 의존영향을 확인합니다.
2. 백업·복구 가능성과변경허용시간을 검토합니다.
3. 정책 검사로 승인없는 중요자원 삭제를 차단합니다.
4. 테스트 환경 검증뒤검토된정확한계획을 적용하고 상태를 확인합니다.

**결과·해석:** 코드차이가작아도자원 영향은 클수 있음을검토 절차로 통제합니다.

**전제·주의:** provider·API 버전변화와외부수동변경까지 영구고정되는것은아닙니다.

### 답안 골격과 혼동 방지

정의·필요성 → Write-Plan-Apply → 상태·drift → 검토·보안 → 변경예

- 코드가 있으면 복구훈련이불필요하다고하지 않습니다.
- state를 민감정보없는 단순 캐시로 취급하지 않습니다.
