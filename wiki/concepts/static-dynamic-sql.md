# 정적 SQL과 동적 SQL

## 서브노트

### 한눈에 이해

미리 정한 주문조회 양식에 주문번호만 넣는 방식과, 사용자가 선택한 조건·테이블에 따라 조회문 자체를 조립하는 방식의 차이입니다. 값이 달라진다고 모두 동적 SQL인 것은 아닙니다.

### 정의와 핵심 원리

정적 SQL은 프로그램에 문장이 고정되어 있고 동적 SQL은 실행 시 문장 일부 또는 전체를 구성하여 실행하는 방법입니다.

- 정적 SQL은 컴파일 시 객체·권한·자료형 검증과 의존성 관리에 유리합니다. 동적 SQL은 임의 검색 조건·미확정 식별자·DDL 실행처럼 유연성이 필요할 때 사용합니다. 제품별 prepare/parse 시점이 다르므로 정적=실행계획 영구고정이라고 단정하지 않습니다.
- 바인드 변수는 값과 SQL 구조를 분리합니다. 정적/동적 모두 바인드를 사용할 수 있고, 문자열로 값을 이어 붙이는 것은 동적 SQL의 필수 조건이 아닙니다. 바인드는 일반적으로 테이블명·컬럼명 같은 식별자를 대신할 수 없습니다.
- 동적 구조의 허용 범위를 목록으로 제한하고 파라미터 타입·권한을 검증합니다. SQL 텍스트가 과도하게 달라지면 parse·plan cache 관리 비용이 증가합니다. 실행계획·응답시간·오류·감사 로그를 보며 유연성과 예측 가능성의 균형을 정합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 정적 SQL | 문장 구조가 코드에 고정 | 컴파일 검증·의존성 관리 |
| 동적 SQL | 실행 시 구조 생성 | 자유 검색·도구에서 유용 |
| 바인드 | 구조와 입력값 분리 | 정적·동적 양쪽 사용 가능 |

### 적용 예제

**주문 검색 화면**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 고객번호는 필수이고 날짜 조건은 선택입니다.

1. 기본 문장 SELECT ... FROM orders WHERE customer_id=:id를 정합니다.
2. 날짜 조건을 선택하면 AND ordered_at>=:date 조각만 추가하고 실제 날짜 값은 바인드합니다.
3. 사용자 입력을 테이블명으로 곧바로 붙이지 않고 허용된 검색 대상과 컬럼만 선택합니다.

**결과·해석:** 문장 생성의 유연성을 유지하면서 값의 처리와 구조를 분리합니다.

**전제·주의:** 동적 SQL 실행 권한은 원래 사용자가 열람할 수 있는 데이터 범위를 넘기지 않도록 설계합니다.

### 답안 골격과 혼동 방지

정의 → 구조 결정 시점 비교 → 바인드와 식별자 → 선택 조건 예시 → 성능·검증·운영 고려

- 정적 SQL은 바인드를 못 쓴다는 오해를 피합니다.
- 바인드만 쓰면 임의의 식별자까지 안전하다고 가정하지 않습니다.
