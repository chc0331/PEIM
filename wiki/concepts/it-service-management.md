# IT 서비스 관리(ITSM)

## 서브노트

### 정의

ITSM은 고객·사업 요구를 충족하는 IT 서비스를 계획·설계·전환·제공·개선하는 관리 체계다. ISO/IEC 20000-1은 이를 서비스관리시스템(SMS) 요구사항으로 다룬다.

### 핵심 구조·도식

`요구·SLA → 계획/설계 → 전환(변경·릴리스) → 운영(사건·요청) → 성과측정·지속개선 → 요구`

### 답안 키워드·비교·적용

| 키워드 | 답안 포인트 |
| --- | --- |
| SLA | 고객 기대와 측정 가능한 서비스 수준 합의 |
| Incident | 서비스 복구를 우선하는 장애 대응 |
| Problem | 근본원인 제거와 재발 방지 |
| Change | 위험을 통제하며 변경 승인·배포 |
| CSI | 지표 기반의 지속적 서비스 개선 |

ITSM은 운영만이 아니라 서비스 생명주기를 다룬다. DevOps와는 충돌 개념이 아니며, 자동화·피드백을 통해 서비스 관리 목표를 강화할 수 있다.

### 한계·리스크

티켓 처리량만 측정하면 고객 가치가 사라진다. 경직된 변경 절차는 배포를 지연시키므로 위험도에 따른 변경 유형과 자동화된 통제를 둔다.

### 답안 골격

- **1교시:** 정의 → 서비스 생명주기 → 핵심 프로세스 비교 → SLA·KPI → 개선 효과.
- **논술형:** 서비스 현황 → SLA·카탈로그 → 전환·운영 통제 → 측정·개선 → DevOps 연계.

### 회상 확인

1. Incident와 Problem의 목적과 산출물을 비교하라.
2. SLA에 포함할 측정 항목 세 가지를 제시하라.
3. 신속한 배포와 변경 통제를 함께 달성하는 방법은 무엇인가?
