# SDN·OpenFlow·IBN

## 서브노트

### 한눈에 이해

장비마다 명령을 입력하는 데서 나아가 중앙의 정책과 상태를 바탕으로 네트워크 동작을 제어합니다.

### 정의와 핵심 원리

SDN은 네트워크 제어 기능과 패킷 전달 기능의 분리·추상화·프로그래밍 가능성을 강조하는 접근입니다. OpenFlow는 컨트롤러와 스위치가 흐름 규칙을 교환하는 인터페이스 계열이고 IBN은 의도를 정책으로 변환하고 충족 여부를 지속 검증합니다.

- 응용 계층은 서비스 요구를 표현하고 제어계층은 토폴로지·경로·정책을 계산하며 데이터평면은규칙에 따라 전달합니다.논리적중앙화와물리적단일장애점은 같은 뜻이아니며컨트롤러복제·분산일관성·상실시정책을 설계합니다.
- OpenFlow의 흐름 표는 일치조건·우선순위·동작·카운터등을 갖습니다.기존 규칙이 없는 패킷을 컨트롤러로알려규칙을 설치하거나사전설치할 수 있습니다.버전별pipeline·group등의 세부기능은 명세확인이 필요합니다.
- IBN은 의도수집 → 변환·검증 → 활성화 → 텔레메트리기반보장으로설명합니다.예를들어고객정보 서버에 승인 업무만 접속가능하다는의도를분류·접근 정책으로 구현하고 실제 흐름과 대조합니다.AI사용이필수정의 는아니며잘못된의도·충돌·관측누락을고려합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 전통관리 | 장비별명령·구성 | 수동오류·변경추적 |
| SDN | 제어/전달 분리·API | 제어면가용성·보안 |
| IBN | 의도와결과의 폐루프 | 의도모호성·검증 모델 |

### 적용 예제

**업무망 격리 의도**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 인사서비스는 인사단말에 서 만허용;백업은 별도 경로

1. 의도를출발지·목적지·서비스·예외로 명세합니다.
2. 컨트롤러가토폴로지와정책 충돌을 검증합니다.
3. 허용·차단 규칙을 설치하고 카운터·플로우로그를 수집합니다.
4. 실제 접속시험에 서 위반이있으면 변경 원인과 정책을 재평가합니다.

**결과·해석:** 원하는상태와 관측한상태의 차이를운영루프로관리합니다.

**전제·주의:** RFC7149는SDN관점문서이며 OpenFlow명세및IBN 규격 전문은 미열람입니다.

### 답안 골격과 혼동 방지

문제와 정의 → 3계층도 식 → OpenFlow 흐름 표 → IBN폐루프 → 보안·가용성

- SDN이 OpenFlow하나와동의어라고쓰지않습니다.
- 중앙화가반드시 하나의서버를 뜻하지 않습니다.
