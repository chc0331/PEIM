# SDN·OpenFlow·IBN

## 서브노트

### 한눈에 이해

장비마다 명령을 입력하는 데서 나아가 중앙의 정책과 상태를 바탕으로 네트워크 동작을 제어합니다.

### 정의와 핵심 원리

SDN은 네트워크 제어 기능과 패킷 전달 기능의 분리·추상화·프로그래밍 가능성을 강조하는 접근입니다. OpenFlow는 컨트롤러와 스위치가 흐름 규칙을 교환하는 인터페이스 계열이고 IBN은 의도를 정책으로 변환하고 충족 여부를 지속 검증합니다.

- 응용 계층은 서비스 요구를 표현하고, 제어 계층은 토폴로지·경로·정책을 계산합니다. 데이터 평면은 정해진 규칙으로 패킷을 전달합니다. 논리적으로 중앙에서 제어해도 여러 컨트롤러를 운용할 수 있습니다. 복제·일관성·제어 연결이 끊겼을 때의 동작을 설계합니다.
- OpenFlow 흐름 표에는 일치 조건·우선순위·동작·카운터가 있습니다. 일치하는 규칙이 없을 때 스위치가 패킷을 컨트롤러로 보내게 하거나, 필요한 규칙을 미리 설치할 수 있습니다. 파이프라인과 그룹 등 세부 기능은 해당 버전 명세를 확인합니다.
- IBN은 의도를 받아 정책으로 바꾸고 검증한 뒤 적용합니다. 적용 후에도 관측값을 의도와 대조합니다. 예를 들어 고객 정보 서버에 승인된 업무만 연결하도록 접근 정책을 정하고 실제 흐름을 확인합니다. 의도 자체의 오류와 충돌, 관측 누락도 점검합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 전통관리 | 장비별 명령·구성 | 수동 작업 오류·변경 추적 |
| SDN | 제어/전달 분리·API | 제어면 가용성·보안 |
| IBN | 의도와 결과의 폐루프 | 의도의 모호성·검증 모델 |

### 적용 예제

**업무망 격리 의도**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 인사 서비스는 지정된 인사 단말에서만 접근하고, 백업은 별도 경로로 보냅니다.

1. 의도를 출발지·목적지·서비스·예외 규칙으로 구체화합니다.
2. 컨트롤러가 토폴로지와 정책 충돌을 검증합니다.
3. 허용·차단 규칙을 설치하고 카운터와 흐름 로그를 수집합니다.
4. 실제 접속 시험에서 위반이 있으면 변경 원인과 정책을 재평가합니다.

**결과·해석:** 원하는 상태와 실제 상태를 계속 대조하고 차이가 나면 정책이나 구성을 확인합니다.

**전제·주의:** RFC 7149는 SDN의 관점 문서입니다. OpenFlow 명세와 IBN 규격 전문은 확인이 남아 있습니다.

### 답안 골격과 혼동 방지

문제와 정의 → 세 계층과 역할 → OpenFlow 흐름 표 → IBN 검증 흐름 → 보안·가용성

- SDN이 OpenFlow 하나와 동의어라고 쓰지 않습니다.
- 중앙화가 반드시 하나의 서버를 뜻하지 않습니다.

3. 컨트롤러 장애 시 정책은 무엇입니까?

### 적용 기준과 근거

명시한 출처 판본의 원리를 설명하며 제품별 구현 차이는 별도 확인합니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.
