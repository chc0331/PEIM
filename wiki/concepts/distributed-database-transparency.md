# 분산 DB의 투명성

## 서브노트

### 한눈에 이해

사용자는 주문이라는 하나의 표를 조회하지만 실제 자료는 여러 지역에 나뉘거나 복제되어 있을 수 있습니다. 그 복잡함을 애플리케이션이 매번 직접 다루지 않게 하는 성질이 투명성입니다.

### 정의와 핵심 원리

분산 저장·처리의 위치·분할·복제·동시성·장애 등의 세부를 사용자가 알지 않아도 정해진 논리 동작을 제공하는 성질입니다.

- 위치 투명성은 어느 사이트에 있는지, 분할 투명성은 어떤 조각으로 나뉘었는지, 복제 투명성은 몇 사본에서 읽고 쓰는지를 숨깁니다. 전역 이름과 메타데이터·라우팅·분산 질의 처리가 이를 지원합니다.
- 동시성 투명성은 여러 트랜잭션이 겹쳐도 정해진 격리 규칙을 지키는 성질입니다. 장애 투명성은 일부 노드가 실패해도 복구나 재시도로 정해진 성공·실패 규칙을 지키는 성질입니다. 통신이 끊기면 같은 결과를 보장할지, 요청을 계속 받을지 판단해야 합니다.
- 교재는 data transparency를 위치·분할·복제의 세 가지로 정리하고 동시성·장애는 별도 분산 트랜잭션/가용성에서 다룹니다. 기출의 5가지를 답할 때는 이 분류 차이를 밝혀 3개 데이터 투명성+동시성+장애의 교육용 묶음으로 설명합니다. 구현의 보장 범위를 제품 문서에서 다시 확인합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 위치·분할 | 논리 자료를 실제 사이트/조각으로 해석 | 라우팅·분산 계획 |
| 복제 | 여러 사본을 한 자료처럼 사용 | 복제 일관성·실패 처리 |
| 동시성·장애 | 격리·완료 의미 유지 | 분산 트랜잭션·복구 |

### 적용 예제

**서울·부산 주문 조회**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 서울 주문과 부산 주문은 다른 노드에 저장되며 각 노드에 복제본이 있습니다.

1. 사용자는 SELECT SUM(amount) FROM orders를 요청합니다.
2. 분산 계획기가 해당 조각에서 부분합을 구해 합산하고 읽을 복제본을 선택합니다.
3. 한 노드가 실패하면 허용된 복제본으로 재시도하거나 전체 결과를 실패 처리하며, 일부 결과를 전체 합계라고 반환하지 않습니다.

**결과·해석:** 논리 인터페이스는 단순하지만 정확한 결과의 완료 조건은 명확해야 합니다.

**전제·주의:** 사용자가 데이터 위치를 몰라도 조회할 수 있지만, 운영자가 장애를 찾으려면 실제 배치와 복제 상태를 확인할 수 있어야 합니다.

### 답안 골격과 혼동 방지

정의·통합 논리뷰 → 위치/분할/복제 → 동시성/장애 → 집계 흐름 예시 → 보장 수준·지연 한계

- 데이터가 물리적으로 한곳에 있어야 한다는 뜻이 아닙니다.
- 5종 명칭이 모든 표준에서 동일하다고 단정하지 않습니다.

### 내용을 가리고 회상

1. 위치와 분할 투명성을 각각 한 문장으로 설명할 수 있습니까?
2. 한 shard의 실패가 합계 결과에 주는 영향을 어떻게 처리합니까?
3. 투명성과 관측 가능성은 왜 함께 필요합니까?

### 적용 기준과 근거

공개 교재의 3가지 data transparency는 확인했습니다. 기출의 정확한 5종 공식 분류 원문은 지정되어 있지 않아 분류 기준을 공개합니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [Database System Concepts 5th ed., Chapter 22: Distributed Databases](https://www.db-book.com/Previous-editions/db5/slide-dir/ch22.pdf) — A. Silberschatz, H. F. Korth, S. Sudarshan; 2005-08-22; 확인 2026-11-05. 확인 범위: 실제 열람: 분산 사이트, 복제·분할, 위치·분할·복제 투명성과 분산 트랜잭션 구성. 시험에서 말하는 5종 전체 목록은 출처별 분류 차이를 명시합니다.
- [PostgreSQL 16: Transaction Isolation](https://www.postgresql.org/docs/16/transaction-iso.html) — PostgreSQL Global Development Group; PostgreSQL 16; 확인 2026-11-05. 확인 범위: 실제 열람: SQL 네 단계와 이상현상 표, PostgreSQL RU=RC, RR에서 팬텀 방지·직렬화 이상 가능, SSI 재시도. 표준 최소 보장과 구현 차이를 명시합니다.
