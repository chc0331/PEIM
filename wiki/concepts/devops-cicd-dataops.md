# DevOps·CI/CD·DataOps와 보안 자동화

## 서브노트

### 한눈에 이해

DevOps에서는 개발팀과 운영팀이 변경 사항을 자동으로 검증하고 함께 배포 결과를 확인합니다.

### 정의와 핵심 원리

DevOps는 개발·운영이 서비스 결과를 공동 책임지며 자동화·관측·피드백으로 전달을 개선하는 접근입니다. CI는 빈번한 변경 통합·검증, 지속적 전달은 배포 가능 상태 유지, 지속적 배포는 검증된 변경의 운영 자동 반영입니다.

- 파이프라인은 변경/검토→빌드·의존성 고정→단위·정적 검사→패키징·아티팩트 식별→통합·성능·보안 검증→배포 승인/자동전환→관측·롤백으로 구성할 수 있습니다. 동일 빌드 산출물을 승격하고 환경설정과 비밀을 분리해야 재현 가능합니다.
- 장점은 빠른 피드백·작은 변경·반복 작업 감소·추적성입니다. 단점/비용은 초기 자동화 투자, 도구 복잡도, 조직 갈등, 권한·비밀 노출, 잘못된 설정이 자동으로 퍼질 위험입니다. 공통 기준을 정하고 좁은 범위부터 적용해 위험을 줄입니다.
- DevSecOps는 요구·위협모델·SAST·SCA·비밀 탐지·컨테이너/IaC 검사·DAST·서명/출처 검증·런타임 관측을 파이프라인에 통합합니다. 위험 임계값·예외 승인·담당자·증거를 정해 무조건 검사만 늘려 전달을 막지 않도록 합니다.
- DataOps는 데이터 파이프라인의 품질·흐름·협업을 관리합니다. 수집→저장/변환→시험·품질계약→제공→관측 구조에서 데이터·스키마·변환코드·계보를 버전 관리하고 지연·완전성·정확성·변경을 감시합니다. 앱 배포뿐 아니라 바뀌는 데이터의 검증과 재처리가 중요합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| CI | 빈번한 통합과 자동 피드백 | 깨진 기본 브랜치 즉시 복구 |
| Delivery/Deployment | 배포 가능 / 운영 자동 반영 | 수동 승인 여부와 제품 특성 구분 |
| DataOps | 데이터 품질·계보·재처리 | DevOps 원리를 데이터 수명주기에 적용 |

### 적용 예제

**강사 창작 적용 예시: 정산 API와 데이터 집계 배포**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 코드 수정과 원천 스키마 변경이 함께 들어옵니다.

1. 코드는 단위·통합·보안 검사를 거쳐 불변 아티팩트로 만듭니다.
2. 집계는 스키마 계약·행수·합계 대사와 데이터 계보를 검증합니다.
3. 운영에 반영한 뒤 오류율·지연·집계 품질을 관찰합니다. 문제가 생기면 코드와 데이터를 각 복구 절차에 따라 되돌립니다.

**결과·해석:** 코드와 데이터 변화의 서로 다른 실패 원인을 함께 통제합니다.

**전제·주의:** 보안 자동화 상세 분류·공급망 검증은 보안 담당 원고를 결합해야 완전한 답안이 됩니다.

### 답안 골격과 혼동 방지

DevOps 개념·장단점 → CI/Delivery/Deployment 파이프라인 → DataOps 비교·아키텍처와 DevSecOps 활동

- 지속적 전달과 지속적 배포를 같은 뜻으로 쓰지 않습니다.
- 검사 통과가 위험이 없다는 인증은 아닙니다.

### 내용을 가리고 회상

1. 배포 가능한 상태와 실제 자동배포는 어떻게 다릅니까?
2. 불변 아티팩트를 승격하는 이유는 무엇입니까?
3. DataOps에서 코드 외에 버전 관리할 대상은 무엇입니까?

### 적용 기준과 근거

DORA의 CI/CD 구분을 확인했습니다. DataOps 아키텍처·보안 자동화 도구의 상세 검증은 관련 담당 자료와 결합해야 합니다.
