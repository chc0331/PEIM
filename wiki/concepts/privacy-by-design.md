# Privacy by Design의 7원칙과 8전략

## 서브노트

### 한눈에 이해

완성된 제품에 동의 화면을 만들기 전에 수집 목적, 필요한 데이터, 기본 설정, 이용자 권리를 정합니다.

### 정의와 핵심 원리

PbD는 IT·업무·인프라의 설계 단계부터 프라이버시를 내재화하는 방법론입니다. 7가지 원칙은 설계 방향을 제시합니다. 8가지 전략은 그 방향을 데이터 처리와 운영 절차에 적용할 때 참고할 수 있습니다.

- 7가지 원칙은 사후 대응보다 사전 예방, 기본 설정으로서의 프라이버시, 설계에 내재화, 기능과 보호의 상생, 수명 주기 전체 보호, 가시성과 투명성, 사용자 프라이버시 존중입니다. 보호를 사용자가 힘들게 설정해야 얻는 옵션으로만 두지 않습니다.
- Hoepman의 8가지 전략은 데이터 중심 minimise/hide/separate/abstract와 절차 중심 inform/control/enforce/demonstrate로 정리합니다. 일부 문헌은 aggregate를 쓰며, 여기서 확인한 저자 판본은 abstract를 씁니다. 최소 수집·암호화·분리·거친 추상화·설명·선택·집행·증빙으로 설계에 연결합니다.
- 개인정보 보호법 제3조의 목적 명확·최소 처리·목적 범위·정확성·안전 관리·공개·권리·사생활 최소화 등과 방향을 비교할 수 있으나 국내 법 조문의 모든 항과 일대일 대응 표라고 단정하지 않습니다. 기술·정책·UI·운영이 같이 동작해야 하며 영향 평가와 잔여 위험을 문서화합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 7원칙 | 어떤 가치를 기본으로 둘 것인가 | 기본 보호·내재화 |
| 8전략 | 설계에 어떤 조치를 적용할 것인가 | 데이터·절차 행동 |
| 법적 의무 | 무엇을 준수해야 하는가 | 대상·판본·근거 확인 |

### 적용 예제

**위치 기반 알림 앱**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 근처 매장을 알려 주려면 이용자의 위치가 필요합니다.

1. 필요 시점에만 위치를 읽고 정확한 좌표 대신 영역 정보 사용을 검토합니다.
2. 기본 추적은 최소화하고 목적·보관 기간을 설명합니다.
3. 사용자가 일시 정지·삭제·동의 철회를 쉽게 하도록 설계합니다.
4. 로그·SDK·백업에도 같은 정책이 적용됐는지 기록을 확인합니다.

**결과·해석:** 원칙을 데이터 필드·기본 설정·권리 행사 절차·운영 증거로 구현합니다.

**전제·주의:** 국내 법 제3조 최신 원문 전 항은 미열람이며 본 비교는 방향성 설명입니다.

### 답안 골격과 혼동 방지

배경·정의 → 7원칙 → 8전략 → 법 원칙과 비교 → 설계 예제

- 암호화 하나로 PbD가 완료됐다고 하지 않습니다.
- 동의만 받으면 최소 수집이 불필요하다고 쓰지 않습니다.

### 내용을 가리고 회상

1. 기본 설정 프라이버시는 어떤 화면 설계를 뜻합니까?
2. separate와 abstract는 어떻게 다릅니까?
3. demonstrate는 어떤 증거를 요구합니까?

### 적용 기준과 근거

명시한 출처 판본의 원리를 설명하며 제품별 구현 차이는 별도 확인합니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [Privacy by Design: Seven Foundational Principles](https://www.ipc.on.ca/sites/default/files/legacy/2018/01/pbd.pdf) — Information and Privacy Commissioner of Ontario; 2018-01; 확인 2026-11-05. 확인 범위: 공공기관 2쪽 원문 열람. 7원칙 직접 확인.
- [Privacy Design Strategies, The Little Blue Book](https://www.cs.ru.nl/~jhh/publications/pds-booklet.pdf) — Jaap-Henk Hoepman; 2022-04-19; 확인 2026-11-05. 확인 범위: 저자 원문 8전략 열람. abstract를 기존 문헌의 aggregate와 무조건 동일 용어로 바꾸지 않음.
