# 정규화와 이상현상: 함수종속에서 제4정규형까지

## 서브노트

### 한눈에 이해

학생 주소를 수강 과목마다 적으면 이사할 때 여러 행을 고쳐야 합니다. 학생 정보와 수강 기록을 나눠 저장하면 주소는 한 곳에서만 고치면 됩니다. 정규화는 이렇게 데이터가 서로 어떤 값에 종속되는지 보고 테이블을 나누는 작업입니다.

### 정의와 핵심 원리

속성 사이의 함수종속·다치종속을 기준으로 릴레이션을 분해하여 삽입·갱신·삭제 이상을 줄이고 무손실 조인을 확보하는 논리 설계 과정입니다.

- 함수종속(FD) X→Y는 X가 같은 행에서 Y도 같아야 한다는 규칙입니다. 후보키 하나라도 이루는 속성은 주요 속성입니다. 1NF는 값을 원자값으로 다룹니다. 2NF에서는 비주요 속성이 모든 후보키 각각에 완전히 종속되어야 합니다. 3NF는 비자명한 FD X→A마다 X가 슈퍼키이거나 A가 주요 속성이어야 합니다.
- BCNF에서는 모든 비자명한 함수종속의 결정자가 슈퍼키여야 합니다. 3NF의 주요 속성 예외는 없습니다. 두 릴레이션으로 분해할 때, 공통 속성이 적어도 한쪽의 모든 속성을 결정하면 무손실입니다. BCNF로 무손실 분해하더라도 종속성이 모두 보존되지는 않을 수 있습니다.
- 4NF는 모든 비자명 다치종속 X↠Y의 X가 슈퍼키여야 합니다. 한 학생의 취미와 사용언어가 서로 독립인데 같은 표에 넣으면 취미 수×언어 수의 조합이 생깁니다. 학생취미와 학생언어로 분해하면 독립 사실의 중복을 제거합니다.

### 구조·비교·판단

| 구분 | 제거 대상/조건 | 주의 |
| --- | --- | --- |
| 2NF | 복합 후보키 일부에만 의존하는 비주요 속성 | 단일 속성 후보키만 있으면 부분종속 없음 |
| 3NF·BCNF | 3NF는 주요 속성 예외 허용; BCNF는 결정자 슈퍼키 | BCNF의 종속성 보존 확인 |
| 4NF | 독립적인 다치 사실의 조합 중복 | 다치종속은 단순 다중값과 다름 |

### 적용 예제

**129회 수강테이블 분해**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** R(학번,학과,지도교수,수강코드), PK=(학번,수강코드). 업무상 학생당 학과·지도교수 하나라고 가정합니다.

1. 학번→학과, 지도교수라는 함수종속을 적습니다. 수강코드가 없으면 학생 정보만 넣기 어렵습니다. 학생 정보가 바뀌면 여러 행을 고쳐야 하고, 마지막 수강 행을 삭제하면 학생 정보도 사라집니다.
2. 학생(학번 PK,학과,지도교수)과 수강(학번 FK,수강코드,PK=(학번,수강코드))으로 분해합니다.
3. 두 테이블의 공통 속성인 학번이 학생 테이블의 모든 속성을 결정하므로 조인하면 원래 행을 복원할 수 있습니다. 수강 테이블의 학번은 학생 테이블을 참조하는 외래키입니다. 원문이 학과→지도교수를 보장하지 않으므로 여기서 더 나누지 않습니다.

**결과·해석:** 학생 정보는 한 번 저장하고 수강은 학생-과목 관계만 저장합니다.

**전제·주의:** 기출에서 같은 컴퓨터과 학생의 지도교수가 K1/M1로 달라 학과→지도교수를 가정하면 원자료와 충돌합니다.

### 답안 골격과 혼동 방지

정의·이상 3종 → 업무 FD·후보키 명시 → 정규형 조건 비교 → 분해 전후 스키마·PK/FK → 무손실·종속성 보존 검토

- 기본키 하나만 보고 다른 후보키를 무시하지 않습니다.
- 정규화가 조회 성능을 항상 높인다고 단정하지 않습니다.

## 정규화와 이상현상: 함수종속에서 제4정규형까지

### 서브노트

#### 한눈에 이해

학생 주소를 수강 과목마다 적으면 이사할 때 여러 행을 고쳐야 합니다. 정규화는 같은 사실을 여러 곳에 반복 기록하지 않도록, 사실의 주인을 찾아 테이블을 나누는 작업입니다. 표를 작게 만드는 것 자체가 목적은 아닙니다.

#### 정의와 핵심 원리

속성 사이의 함수종속·다치종속을 기준으로 릴레이션을 분해하여 삽입·갱신·삭제 이상을 줄이고 무손실 조인을 확보하는 논리 설계 과정입니다.

- FD X→Y는 X가 같은 두 행에서 Y도 같아야 한다는 업무 규칙입니다. 현재 표의 우연한 값으로 FD를 확정하지 않습니다. 1NF는 원자값, 2NF는 비주요 속성의 후보키 전체에 대한 완전 함수종속, 3NF는 모든 비자명 FD X→A에서 X가 슈퍼키이거나 A가 주요 속성인 조건입니다.
- BCNF는 모든 비자명 FD의 결정자가 슈퍼키여야 합니다. 3NF보다 엄격하며, BCNF 무손실 분해가 종속성 보존까지 항상 보장하지는 않습니다. 2개 릴레이션 분해에서는 공통 속성이 한쪽 전체를 결정하는지 확인합니다.
- 4NF는 모든 비자명 다치종속 X↠Y의 X가 슈퍼키여야 합니다. 한 학생의 취미와 사용언어가 서로 독립인데 같은 표에 넣으면 취미 수×언어 수의 조합이 생깁니다. 학생취미와 학생언어로 분해하면 독립 사실의 중복을 제거합니다.

#### 구조·비교·판단

| 구분 | 제거 대상/조건 | 주의 |
| --- | --- | --- |
| 2NF | 복합 후보키 일부에만 의존하는 비주요 속성 | 단일 속성 후보키만 있으면 부분종속 없음 |
| 3NF·BCNF | 3NF는 주요 속성 예외 허용; BCNF는 결정자 슈퍼키 | BCNF의 종속성 보존 확인 |
| 4NF | 독립적인 다치 사실의 조합 중복 | 다치종속은 단순 다중값과 다름 |

#### 적용 예제

**129회 수강테이블 분해**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** R(학번,학과,지도교수,수강코드), PK=(학번,수강코드). 업무상 학생당 학과·지도교수 하나라고 가정합니다.

1. FD 학번→학과,지도교수를 선언합니다. 과목을 아직 신청하지 않은 학생은 삽입하기 어렵고, 학생 정보 갱신이 여러 행에 걸리며, 마지막 수강행을 지우면 학생 정보도 사라집니다.
2. 학생(학번 PK,학과,지도교수)과 수강(학번 FK,수강코드,PK=(학번,수강코드))으로 분해합니다.
3. 공통 학번이 학생 전체 속성을 결정하므로 무손실입니다. 수강의 학번에 외래키를 둡니다. 학과→지도교수는 원문에서 보장되지 않으므로 추가 분해하지 않습니다.

**결과·해석:** 학생 정보는 한 번 저장하고 수강은 학생-과목 관계만 저장합니다.

- 기본키 하나만 보고 다른 후보키를 무시하지 않습니다.
- 정규화가 조회 성능을 항상 높인다고 단정하지 않습니다.
