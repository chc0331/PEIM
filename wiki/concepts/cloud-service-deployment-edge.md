# 클라우드 서비스·배포 모델과 엣지

## 서브노트

### 한눈에 이해

무엇을 서비스로 빌리는지와 누구와 자원을 공유하는지, 연산을 어디서 하는지는 서로 다른 선택입니다.

### 정의와 핵심 원리

클라우드 컴퓨팅은 공유된 구성가능 자원에 필요시 접근하고 신속히 할당·반환하는 서비스 모델입니다. IaaS/PaaS/SaaS는 제공 계층, 퍼블릭/프라이빗/커뮤니티/하이브리드는 배포 모델이며 엣지는 데이터 발생원 가까이에 연산을 배치하는 접근입니다.

- NIST의 다섯 특성은 주문형 셀프서비스, 광대역 네트워크 접근, 자원 풀링, 신속한 탄력성, 측정 가능한 서비스입니다. 단순한 외부 서버 호스팅이나 가상화만으로 모든 특성을 충족하는 것은 아닙니다.
- IaaS는 컴퓨팅·스토리지·네트워크를 제공하고 이용자가 OS·응용을 관리합니다. PaaS는 응용 실행 플랫폼을 제공하고 SaaS는 제공자의 응용을 사용합니다. 어느 모델에서도 이용자의 데이터·권한·설정 책임이 전부 없어지는 것은 아닙니다.
- 엣지는 전송 지연·대역 비용·연결 단절·데이터 지역성 때문에 유리하지만 작은 자원·분산 운영·물리보안이 과제입니다. 중앙 클라우드는 대규모 자원과 통합 관리에 유리하므로 엣지의 즉시 제어와 클라우드의 학습·장기 분석을 연결할 수 있습니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 서비스 모델 | IaaS/PaaS/SaaS | 관리 책임 경계 |
| 배포 모델 | 공유·소유·접근 범위 | 퍼블릭도전용자원가 능 |
| 엣지배치 | 발생원 인근 처리 | 단절·지연·분산관리 |

### 적용 예제

**공장 영상 검사**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 불량판정50ms이 내;중앙망가끔단절

1. 엣지에서 즉시추론과 안전한 기본제어를 수행합니다.
2. 클라우드에 선별 데이터와 지표를 전송해 재학습·집계를 합니다.
3. 모델 버전·업데이트 서명·롤백과 단절시 정책을 둡니다.
4. 중앙 집중과 엣지 분산의 총운영비·보안 범위를 비교합니다.

**결과·해석:** 서비스 계층과 배치 위치를 조합하여 요구를 충족합니다.

**전제·주의:** 클라우드·엣지의 빠르기를 거리만으로 단정하지 않고 종단간 지연을 측정합니다.

### 답안 골격과 혼동 방지

5특성 → 3서비스 책임 표 → 4배포 모델 → 엣지 비교 → 적용 사례

- 퍼블릭과IaaS를 같은 분류축으로비교하지 않습니다.
- 엣지가클라우드를 완전히대체한다고쓰지않습니다.
