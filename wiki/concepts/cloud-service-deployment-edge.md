# 클라우드 서비스·배포 모델과 엣지

## 서브노트

### 한눈에 이해

무엇을 서비스로 빌리는지와 누구와 자원을 공유하는지, 연산을 어디서 하는지는 서로 다른 선택입니다.

### 정의와 핵심 원리

클라우드 컴퓨팅은 공유 자원이 필요할 때 접근해 빠르게 할당받고 반납할 수 있는 서비스 모델입니다. IaaS·PaaS·SaaS는 어디까지 제공받는지를, 퍼블릭·프라이빗·커뮤니티·하이브리드는 배포 범위를 구분합니다. 엣지 컴퓨팅은 데이터가 생기는 곳 가까이에 연산을 배치합니다.

- NIST의 다섯 특성은 주문형 셀프서비스, 광대역 네트워크 접근, 자원 풀링, 신속한 탄력성, 측정 가능한 서비스입니다. 단순한 외부 서버 호스팅이나 가상화만으로 모든 특성을 충족하는 것은 아닙니다.
- IaaS는 컴퓨팅·스토리지·네트워크를 제공하며 이용자가 운영체제와 응용 프로그램을 관리합니다. PaaS는 응용 프로그램의 실행 환경을 제공하고, SaaS는 제공자의 응용 프로그램을 이용하는 방식입니다. 세 방식 모두 이용자가 맡는 데이터·권한·설정 관리 범위를 확인해야 합니다.
- 엣지에서는 처리 지연과 전송 비용을 줄이고 중앙망이 끊겨도 일부 처리를 계속할 수 있습니다. 데이터가 머무는 위치를 제한하는 데도 도움이 됩니다. 반면 장치의 자원이 적고 여러 곳의 장치와 물리 보안을 관리해야 합니다. 엣지에서 즉시 제어하고 중앙 클라우드에서 학습과 장기 분석을 할 수 있습니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 서비스 모델 | IaaS/PaaS/SaaS | 관리 책임 경계 |
| 배포 모델 | 공유·소유·접근 범위 | 배포 범위와 개별 자원의 전용 여부를 구분 |
| 엣지 배치 | 데이터가 생기는 곳 가까이에서 처리 | 단절·지연·분산 관리 |

### 적용 예제

**공장 영상 검사**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 불량 여부를 50 ms 안에 판정해야 합니다. 중앙망이 가끔 끊깁니다.

1. 엣지 장치에서 즉시 불량을 판정하고 안전을 위한 기본 제어를 수행합니다.
2. 클라우드에 선별 데이터와 지표를 전송해 재학습·집계를 합니다.
3. 모델 버전과 업데이트 서명을 확인하고, 업데이트를 되돌리는 절차와 중앙망이 끊겼을 때의 운영 규칙을 정합니다.
4. 중앙 집중과 엣지 분산의 총운영비·보안 범위를 비교합니다.

**결과·해석:** 서비스 계층과 배치 위치를 조합하여 요구를 충족합니다.

**전제·주의:** 거리가 짧아도 처리 대기와 장치 성능에 따라 느릴 수 있으므로 전체 응답 시간을 측정합니다.

### 답안 골격과 혼동 방지

클라우드의 다섯 특성 → 세 서비스 모델의 책임 범위 → 네 배포 모델 → 엣지와 중앙의 역할 → 적용 사례

- 퍼블릭은 배포 모델, IaaS는 서비스 모델입니다.
- 엣지와 중앙 클라우드는 지연·가용 자원·관리 방식에 맞춰 조합합니다.

### 내용을 가리고 회상

1. PaaS 이용자가 맡는 책임에는 무엇이 있습니까?
2. 서비스 모델과 배포 모델은 각각 어떤 기준으로 구분합니까?
3. 장치를 여러 곳에 배치하면 어떤 보안 관리가 추가로 필요합니까?
