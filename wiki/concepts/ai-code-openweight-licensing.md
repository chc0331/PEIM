# AI 생성 코드·오픈웨이트 라이선스와 컴플라이언스

## 서브노트

### 한눈에 이해

생성된 결과나 내려받은 가중치가 자유이용을 뜻하지 않으므로 각 구성 요소의 출처·허용범위·배포 의무를 확인합니다.

### 정의와 핵심 원리

AI 라이선스 관리는 코드·의존성·모델 가중치·데이터·도구·출력에 적용되는 조건을 식별하고 사용·수정·배포·서비스 제공의 의무를 관리하는 활동입니다. 오픈웨이트는 가중치 공개를 뜻할 뿐, OSI의 오픈소스 AI 정의 충족을 자동으로 의미하지 않습니다.

- MIT는 고지 유지가 핵심이며 Apache2.0은 라이선스·변경 고지·관련 NOTICE등과 특허 조건을 검토합니다. GPL은 배포·결합 관계에 따른 소스 제공 등의 조건을 확인해야 하고 AGPL의 네트워크 조항·모델 커스텀 사용 제한은 개별 원문을 확인합니다. 생성 코드의 유사성이 있으면 출처·권리·적용 조건을 검토하되 유사성 점수만으로 위반을 단정하지 않습니다.
- 점검은 출처·버전·저작권·SPDX식별·허용 용도·배포/수정·상표/특허·고지·소스 제공·재배포·사용 제한·데이터 권리·의존 조건을 포함합니다. 모델 라이선스와 추론 엔진코드 라이선스가 다를 수 있고 버전별 정책 변경을 추적합니다. SSPL/BSL을 무조건 OSI승인 오픈소스라하지 않습니다.
- 통합 절차는 인벤토리/SBOM·모델 목록 → 자동탐지/SCA·ScanCode등 → 정책 분류·법무/권리검토 → 승인·고지/소스 준비 → 릴리스 게이트 → 운영 모니터링·업데이트입니다. OSI1.0은 이용·연구·수정·공유 자유와 수정에 필요한 데이터 정보·코드·파라미터를 다룹니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 코드 라이선스 | 저작권·배포·결합조건 | 생성출력도 검토 |
| 모델 가중치 조건 | 이용·재배포·사용 제한 | 오픈웨이트≠자동오픈소스 |
| 스캔·심사 | 탐지·정책·권리 판단 | 도구는 법적완전판정아님 |

### 적용 예제

**AI가 제안한 함수의 배포**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 코드조각과 오픈웨이트모델을 제품에 포함하는 가정

1. 생성 코드의 유사원본·의존성과모델정확버전을 기록합니다.
2. 해당라이선스의 이용·수정·배포 조건을 각각 검토합니다.
3. 필요고지·소스 제공·사용 제한준수증거를 릴리스에연결합니다.
4. 스캔미검출과권리확보를동일시하지 않고잔여이슈를검토합니다.

**결과·해석:** 생성 시점부터 업데이트까지 추적가능한 정책과 증빙을만듭니다.

**전제·주의:** 개별저작권침해·파생저작물·계약효력의법적 판단은아닙니다.AGPl·SSPL·BSL·특정 모델 원문 전체는미열람입니다.

### 답안 골격과 혼동 방지

리스크·구성 요소 → 허용·카피레프트·커스텀조건 → 점검 표 → 통합거버넌스 → 검증 도구 한계

- 공개 가중치면상업이용·재배포가 항상 자유롭다고쓰지않습니다.
- AI가 만든코드는 저작권이없다고단정하지 않습니다.
