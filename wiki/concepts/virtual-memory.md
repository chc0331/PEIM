# 가상 메모리·단편화·스레싱

## 서브노트

### 한눈에 이해

프로그램이 보는 주소와 실제 RAM 위치를 분리하고 필요한 조각만 올리지만, 조각 교체에 매달리면 오히려 느려집니다.

### 정의와 핵심 원리

가상 메모리는 프로세스별 가상 주소를 물리 프레임에 매핑하여 격리·보호·공유·비연속 배치를 제공하는 메모리 추상화입니다. 페이지 부재 시 운영체제가 저장 장치 등에서 필요한 내용을 준비합니다.

- 페이징은 고정 크기의 가상 페이지를 물리 프레임에 매핑합니다. 페이지 마지막에 쓰고 남은 공간이 내부 단편화입니다. 프레임을 연속해서 배치할 필요가 없어 외부 단편화 문제를 피할 수 있습니다. 페이지 테이블은 매핑을 저장하고, 주소 변환 캐시(TLB)는 자주 쓰는 매핑을 저장해 테이블 조회 비용을 줄입니다.
- 세그멘테이션은 코드·데이터 등 논리 단위마다 가변 길이 영역과 시작 주소·범위(base/limit)를 사용합니다. 영역별로 보호하고 공유하기 쉽지만 물리 공간에 외부 단편화가 생길 수 있습니다. 두 기법을 결합할 때는 논리 세그먼트를 다시 페이지로 나눕니다.
- 스레싱은 작업이 자주 접근하는 페이지 집합을 가용 프레임에 담기 어려워 페이지 부재와 교체가 반복되고, 실제 계산이 줄어드는 상태입니다. 동시에 실행할 작업 수를 줄이거나 작업 집합·부재 빈도를 기준으로 프레임을 조절합니다. 메모리 증설과 접근 지역성 개선도 검토합니다. 큰 페이지는 TLB 효율을 높일 수 있지만 내부 낭비와 연속 할당 부담이 커질 수 있습니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 페이징 | 고정 단위와 페이지 테이블 | 내부 단편화, 페이지 테이블의 메모리 사용량 |
| 세그멘테이션 | 가변 길이 논리 단위와 시작 주소·범위 | 외부 단편화와 배치 문제 |
| 스레싱 제어 | 자주 쓰는 페이지를 RAM에 수용 | CPU 사용률이 낮다고 작업을 더 늘리면 악화 가능 |

### 적용 예제

**주소변환과 내부단편화**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 페이지 4 KiB, 가상 주소 0x12345, 해당 VPN 0x12 → PFN 0xA0

1. 하위 12비트가 오프셋입니다. 이 예에서 오프셋은 0x345입니다.
2. 물리 주소는 0xA0000 + 0x345 = 0xA0345입니다.
3. 크기 10 KiB인 영역에 3페이지를 배정하면 12 KiB 중 2 KiB가 남습니다.
4. 많은 페이지를 반복해서 참조할 때는 TLB에 매핑이 없는 경우와 물리 메모리에 페이지가 없는 경우를 따로 측정합니다.

**결과·해석:** 주소를 바꾸는 과정과 페이지에서 쓰고 남은 공간을 각각 계산합니다.

**전제·주의:** 페이지 부재는 항상 디스크 I/O를 뜻하지 않으며 zero-fill·COW도 있습니다.

### 답안 골격과 혼동 방지

주소 변환 도식 → 페이지와 세그먼트 비교 → 단편화의 종류 → 스레싱의 원인과 제어 → 계산 예

- 가상 메모리의 역할에는 주소 매핑뿐 아니라 격리·보호·공유도 포함됩니다.
- 페이지 부재는 필요한 페이지를 준비하는 정상 처리 과정에서 발생할 수 있습니다.

### 내용을 가리고 회상

1. 페이징에서 내부 단편화가 생기는 이유는 무엇입니까?
2. 스레싱이 발생하면 CPU 사용률이 낮아질 수 있는 이유는 무엇입니까?
3. 큰 페이지를 사용하면 어떤 이점과 비용이 생깁니까?
