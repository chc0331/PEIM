# 가상 메모리·단편화·스레싱

## 서브노트

### 한눈에 이해

프로그램이 보는 주소와 실제 RAM 위치를 분리하고 필요한 조각만 올리지만, 조각 교체에 매달리면 오히려 느려집니다.

### 정의와 핵심 원리

가상 메모리는 프로세스별 가상 주소를 물리 프레임에 매핑하여 격리·보호·공유·비연속 배치를 제공하는 메모리 추상화입니다. 페이지 부재 시 운영체제가 저장 장치 등에서 필요한 내용을 준비합니다.

- 페이징은 고정 크기 페이지와 프레임을 매핑합니다. 페이지 내부의 사용하지 않는 끝 공간은 내부단편화이며 비연속 프레임 배치로 일반적인 외부단편화를 피합니다. 페이지 테이블·TLB가 주소변환 비용을 줄입니다.
- 세그멘테이션은 코드·데이터 등 논리 단위의 가변길이 영역과 base/limit를 사용합니다. 논리 보호·공유가 쉽지만 물리 공간의 외부단편화가 생길 수 있습니다. 결합형은 논리 세그먼트를 다시 페이지로 나눕니다.
- 스레싱은 활동 작업집합이 가용 프레임보다 커져 잦은 페이지 부재와 교체가 유효 CPU 실행을 압도하는 상태입니다. 다중프로그래밍 정도 축소, 작업집합·부재 빈도 기반 프레임 조절, 메모리 증설과 접근 지역성 개선을 검토합니다. 큰페이지는 TLB 효율 대신 내부낭비·연속할당 부담을 늘릴 수 있습니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 페이징 | 고정단위;페이지 표 | 내부단편화·표 메모리 |
| 세그멘테이션 | 논리단위;base/limit | 외부단편화·배치문제 |
| 스레싱제어 | 활성작업집합을 RAM에 맞춤 | CPU 낮다고 작업을 더 늘리면 악화 |

### 적용 예제

**주소변환과 내부단편화**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 페이지4KiB, 가상 주소0x12345, 해당VPN0x12 → PFN0xA0

1. 하위 12비트오프셋은0x345입니다.
2. 물리 주소는 0xA0000+0x345=0xA0345입니다.
3. 크기10KiB영역에 3페이지를 배정하면 12KiB 중2KiB가 남습니다.
4. 서로 다른 많은페이지를 순환참조하면 TLB미스와부재를분리 측정합니다.

**결과·해석:** 주소변환과공간낭비를각각 계산하여 단편화와교체문제를 구분합니다.

**전제·주의:** 페이지 부재는항상 디스크I/O를 뜻하지 않으며zero-fill·COW도 있습니다.

### 답안 골격과 혼동 방지

주소변환도식 → 페이지·세그먼트비교 → 단편화종류 → 스레싱원인·제어 → 계산예

- 가상 메모리를 단순 히디스크를 RAM처럼쓰는기술로 한정하지 않습니다.
- 모든 부재를오류라하지 않습니다.
