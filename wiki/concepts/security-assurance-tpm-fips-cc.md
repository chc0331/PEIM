# TPM·FIPS140-2·CC·신속확인 제도

## 서브노트

### 한눈에 이해

알고리즘이 강한지, 키를 다루는 모듈이 안전한 지, 제품의 주장한 보안 기능을 평가했는지는 서로 다른 보증 범위입니다.

### 정의와 핵심 원리

TPM은 키 보호·측정 값보관·상태증명등을 지원하는신뢰 기반모듈입니다. FIPS140은 암호모듈보안 요구를, CC는 정의된평가 대상과 보안 요구·보증을 다루며신속확인은 기존 평가 기준이 없는 신기술보안제품의 공공도입을돕는국내 제도입니다.

- TPM은 보호된키와 PCR측정 값을 연결한seal/unseal·attestation등에활용됩니다. 측정된부팅은구성변경의 증거를 제공하지만실행중모든 악성행위를 항상 탐지하는완전무결장치가 아닙니다. 소유권·등록·복구·펌웨어·물리 공격을 고려합니다.
- FIPS140-2는 레벨1~4의점증적보증수준을제공합니다. 모듈명세·인터페이스·역할/인증·물리보안·운영 환경·키 관리·자가시험·설계 보증등을 다룹니다. 대체로 1기본 요구, 2tamper-evidence와 역할인증, 3침입방어·신원인증, 4포괄물리보호·환경 대응으로 설명하되수준별전요구는 원문 표를 확인합니다.
- CC는TOE·ST·PP와 기능 요구/보증 요구를 구분하며 높은 평가수준이모든 위협에 서 무조건 더안전함을뜻하지 않습니다. 신속확인은 취약점·소스보안약점 점검과 보안성 심사등의 범위를 확인해야 하고 정식CC와 동일인증이라 하지 않습니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| TPM | 키·측정·증명기반 | 플랫폼 신뢰의 일부 |
| FIPS140 | 암호모듈보안 | 제품·전체 서비스와 범위구분 |
| CC/신속확인 | 제품별보안성 보증 | 대상·판본·유효성확인 |

### 적용 예제

**보안모듈 구매 검토**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** AES 지원 제품의 공공업무사용가정

1. 인증서의 모듈명·버전·운영 모드·보안경계를 확인합니다.
2. 승인 알고리즘 지원과 모듈검증을 구분합니다.
3. 키 생성·백업·복구·관리자역할·감사요구를 검토합니다.
4. 실제 배포 버전이 평가 대상과 같은 지검증합니다.

**결과·해석:** 인증 이름보다 적용 범위와 운용조건으로 보증을 판단합니다.

**전제·주의:** FIPS140-2구판원문은 확인했으나140-3전환·CC현행 절차·신속확인 최신 요건은 미확인입니다.

### 적용 기준과 근거

명시한 출처 판본의 원리를 설명하며 제품별 구현 차이는 별도 확인합니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [TPM2.0 Library](https://www.trustedcomputinggroup.org/resources/documents/tpm-library-specification) — Trusted Computing Group; 상시 규격목록; 확인 2026-11-05. 확인 범위: 공식 규격 게재 페이지 열람. PCR·seal·attest의 상세 명령 명세는 미열람.
- [FIPS140-2 Security Requirements for Cryptographic Modules](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.140-2.pdf) — NIST; 2001-05-25;2002정정; 확인 2026-11-05. 확인 범위: 69쪽 PDF의 4수준·보안영역 열람. 구판 문제 해설이며 현행 도입은140-3 전환상태 확인 필요.
