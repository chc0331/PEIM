# 벡터 DB의 HNSW·IVF 검색

## 서브노트

### 한눈에 이해

벡터가 수억 개면 매번 전부 거리를 계산하기 어렵습니다. 가까운 이웃으로 이어진 길을 따라가거나 공간을 먼저 여러 구역으로 나누어 필요한 구역만 뒤지는 방식으로 후보를 줄입니다.

### 정의와 핵심 원리

근사 최근접 탐색(ANN)은 정확도 일부와 계산/메모리를 절충하여 유사 벡터를 검색하며 HNSW는 계층 그래프, IVF는 coarse 구역의 역파일을 이용합니다.

- HNSW는 높은 층의 희소 연결로 큰 이동을 한 뒤 아래층의 촘촘한 이웃을 탐색합니다. M은 노드 연결 수, efConstruction은 구축 탐색 폭, efSearch는 질의 탐색 폭에 영향을 주며 커질수록 대체로 recall과 시간/메모리 비용이 증가합니다.
- IVF는 벡터를 학습한 중심점(centroid)에 따라 nlist개 구역으로 나누고 구역마다 벡터 목록을 저장합니다. 질의와 가까운 nprobe개 구역의 목록만 검색합니다. 실제 최근접 벡터가 다른 구역에 있으면 놓칠 수 있습니다. 구역마다 벡터 수가 달라 실제 검색량은 nprobe/nlist 비율과 다를 수 있습니다.
- 거리 척도 cosine/내적/L2·정규화·차원·필터·갱신/삭제·분산 운영을 일치시킵니다. 정확 flat 검색 결과를 기준으로 recall@k와 p95 지연·메모리·구축/갱신 비용을 측정합니다. PQ는 벡터 압축 방식이고 IVF/HNSW는 후보 탐색 방식이라 결합 가능하며 같은 분류 축의 대안으로만 놓지 않습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| Flat | 모든 후보와 정확 거리 | 기준 정답·작은 자료 |
| HNSW | 계층 근접 그래프 탐색 | 고recall/낮은 지연·메모리 부담 |
| IVF | coarse 구역 선택 후 목록 검색 | nlist/nprobe·학습·편향 |

### 적용 예제

**IVF 탐색 범위**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 벡터 100만 개를 nlist=100개 구역에 고르게 두고 nprobe=5로 검색합니다.

1. 질의 벡터와 가까운 구역 5개를 선택해 목록에 있는 약 5만 개 벡터를 비교합니다.
2. nprobe=10이면 약 10만 개 벡터를 비교합니다. 더 많은 후보를 찾아 재현율이 높아질 수 있지만 시간이 더 걸립니다.
3. 실제 목록 길이는 다를 수 있으므로 실측 후보수·정확 top-k 대비 recall을 보고합니다.

**결과·해석:** 빠르다는 주장 대신 검색 범위·정확도·자원 비용의 절충을 설명합니다.

**전제·주의:** embedding 모델 버전이나 정규화를 바꾸면 저장 벡터/질의와 색인을 함께 재검증합니다.

### 답안 골격과 혼동 방지

벡터/ANN 정의 → HNSW 구축·계층 탐색 → IVF 분할·역파일 → 파라미터 비교 → recall·지연·메모리 검증

- IVF는 모든 목록을 자동 검색한다고 쓰지 않습니다.
- Faiss의 특정 삭제 제약을 모든 HNSW 구현에 일반화하지 않습니다.
