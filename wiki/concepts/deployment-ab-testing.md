# 무중단 배포·테스트 전략·A/B 실험

## 서브노트

### 한눈에 이해

서버를 바꾸는 배포와 이용자를 나누는 실험은 목적이 다릅니다. 두 경우 모두 실패를 빨리 알아차릴 지표가 필요합니다.

### 정의와 핵심 원리

무중단 배포는 서비스 제공을 유지하면서 새 버전으로 전환하는 전략입니다. A/B 테스팅은 사용자를 무작위 집단에 배정해 대안의 인과적 효과를 비교하는 통제 실험입니다.

- 중단 배포는 프로세스를 멈추고 교체하므로 요청 실패·작업 손실·가용성 저하가 발생할 수 있습니다. 리버스 프록시는 백엔드 앞에서 요청을 대리하고 로드밸런서는 준비된 인스턴스에 분산하며 상태 확인·기존 연결을 마칠 시간을 주어 전환을 돕습니다.
- Rolling은 일부 인스턴스씩 교체하여 자원 부담을 줄이지만 구/신 버전 공존 호환성이 필요합니다. Blue-Green은 두 환경을 준비해 트래픽을 일괄 전환하므로 복귀가 빠르나 자원 비용과 데이터 호환을 고려합니다. Canary는 일부 트래픽부터 점진 확대해 영향 범위를 제한합니다.
- 배포 전 단위·계약·통합·성능·보안 시험, 배포 중 헬스체크·스모크·합성 트랜잭션, 배포 후 오류율·지연·업무 지표를 확인합니다. 스키마는 추가→양 버전 호환→전환→구필드 제거의 확장/축소 방식으로 계획하고 기능 플래그와 롤백을 준비합니다.
- A/B는 가설·분석 단위·대상·주요 지표·보호 지표·표본 크기/기간·종료 규칙을 사전에 정합니다. 사용자 단위의 안정된 무작위 배정, 집단 간 간섭·선택편향·실험 중간에 결과를 반복 확인하는 문제와 여러 지표를 비교하는 문제를 통제하고 효과 크기와 불확실성을 해석합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| Blue-Green | 두 환경 일괄 전환 | 빠른 복귀·추가 자원 |
| Rolling/Canary | 인스턴스 교체 / 트래픽 단계 확대 | 호환성과 관측·중단 기준 필요 |
| A/B | 대안의 업무 효과 실험 | 무작위 배정·통계적 검증 |

### 적용 예제

**강사 창작 적용 예시: 결제 화면 변경**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 신규 UI가 전환율을 높이는지 확인하려고 합니다.

1. Canary로 작은 운영 트래픽에서 오류·지연을 먼저 확인합니다.
2. 안정성 확인 뒤 사용자별 A/B 배정과 사전 정의한 전환·환불 지표를 측정합니다.
3. 지표 악화 시 기능을 끄고 호환 버전으로 복귀합니다.

**결과·해석:** 먼저 배포를 계속해도 되는지 판단한 뒤 화면 변경이 전환율에 미친 효과를 따로 평가합니다.

**전제·주의:** 전환율 수치·유의성은 실제 데이터 없이는 만들지 않습니다. A/B 표본설계 세부는 통계 원고와 연결해야 합니다.

### 답안 골격과 혼동 방지

중단 배포 문제·프록시/LB → 3종 배포 방식·검증·DB 호환 → A/B 목적·절차·유의점

- 무중단은 새 버전의 논리 오류까지 없다는 뜻이 아닙니다.
- Canary의 표본이 임의라면 이를 곧 A/B 인과실험으로 부르지 않습니다.

### 내용을 가리고 회상

1. Rolling에서 구/신 버전 공존이 왜 중요합니까?
2. 애플리케이션 롤백만으로 DB 변경을 복구할 수 있습니까?
3. A/B의 무작위 배정과 보호 지표는 왜 필요합니까?

### 적용 기준과 근거

배포·트래픽 분할 공식 자료를 확인했습니다. A/B의 통계 세부와 효과 추정은 별도 통계 근거 추가 대조가 필요합니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [Capabilities: Continuous delivery](https://dora.dev/capabilities/continuous-delivery/) — DORA; 지속 갱신 문서; 확인 2026-11-05. 확인 범위: 본문 또는 해당 절을 실제 열람했습니다. 자체 요약만 저장하며 외부 원문 전체는 보관하지 않습니다.
- [The Istio service mesh](https://istio.io/latest/about/service-mesh/) — Istio 프로젝트; 열람 화면 1.31.3; 확인 2026-11-05. 확인 범위: 공식 문서에서 서비스 메시 기능과 ambient/sidecar 두 배포 모드 확인. 모든 메시가 sidecar만 사용한다고 설명하지 않습니다.
- [Certified Tester Foundation Level Syllabus v4.0.1](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf) — ISTQB; 2024-09-15; 확인 2026-11-05. 확인 범위: 공개 PDF 열람. §1.3, §2.2, §3, §4, §5의 원리·기법·계획 범위를 확인했습니다. 자격시험 공식답안이라는 뜻은 아닙니다.
