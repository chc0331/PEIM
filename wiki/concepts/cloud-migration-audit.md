# 클라우드 전환 사업의 단계별 감리

## 서브노트

### 한눈에 이해

클라우드 자원을 만들었는지보다 업무와 데이터를 안전하게 옮기고 운영할 수 있는지 단계별로 검증합니다.

### 정의와 핵심 원리

클라우드 전환 감리는 전환 목표·대상 선정에서 설계·이행·시험·운영 인수까지 요구와 위험·통제를 독립적으로 점검하는 활동입니다. 전환 방식과 서비스 모델에 따라 점검 범위를 조정합니다.

- 계획/분석에서는 업무 중요도·데이터 분류·현행 자산/의존성·라이선스·비용·제약을 파악하고 공공/민간·IaaS/PaaS/SaaS·전환 방식·우선순위·중단 허용·출구전략의 타당성을 검토합니다. 가상서버 이전만으로 클라우드 네이티브 목표가 충족되지는 않습니다.
- 설계에서는 자원·망·계정/권한·암호키·모니터링·백업·가용성·재해복구·SLA·책임분담, 앱의 상태·확장·연계·데이터 이전 구조를 확인합니다. 규정상 보안성 검토·인증·데이터 위치 요건은 적용대상과 현행 기준을 별도 대조합니다.
- 구축/전환에서는 IaC·설정·접근권한·이미지·보안구성, 단계별 데이터 이관·정합성·재처리, 구/신 시스템 연계와 전환순서·롤백 계획이 설계대로 구현되었는지 실증합니다. 원본과 이관 증거를 보존합니다.
- 시험/종료에서는 기능·성능·부하·확장·장애·복구·보안 시험과 사용자 인수, 운영 매뉴얼·교육·자산/권한 인계, 지표·비용·SLA 보고·공급자 지원·종료 시 데이터 반환/삭제를 확인합니다. 감리 지적의 조치 결과를 다시 확인하고 미해결 위험의 승인 주체를 기록합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 분석 | 전환 대상·제약·목표·계획 | 업무·데이터·의존성 누락 점검 |
| 설계/이행 | 목표 구조·변경·이관 통제 | 책임분담·일관성·롤백 |
| 검증/운영인수 | 실제 서비스와 복구 능력 | 시험·운영 증거와 잔여 위험 |

### 적용 예제

**강사 창작 적용 예시: 신청 포털 클라우드 이전**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 첨부파일 서버와 인증 서버가 외부 연계에 의존합니다.

1. 현행 의존성과 중단 허용시간을 분석합니다.
2. 첨부 저장·세션·인증 경로와 백업 복구를 설계·검토합니다.
3. 모의 이관·부하·장애·복구 시험을 거쳐 운영 인계의 누락을 확인합니다.

**결과·해석:** 인프라 구성 완료와 업무 서비스 전환 완료를 구분합니다.

**전제·주의:** 가용률·인증 필요 여부는 문항 시점과 실제 법령·계약 조건으로 확인해야 합니다.

### 답안 골격과 혼동 방지

전환 유형·감리 범위 → 분석→설계→구축/이행→시험/종료 → 단계별 산출물·실증·시정조치

- CSP가 맡는 보안과 고객이 맡는 앱/데이터 보안을 구분합니다.
- 운영비 감소를 측정 없이 성과로 주장하지 않습니다.
