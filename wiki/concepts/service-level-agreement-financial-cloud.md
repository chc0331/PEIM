# SLA 지표·측정·금융 클라우드

## 서브노트

### 한눈에 이해

좋은 SLA는 높은 숫자만 적는 계약이 아니라, 무엇을 어느 구간에서 누가 어떻게 측정하고 미달 때 무엇을 할지 정합니다.

### 정의와 핵심 원리

SLA는 서비스 제공자와 이용자가 서비스 범위·역할·수준·측정·보고·미달 조치와 변경을 합의하는 약정입니다. 클라우드는 서비스 모델별 책임과 외부 의존·데이터 종료를 함께 다룹니다.

- 구성은 서비스·적용대상/기간·지원시간·역할·정의, 지표·목표/최소수준·측정원·주기·제외조건·가중치, 보고·검토·개선, 위약/보상·분쟁·변경·종료입니다. 요구분석→지표/수준 협의→계약→측정/보고→평가/개선→갱신 절차로 운영합니다.
- 전자상거래의 HW는 가용성·CPU/메모리·복구시간, SW는 결제성공·주문처리 지연·오류율·배포실패, 네트워크는 지연·손실·대역폭·가용성을 측정할 수 있습니다. 자원 지표와 고객이 보는 업무 성공을 함께 측정해야 합니다.
- 가용률=(약정서비스시간−산정장애시간)/약정서비스시간×100이며 장애 시작/종료·부분 장애·계획정지·고객귀책·중복 장애·측정 실패를 정의해야 합니다. 평균만으로 장시간·반복 장애나 꼬리 지연이 가려지지 않게 보호 지표를 둡니다.
- 금융 클라우드에서는 업무 중요도·CSP 위험·보안/연속성 평가, 위탁/재위탁·감사권·접근/통제·사고 통지·데이터 위치/반환/파기·출구전략을 계약에 반영합니다. 2025 금융보안원 가이드는2025.2.5 시행 감독규정을 반영하므로130회 당시 절차와 보고기한을 혼합하지 않습니다.
- 강사 생성 측정 예시: HW는 모니터링 시스템에서 1분 간격 CPU 사용률을 수집해 월간 평균·상위 백분위수를 산출합니다. SW는 결제 API 로그에서 성공 건수/전체 유효 시도 건수와 처리시간 p95를 구하고 오류·중복 포함 규칙을 합의합니다. 네트워크는 합의한 측정지점과 대상 사이에서 정기 탐침으로 왕복지연과 송신 대비 손실 비율을 측정합니다. 이 주기·방법은 학습용 설계이며 목표·제외조건·측정 실패 처리는 계약에서 정합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 서비스 지표 | 응답·성공·가용성 | 고객 체감 결과 |
| 운영 지표 | 자원·작업·복구·요청 | 문제 원인과 개선 관리 |
| 금융 클라우드 | 감사·연속성·데이터/위탁 통제 | 책임분담·종료·규제 반영 |

### 적용 예제

**강사 창작 적용 예시: 월 가용률 산술**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 30일24시간 서비스, 산정 대상 장애60분입니다.

1. 약정시간43200분을 계산합니다.
2. 가용률=(43200−60)/43200×100≈99.8611%입니다.
3. 제외조건·장애 중복과 실제 결제 영향에 따라 산정 근거를 검토합니다.

**결과·해석:** 분모와 산정범위를 명확히 하는 연습입니다.

**전제·주의:** 예시는 특정 공공/금융 SLA의 목표나 위약금 기준이 아닙니다.

### 답안 골격과 혼동 방지

SLA 구성·수립 절차 → HW/SW/망 지표·측정 사례 → 클라우드·금융 통제·가용률 계산

- RTO와 SLA 장애조치시간을 자동으로 같은 값이라 보지 않습니다.
- 제공자 가용률 합의가 고객 전체 업무 가용성을 보장하지 않습니다.

### 내용을 가리고 회상

1. 가용률 산정의 분모를 어떻게 정의합니까?
2. 전자상거래 SW 지표로 결제성공을 보는 이유는 무엇입니까?
3. 출구전략에서 데이터 반환 외에 무엇을 확인합니까?

### 적용 기준과 근거

일반 SLA 공식 표준 적용범위·운영 가이드는 확인. 금융2025 공식 배포는 확인했고 세부 원문 대조 중이며130회 당시 금융 가이드와의 차이는 추가 확인 필요합니다.
