# 좀비 프로세스와 자식 회수

## 서브노트

### 한눈에 이해

실행은 끝났지만 부모가 종료 결과를 가져가지 않아 작은 종료 기록이 남아 있는 상태입니다.

### 정의와 핵심 원리

좀비 프로세스는 종료했으나 부모가 wait 계열 호출로 종료 상태를 회수하지 않아 프로세스 테이블의 상태 정보가 남은 프로세스입니다. 계속 실행하는 프로세스나 부모를 잃은 고아 프로세스와 구분합니다.

- 자식 종료시주소 공간등대부분의자원은 해제되지만PID·종료 상태·사용자원 통계등을 부모가 확인할때까지보존합니다.wait/waitpid/waitid는 자식의 상태변화를기다리고종료 결과를 회수할 수 있게합니다.
- 부모는 다수자식이 동시에종료할 수 있으므로SIGCHLD를 받았다는사실만세지않고WNOHANG을 이용한반복회수등설계에 맞는방법을 사용합니다.명시적인SIGCHLD무시·SA_NOCLDWAIT동작은 운영체제규칙을 확인합니다.
- 좀비자체는이미종료했으므로kill로실행을 중단시킬대상이 아닙니다.회수하지 않는부모의 버그를고치거나적절한 재시작으로 관리 주체가 회수하게합니다.컨테이너에서도PID1역할을하는프로세스의 자식 회수 기능을 확인해야합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 좀비 | 자식 종료·결과미회수 | 프로세스슬롯·PID고갈가능 |
| 고아 | 부모가 먼저 종료 | 다른 관리 주체에 재부모화 |
| 실행·대기 | 아직작업이 끝나지않음 | CPU·I/O·잠금 상태 분석 |

### 적용 예제

**배치 서버의 종료 누락**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 부모가 매초자식 10개생성;모두즉시종료;wait없음

1. ps의상태Z와 부모PID를 확인합니다.
2. 60초면최대 600개의미 회수 종료 기록이 쌓일수 있습니다.
3. 부모의 상태 회수루프를추가 하고 이미대기가능한 모든 자식을 회수합니다.
4. 반복부하후Z상태개수가증가하지 않고종료 코드 처리가 유지되는지확인합니다.

**결과·해석:** CPU사용량보다 미회수 자식수의증가를 증거로 원인을 판단합니다.

**전제·주의:** 부모 강제 종료는 다른 업무를 중단할 수 있으므로프로그램 수정과 정상관리 절차를 우선합니다.

### 답안 골격과 혼동 방지

정의·상태전이 → 남는정보 → wait와SIGCHLD → 고아비교 → 컨테이너회수

- 좀비를죽지않는실행 프로세스라하지 않습니다.
- 메모리전체가계속점유된다고설명하지 않습니다.
