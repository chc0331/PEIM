# 반정규화와 조회 성능의 대가

## 서브노트

### 한눈에 이해

정규화한 고객·주문 표를 매번 합치는 일이 실제 병목일 때, 조회용 요약을 더 만들어 속도를 얻을 수 있습니다. 대신 요약이 원본과 어긋나지 않도록 관리해야 합니다.

### 정의와 핵심 원리

측정된 성능 문제를 해결하기 위해 중복·집계·분할·병합 등을 의도적으로 도입하는 물리 설계 최적화입니다.

- 절차는 병목 SQL·접근 빈도·실행계획 확인→인덱스/SQL/메모리 등 대안 검토→반정규화 후보 선정→갱신 경로·정합성 설계→부하 시험입니다. 논리 모델의 오류를 성능이라는 이름으로 덮지 않습니다.
- 테이블 병합은 잦은 조인을 줄이고, 수평/수직 분할은 읽을 범위를 줄이며, 중복 컬럼·집계 테이블은 반복 계산을 줄입니다. 이들은 목적과 장애 시 복구 방식이 서로 다르므로 모두 중복 저장 하나로 설명하면 부족합니다.
- 중복의 원본, 동기/비동기 갱신, 허용 지연, 재생성 방법을 정합니다. 조회 속도만 측정하면 갱신 비용·저장량·오류 복구가 빠집니다. 실시간 잔액은 강한 정합성이 필요하지만 일별 통계는 지연 갱신을 허용할 수 있습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 병합 | 자주 함께 읽는 표 결합 | 중복·희소 컬럼 증가 |
| 중복 컬럼 | 조인 없이 속성 조회 | 원본 변경 전파 필요 |
| 집계 표 | 합계·건수 미리 계산 | 갱신 시점·재계산 필요 |

### 적용 예제

**일별 매출 요약**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 주문 1천만 건에서 날짜별 합계를 수초마다 조회합니다.

1. 원본 주문의 날짜·금액을 집계하는 비용이 병목인지 계획과 부하로 확인합니다.
2. 일매출(일자 PK,건수,합계)을 만들고 완료된 주문만 반영하는 작업을 설계합니다.
3. 늦게 도착한 취소·환불을 반영하고, 같은 일자의 원본 SUM과 요약 합계를 정기 대사합니다.

**결과·해석:** 조회는 작은 요약 표를 읽지만 원본·요약 간 갱신 책임이 추가됩니다.

**전제·주의:** 요약 갱신 재실행 때 같은 주문을 두 번 더하지 않도록 처리 식별자나 재계산 단위를 정합니다.

### 답안 골격과 혼동 방지

정의·도입 조건 → 측정→대안→선정→검증 → 병합/분할/중복/집계 → 정합성·갱신 책임 → 전후 비용 비교

- 정규화 역순으로 모든 표를 합치는 작업이 아닙니다.
- 캐시·인덱스로 충분한데 원본 중복부터 도입하지 않습니다.
