# 데이터 거버넌스와 마스터 데이터 관리

## 서브노트

### 한눈에 이해

같은 고객이 영업에는 A123, 정산에는 C456으로 있으면 매출이 둘로 나뉩니다. 누가 기준을 정하고 어떤 고객이 동일인인지 판정하며 수정 책임을 질지 정해야 합니다.

### 정의와 핵심 원리

데이터 거버넌스는 데이터의 의사결정 권한·책임·정책을 운영하는 체계이며 MDM은 핵심 업무 대상의 신뢰할 기준 레코드를 관리하는 실행 체계입니다.

- 거버넌스는 데이터 owner/steward, 표준·품질·메타데이터·계보·접근 정책·이슈 조정·성과 지표를 연결합니다. 중앙 조직이 공통 원칙을 정하고 업무 부서가 뜻과 품질을 책임지는 연합 운영도 가능합니다. 도구 설치만으로 책임체계가 생기지는 않습니다.
- 마스터는 고객·상품·조직처럼 거래의 기준이 되는 비교적 지속적인 업무 대상입니다. 거래 데이터는 주문·결제 같은 사건이고 참조 데이터는 국가·상태 코드처럼 허용값 집합입니다. 모든 데이터를 하나의 중앙 원장에 모으는 것이 MDM의 유일한 방식은 아닙니다.
- MDM은 원천 식별→표준화→매칭·중복 제거→상충 해결/생존 규칙→golden record·전역 ID→배포·동기화·이력 관리로 설계합니다. 식별 정확도·기존 시스템 영향·단계 도입·업무 승인·오병합 복구가 핵심입니다. Microsoft MDS는 예시 제품이며 2025에서 제거된 지원 상태를 신규 권장안과 구분합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 마스터 | 고객·상품 등 핵심 대상 | 전역 ID·중복/상충 해결 |
| 거래 | 주문·결제 등 사건 | 시간·금액·상태 이력 |
| 참조 | 코드·분류 값 집합 | 코드 정의·유효기간 |

### 적용 예제

**고객 중복 통합**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 영업 A123과 정산 C456이 같은 고객으로 추정됩니다.

1. 이메일 하나만으로 자동 병합하지 않고 신뢰도 높은 식별 규칙과 업무 검토 기준을 정합니다.
2. 전역 고객ID와 각 원천ID의 매핑을 보존하고 주소 상충 시 최신성/원천 신뢰도 규칙을 적용합니다.
3. 병합 근거·승인·이력을 남기고 오류 시 분리 복구하며 관련 시스템에 변경을 전파합니다.

**결과·해석:** 데이터 통합은 행 합치기보다 의사결정과 추적 책임의 문제입니다.

**전제·주의:** 법적 개인정보 처리 요건은 별도 검토 대상이며 MDM이 활용 권한을 자동 부여하지 않습니다.

### 답안 골격과 혼동 방지

거버넌스 정의·기능 → 마스터 필요성·분류 → MDM 구성·흐름 → 역할과 품질 지표 → 도입·상충·복구 고려

- 마스터를 항상 변하지 않는 데이터라고 정의하지 않습니다.
- golden record에서 원천과 이력을 지우지 않습니다.
