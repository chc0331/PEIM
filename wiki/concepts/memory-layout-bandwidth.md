# 엔디언·메모리 인터리빙·캐시 일관성

## 서브노트

### 한눈에 이해

바이트를 어떤 순서로 놓을지, 연속 접근을 여러 메모리에 어떻게 나눌지, 복제된 캐시 값의 충돌을 어떻게 막을지 구분합니다.

### 정의와 핵심 원리

엔디언은 다중바이트 값의 바이트 배치 순서이고 메모리 인터리빙은 주소를 여러 뱅크·채널에 분산하여 병렬성을 높이는 배치 기법입니다. 캐시는 자주 쓰는 데이터를 가까운 계층에 복제하며 여러 코어의 사본에 는 일관성이 필요합니다.

- 빅엔디언은최상위바이트를낮은 주소에, 리틀엔디언은최하위바이트를낮은 주소에 둡니다.값자체나비트의중요도가바뀌는것은아닙니다.통신·파일형식은명시한 바이트순서로 직렬화하고 호스트와변환합니다.
- 하위주소비트로뱅크를고르는저위인터리빙은연속주소를 다른 뱅크로보내병렬·파이프라인 접근을 돕습니다.같은 뱅크로몰리는stride접근은 충돌할 수 있습니다.캐시선·채널·NUMA의배치와한계는 장치구성에따릅니다.
- write-through는 하위계층에 함께 반영하고 write-back은dirty상태로 두었다가축출등의 시점에 반영합니다.멀티코어에 서 동일캐시선의사본이 낡으면일관성문제가 생겨snooping·directory와MESI계열상태 프로토콜로 소유권·무효화를관리합니다.일관성과메모리일관성모델은 동일개념이 아닙니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 엔디언 | 값의 바이트순서 | 포맷명세와변환 |
| 인터리빙 | 주소의 뱅크분산 | 대역폭 증가·뱅크충돌 |
| 캐시 일관성 | 여러 사본의 쓰기전파 | false sharing·프로토콜 비용 |

### 적용 예제

**바이트와 뱅크 배치**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 32비트0x12345678;주소100~103;4뱅크

1. 빅엔디언은12, 34, 56, 78;리틀엔디언은78, 56, 34, 12입니다.
2. 워드주소mod4로뱅크를고르면0, 1, 2, 3은 서로 다른 뱅크입니다.
3. 0, 4, 8, 12는 모두뱅크0이 므로 연속접근과 같은 병렬성을 기대할 수 없습니다.
4. 두코어가 같은 캐시선의서로 다른 변수를수정하면 false sharing이 가능합니다.

**결과·해석:** 순서·배치·사본 관리라는서로 다른 문제를 구체예로구분합니다.

**전제·주의:** 엔디언·인터리빙·MESI상세의직접 명세는추가 확인이 필요하며 DMA공식 문서로 주소·일관성기본 범위만 검증했습니다.

### 답안 골격과 혼동 방지

계층 구조 → 엔디언예 → 인터리빙계산 → 쓰기 정책·일관성 → 성능 절충

- write-through가 동시성 잠금을 대체하지 않습니다.
- 엔디언을주소 증가방향과혼동하지 않습니다.
