# 데이터 커머스와 거래소

## 서브노트

### 한눈에 이해

데이터 파일을 전송한다고 거래가 끝나지는 않습니다. 구매자는 무엇이 들어 있는지, 어떤 조건으로 쓸 수 있는지, 얼마나 자주 갱신되는지와 품질을 알아야 합니다.

### 정의와 핵심 원리

데이터를 발굴·가공·상품화하여 검색·평가·계약·제공·사용 정산으로 연결하는 거래 활동이며 거래소는 그 중개와 신뢰 기능을 제공하는 플랫폼입니다.

- 공급자는 메타데이터·표본·범위·갱신 주기·품질·이용 권리·가격을 설명합니다. 소비자는 목적에 맞는지, 다른 자료와 결합할 수 있는지, 비용이 적절한지 확인합니다. 같은 자료의 가치도 가공 방식, 결합할 자료, 독점 여부, 용도에 따라 달라집니다.
- 거래소는 목록/검색·표본/시험 분석·품질 정보·가치평가 연계·이용조건/계약·전달/API·정산/감사를 연결합니다. 파일 납품, API 구독, 플랫폼 내 공유, 통제된 분석 후 결과 반출 등 제공 방식이 다르며 복제·유출·만료·최신성 책임도 달라집니다.
- 기술은 표준 스키마·catalog·matching·API·usage metering·권한·추적과 품질 검증을 포함합니다. 금융 위험 분석·유통 상권 분석·교통/기상 수요예측 등에 활용할 수 있으나 가상 예시와 실제 공개 거래를 구분합니다. 거래 가격은 협상 결과이고 경제적 가치 추정치와 동일하지 않습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 파일 판매 | 일정 시점 자료 전달 | 갱신·재배포 범위 확인 |
| API/구독 | 지속 접근·호출량 과금 | 가용성·쿼터·변경 공지 |
| 플랫폼 공유 | 목록에서 조회·결합 | 공유 조건·권한·결제 |

### 적용 예제

**상권 수요 데이터 구매**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 소매업체가 지역별 유동 인구와 날씨 자료로 재고를 예측합니다.

1. 상세 개인 이동 이력 대신 업무 목적에 필요한 지역·시간 집계의 상품 명세를 비교합니다.
2. 표본으로 누락률·갱신 지연을 확인합니다. 필요한 지역이 들어 있는지와 매출 표에 연결할 수 있는지도 시험합니다.
3. 기간/용도/갱신 주기/제공 방식/장애·오류 조치/요금을 계약에 명시하고 사용량을 대사합니다.

**결과·해석:** 카탈로그의 설명과 실제 활용 검증을 통해 거래 불확실성을 줄입니다.

**전제·주의:** 개인정보·저작권 등 적법성은 해당 법·허용 조건을 별도 확인해야 합니다.

### 답안 골격과 혼동 방지

개념·중요성 → 공급자-거래소-소비자 흐름 → 기술·제공 모델 → 특징·활용 → 권리·품질·지속성

- 데이터 거래를 원본 소유권 전체 양도로 단정하지 않습니다.
- 한 거래소의 공유 구현을 모든 거래소에 일반화하지 않습니다.
