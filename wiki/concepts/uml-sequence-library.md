# UML 순차 다이어그램과 도서예약 변환

## 서브노트

### 한눈에 이해

협력 다이어그램을 순차 다이어그램으로 바꿀 때는 메시지를 번호 순서대로 배치하고 조건을 그대로 옮깁니다.

### 정의와 핵심 원리

순차 다이어그램은 상호작용 참여자의 생명선 사이 메시지 발생 순서와 조건을 보여주는 UML 상호작용 다이어그램입니다. 호출 번호와 가드를 보존하며 협력 구조를 시간 순서로 바꿉니다.

- Frame은 좌상단 sd와 상호작용 이름을 가진 범위입니다. Object는 objectName:Class 형식의 참여자 머리, Lifeline은 아래로 뻗는 점선, Activation(ExecutionSpecification)은 실행 중 구간의 얇은 직사각형입니다.
- 동기 호출은 닫힌 화살촉의 실선, 비동기 메시지는 열린 화살촉, 반환은 점선 화살표로 구별합니다. Guard는 [조건]으로 쓰며 alt 프레임은 상호배타적 대안, opt는 선택 동작, loop는 반복을 표현합니다. 위에서 아래는 발생 순서이며 수평 길이가 수행 시간은 아닙니다.
- 목적은 참여자 간 메시지의 시간 순서·조건·실행 책임을 표현하는 것입니다. 작성은 시나리오/참여자 선정→lifeline 배치→원도식 번호/화살표에 맞춘 메시지→guard/대안·실행 구간→정합성 검토입니다. 참여자는 대여자, 대여, 예약, 도서, 도서항목이며 127회 공식 PDF p.7 원도식을 직접 렌더링해 연결을 확인했습니다.
- 원도식 연결은 1 대여자→대여:대여요청, 2 대여→도서:재고확인, 3 [재고=0] 도서→대여:재고없음통보, 3 [재고>0] 도서→도서항목:대여처리, 3 도서항목→대여:대여처리, 4 대여→예약:예약요청, 5 예약→도서:예약처리입니다. 원문의 4·5에는 가드가 없어 재고=0일 때만 예약한다고 단정하지 않고 후속 메시지로 보존합니다. 통보 메시지의 반환 타입·동기성도 원도식에서 확정하지 않습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 협력/통신 다이어그램 | 연결과 메시지 번호 중심 | 번호·중첩 번호로 순서 식별 |
| 순차 다이어그램 | 생명선과 시간순 메시지 | 조건·반복·활성 구간 가시화 |
| Guard / 반환 | 실행 조건 / 응답 | 조건은 대괄호, 반환은 점선으로 구분 |

### 적용 예제

**강사 구성 적용 예시: 기출 도서예약 상호작용의 변환**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 127회 원도식의 참여자 5개·메시지 번호 1~5와 재고 조건을 사용합니다.

1. 참여자 lifeline을 배치하고 1 대여요청과 2 재고확인을 위에서 아래로 연결합니다.
2. 원도식의 번호 3은 재고=0 통보와 재고>0 대여처리의 조건을 표시하고 도서항목→대여의 대여처리도 연결합니다.
3. 4 대여→예약, 5 예약→도서를 번호 뒤에 보존하고 원문에 없는 가드·반환값은 추가하지 않습니다.

**결과·해석:** 원도식의 객체·연결·호출 순서를 보존한 순차 표현을 구성합니다.

**전제·주의:** 공식 답안이 아닌 강사 변환 예입니다. 번호 3의 세부 순서와 4·5가 실행되는 조건을 정했다면 설계 가정임을 밝힙니다. 원도식만으로 재고 없음 통보가 반환 메시지인지 확정할 수 없습니다.

### 답안 골격과 혼동 방지

목적·작성순서 → Frame/Object/Lifeline/Activation/Message/Guard 표기 → 도서예약 메시지와 alt 변환

- 가드를 메시지 이름의 설명으로만 쓰고 분기를 없애지 않습니다.
- 원문 도식에서 불명확한 연결을 사실처럼 보충하지 않습니다.

### 내용을 가리고 회상

1. 동기·비동기·반환 화살표를 구분해 보십시오.
2. 재고 0과 재고 양수는 어떤 프레임에 배치합니까?
3. 활성상자와 생명선은 어떻게 다릅니까?

### 적용 기준과 근거

제127회 기출 PDF 7쪽의 도식과 OMG UML 2.5.1의 시퀀스 표기를 확인했습니다. 기출에서 지정한 UML 2.0과 공통으로 쓰는 표기를 사용했습니다. 도식에 표시되지 않은 가드와 호출·반환 유형은 판단을 보류했습니다.
