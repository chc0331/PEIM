# 차분 프라이버시와 프라이버시 예산

## 서브노트

### 한눈에 이해

한 사람의 포함 여부가 발표 결과를 크게 바꾸지 않게 만들어 참여자의 추가 노출을 제한합니다.

### 정의와 핵심 원리

차분 프라이버시(DP)는 한 사람의 기록 포함 여부만 다른 인접 데이터셋을 비교해, 확률적 알고리즘의 출력 분포가 얼마나 달라질 수 있는지 제한하는 정의입니다. ε는 출력 확률의 차이를 제한하는 배율에 관여하고, (ε, δ)-DP의 δ는 확률 상한에 더하는 여유입니다.

- 순수 ε-DP는 모든 출력 사건 S에 대해 Pr[M(D)∈S] ≤ exp(ε)Pr[M(D′)∈S]를 요구합니다. 같은 조건에서는 ε가 작을수록 허용하는 차이가 작아져 보호가 강해집니다. 대신 잡음이 커져 결과의 유용성이 떨어질 수 있습니다. ε는 재식별 확률이나 출력 오차율과 구분합니다.
- 질의 민감도는 한 기록의 변경으로 결과가 달라질 수 있는 최대 크기입니다. 라플라스 기법은 일반적으로 척도 Δf/ε의 잡음을 더합니다. 합계 질의에서 개인의 값을 제한하지 않으면 민감도가 무한히 커질 수 있으므로 인접성의 정의와 값의 범위를 밝힙니다.
- 질의를 반복하면 결과에서 얻는 정보가 쌓이므로 프라이버시 예산을 관리합니다. 순수 ε-DP의 기본 순차 합성 상한은 각 ε의 합입니다. 추가 원자료를 보지 않고 출력만 가공하면 보호가 약해지지 않습니다. 중앙형은 신뢰하는 집계자가 원자료를 처리하고, 로컬형은 각 단말이 값을 바꾼 뒤 전송합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 중앙 DP | 신뢰하는 집계자가 원자료 처리 | 집계자 신뢰와 접근 통제 필요 |
| 로컬 DP | 각 단말에서 값을 무작위로 바꿔 전송 | 집계자에게 원자료를 주지 않음, 오차 증가 가능 |
| 출력 관리 | 예산·민감도·질의 횟수 관리 | 예산 계산과 결과 유용성 확인 |

### 적용 예제

**인원수 질의의 잡음 척도**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 개인당 기록 한 건이며, 인접 데이터셋은 한 사람의 기록이 있거나 없는 경우입니다. 인원수를 세는 질의의 민감도는 1입니다.

1. ε = 0.5이면 라플라스 분포의 척도 b = 1/0.5 = 2입니다.
2. 2는 잡음 분포의 척도입니다. 실제로 더하는 값은 호출할 때마다 달라질 수 있습니다.
3. 같은 데이터셋에 ε = 0.5인 질의를 세 번 실행하면 기본 순차 합성 상한은 1.5입니다.
4. 필요한 정확도, 표본 수, 발표 정책을 바탕으로 예산을 나눕니다.

**결과·해석:** DP는 결과에서 개인의 포함 여부를 얼마나 구분할 수 있는지 제한합니다. 실제 오차와 공개 횟수는 별도로 관리합니다.

**전제·주의:** 인원수 질의와 기본 합성을 설명하는 예제입니다. 학습 알고리즘에 DP를 적용하려면 인접성과 보호 조건을 별도로 확인해야 합니다.

### 답안 골격과 혼동 방지

인접성·정의식 → ε와 δ의 의미 → 민감도와 라플라스 잡음 → 합성과 예산 → 중앙·로컬 신뢰 모형

- ε를 익명성을 보장하는 백분율로 해석하지 않습니다.
- 잡음을 더한 뒤에도 DP의 정의식이 성립하는지 확인해야 합니다.

### 내용을 가리고 회상

1. 민감도는 무엇이 변할 때의 최대 변화량입니까?
2. 질의를 여러 번 하면 프라이버시 예산을 더 사용하는 이유는 무엇입니까?
3. 합계를 구할 때 개인별 값의 범위를 정해야 하는 이유는 무엇입니까?
