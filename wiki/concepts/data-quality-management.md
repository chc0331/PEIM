# 데이터 품질의 진단·개선·성숙도

## 서브노트

### 한눈에 이해

값이 채워져 있다고 쓸 수 있는 자료는 아닙니다. 고객 전화번호가 모두 있어도 숫자가 틀리거나 예전 번호이면 안내 업무에 실패합니다. 목적에 맞는 규칙과 개선 책임이 필요합니다.

### 정의와 핵심 원리

사용 목적에 적합한 데이터 상태를 정의하고 생애주기 전반에 측정·원인 분석·개선·통제하는 조직적 활동입니다.

- 품질 아키텍처는 owner/steward와 정책, 표준·메타데이터, 수집/저장/연계 흐름, 규칙 저장소·진단 도구·지표 대시보드·개선 작업을 연결합니다. 총괄 책임자는 정책·예산·역할·우선순위·부서 간 이슈 조정과 개선 이행을 책임지고 개별 오류 전부를 직접 수정하는 역할은 아닙니다.
- 진단은 범위/목표→프로파일링→업무규칙 정의→측정→오류 원인/영향 분석→개선→재진단·지속 통제 순입니다. 정확성·완전성·유효성·일관성·유일성·적시성을 구분하고 분모·제외값·측정시점을 고정합니다. 비정형은 파일 손상·해상도·음질·내용/라벨·메타데이터를 추가 검증합니다.
- 기획에서 품질 목표를 정하고 생성/수집에서 오류 유입을 막고 저장/처리에서 규칙·계보·변경을 관리하며 제공/활용에서 지연·사용자 신고를 반영합니다. 성숙도는 임시 사후 수정→반복 절차→전사 표준→측정 관리→지속 개선으로 설명할 수 있으나 특정 공식 모델의 등급 명칭으로 위장하지 않습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| 정확성·유효성 | 현실 참값/허용 규칙 부합 | 규칙 통과가 참값 일치를 보장하지 않음 |
| 완전성·유일성 | 필요값 누락/중복 여부 | 대상·분모 선언 |
| 정형·비정형 | 컬럼/관계 또는 파일/내용/라벨 | 특성별 검사 추가 |

### 적용 예제

**주소 품질 개선**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 고객 1,000명 중 필수 주소 NULL 20건, 우편번호 형식 오류 30건입니다.

1. 완전성은 (1000−20)/1000=98%로 계산합니다. 형식 오류 30건과 참값 오류는 별도로 셉니다.
2. 오류 발생 시스템·입력 규칙·변환 배치·연계 실패를 추적하여 원인을 고칩니다.
3. 입력 검증과 수정 책임·기한을 정하고 같은 규칙·분모로 재진단하여 재발률을 봅니다.

**결과·해석:** 품질 수치와 예방·개선 활동을 하나의 통제 고리로 연결합니다.

**전제·주의:** NULL 제외 후 비율을 내면 완전성 분모가 왜곡될 수 있으므로 목적별 산식을 공개합니다.

### 답안 골격과 혼동 방지

품질 정의·아키텍처 → 책임자 역할 → 생애주기 활동 → 진단→원인→개선 → 정형/비정형·성숙도

- 등급을 제시하려면 어떤 성숙도 모델인지 밝혀야 합니다.
- 검사 통과율 하나로 모든 품질을 대표하지 않습니다.

### 내용을 가리고 회상

1. 정확성과 형식 유효성은 왜 다릅니까?
2. 오류값만 수정하고 입력 원인을 두면 어떻게 됩니까?
3. 품질 지표의 분모·시점을 왜 고정해야 합니까?

### 적용 기준과 근거

일반 품질 차원·검증 구성과 공공 예방 활동은 확인했습니다. 131회가 의도한 특정 성숙도 모델의 등급별 공식 정의는 미확인으로 구분합니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [Data quality use cases](https://legacy.docs.greatexpectations.io/docs/reference/learn/data_quality_use_cases/dq_use_cases_lp/) — Great Expectations; GX 1.23.2 표시; 확인 2026-11-05. 확인 범위: 실제 열람: distribution/freshness/integrity/missingness/schema/uniqueness/volume와 비정형 metadata 검사. 국내 공공 성숙도 모델 등급을 이 문서로 검증하지 않습니다.
- [Data governance with Microsoft Purview](https://learn.microsoft.com/en-us/purview/data-governance-overview) — Microsoft; 문서 날짜 미표시; 2026-11-05 확인; 확인 2026-11-05. 확인 범위: 실제 열람: 중앙 data office·domain stewards 연합 운영, catalog/data map·metadata와 원데이터 권한의 차이. 거버넌스의 실무 예이며 법정 표준이라고 표현하지 않습니다.
