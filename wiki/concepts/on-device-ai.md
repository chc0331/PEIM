# 온디바이스 AI의 경량화와 실행

## 서브노트

### 한눈에 이해

휴대기기가 음성을 직접 인식하면 네트워크가 끊겨도 동작할 수 있습니다. 기기의 메모리·전력·발열 한계를 고려해 모델을 줄이고, 실제 기기에서 지연과 정확도를 측정합니다.

### 정의와 핵심 원리

추론 또는 일부 학습을 사용자 기기/엣지의 연산 자원에서 수행하여 지연·연결 의존·원자료 이동을 줄이는 AI 실행 방식입니다.

- 하드웨어는 CPU·GPU·DSP/NPU·메모리·센서·전력/열 제어, 소프트웨어는 학습 모델·변환/최적화·runtime·가속 delegate·입출력 전처리로 구성합니다. 모델 연산자와 가속기 지원이 맞지 않으면 일부가 CPU로 돌아가 예상 이득이 사라질 수 있습니다.
- 경량화는 quantization(정밀도 축소), pruning(가중치/구조 희소화), distillation(교사 행동을 학생 모델에 학습), 효율적 구조·연산 fusion·캐시 등을 검토합니다. PTQ는 학습 후 변환, QAT는 학습 중 양자화 영향을 반영하며 실제 기기의 지원 정수 연산·보정 데이터·정확도 변화가 중요합니다.
- 효과는 낮은 왕복 지연·오프라인 동작·원자료 외부 이동 감소·클라우드 비용 절감 가능성입니다. 한계는 모델 크기·배터리·발열·기기 이질성·업데이트·관측·가중치 노출입니다. 일부 과업만 로컬·어려운 요청은 서버로 보내는 hybrid도 가능하며 개인정보 보호는 로컬 실행만으로 완결되지 않습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·주의 |
| --- | --- | --- |
| Cloud AI | 큰 자원·중앙 갱신 | 네트워크·전송·비용 |
| On-device | 기기 내 빠른 추론 | 메모리·전력·지원 연산자 |
| Hybrid | 로컬/서버 과업 분담 | 전송 기준·일관성·오프라인 |

### 적용 예제

**모델 크기 계산**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 가중치 100만 개를 FP32에서 INT8로 바꾼다고 가정합니다.

1. 가중치 값만 저장할 때 FP32는 100만×4바이트=4MB, INT8은 100만×1바이트=1MB입니다.
2. 가중치 저장량은 4분의 1입니다. 전체 메모리 사용량을 계산하려면 스케일·영점 정보와 실행 환경, 활성값, 캐시를 포함해야 합니다.
3. 실기기에서 정확도·p95 지연·배터리·열·미지원 연산의 CPU fallback을 확인합니다.

**결과·해석:** 파일 크기 감소와 전체 메모리/서비스 속도 개선을 구분할 수 있습니다.

**전제·주의:** 양자화가 곧 양자 컴퓨팅이라는 뜻이 아니며 모든 연산이 4배 빨라지지 않습니다.

### 답안 골격과 혼동 방지

정의·배경 → HW/SW 구조 → 경량화·runtime → 효과·제약 → 실기기 평가·hybrid

- 로컬 AI를 학습이 항상 기기에서 일어나는 것으로 정의하지 않습니다.
- 메모리 감소율을 지연 감소율로 바로 바꾸지 않습니다.
