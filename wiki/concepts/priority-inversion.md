# 우선순위 역전·상속·천장

## 서브노트

### 한눈에 이해

급한 작업이 덜 급한 작업의 잠금을 기다리는데, 중간 순위 작업까지 끼어들어 지연이 길어지는 문제입니다.

### 정의와 핵심 원리

우선순위 역전은 높은 우선순위 작업이 낮은 우선순위 작업이 점유한 자원 때문에 막히는 현상입니다. 중간 우선순위 작업이 낮은 작업을 선점하면 높은 작업의 대기 시간이 간접적으로 늘어납니다.

- T1>T2>T3이고 이진세마포어 S=1일 때 T3가P(S)로 임계 구역에 들어갑니다. T1이 도착해P(S)에서 막히면 T3가 실행되어 V(S)해야 합니다. 이때 자원이 필요 없는 T2가 T3를 선점하면 T1까지 늦어집니다.
- 우선순위 상속은 T1이 대기하는 동안 잠금 소유자T3에 T1의 유효 우선순위를 임시 부여합니다. 중첩된 잠금에서 는 상속이 대기 사슬로 전파될 수 있고 해제 시 남은 대기자와 원래 우선순위를 반영해 되돌립니다.
- 우선순위 천장 방식은 자원을 이용할 작업 중 최고 우선순위에 기반한 천장과 진입 규칙을 사용합니다. 획득 즉시 올리는 방식 등 변형이 있으므로 천장의 정의·상승 시점·진입 조건을 함께 씁니다. 짧은 임계 구역과 일관된 잠금 순서도 필요합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 상속 | 실제 고우선 대기가 발생하면 상승 | 동적 대응;PI chain 관리 |
| 천장 | 자원별 최고 우선순위 기반 제한 | 사전 이용 관계 분석 필요 |
| 단순 우선순위 | 실행 가능한 최고 작업 선점 | 잠금 의존성 자체 해결 못함 |

### 적용 예제

**세 작업의 P/V 순서**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** T1 높음, T2 중간, T3 낮음;모두 단일 CPU

1. T3:P(S) → 임계 구역 시작.
2. T1:P(S) → 대기.
3. T2가 실행되어 T3를 지연시키면 역전이 확대됩니다.
4. 상속 시T3를T1 수준으로 올려 임계 구역 완료 → V(S) → T1 재개.
5. T3의 유효 우선순위는 잠금과 대기 사슬 상태에 맞게 복원합니다.

**결과·해석:** 고우선순위 작업의 간접 차단을 제한합니다. 모든 종류의 지연과 교착이 자동 제거되지는 않습니다.

**전제·주의:** Linux rt_mutex의 실제 상속 구현은 확인했습니다. 천장 프로토콜의 모든 변형은 원표준 추가 확인 대상입니다.

### 답안 골격과 혼동 방지

실시간 응답 문제 → T1/T2/T3 시간축 → P/V 흐름 → 상속·천장 비교 → 블로킹 상한

- 낮은 작업이 자원을 가진 사실 자체를 모두 비정상이라 하지 않습니다.
- 상속을 영구 우선순위 변경이라 쓰지 않습니다.

### 내용을 가리고 회상

1. T2가 공유 자원을 쓰지 않아도T1을 늦추는 이유는 무엇입니까?
2. 상속을 언제 복원합니까?
3. 천장에 사전 자원 이용 정보가 필요한 이유는 무엇입니까?

### 적용 기준과 근거

명시한 출처 판본의 원리를 설명하며 제품별 구현 차이는 별도 확인합니다.

**내용 검토 상태: 부분 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [RT-mutex implementation design](https://docs.kernel.org/locking/rt-mutex-design.html) — Steven Rostedt / Linux Kernel; 2006 저작권 표기; 확인 2026-11-05. 확인 범위: 우선순위 역전·상속 및 PI chain에 관한 구현 설명 열람. 우선순위 천장 자체 원전은 미열람.
- [Lock types and their rules](https://docs.kernel.org/locking/locktypes.html) — Linux Kernel documentation; 상시 문서; 확인 2026-11-05. 확인 범위: sleeping/spinning lock, owner semantics, rt_mutex PI 절을 열람. 커널 내부 락의 제약과 일반 사용자 동기화 개념은 구분.
