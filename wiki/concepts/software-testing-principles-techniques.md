# 테스트 7대 원리와 기법 분류

## 서브노트

### 한눈에 이해

시험을 많이 한다는 말보다 무엇을 어떤 근거로 골라 시험했는지가 중요합니다.

### 정의와 핵심 원리

소프트웨어 테스트는 결함 발견·위험 감소·요구 충족 증거 확보를 위해 산출물을 평가하는 활동입니다. 동적 테스트는 실행을, 정적 테스트는 실행 없는 검토·분석을 사용합니다.

- 7대 원리는 ①결함의 존재를 보일 수 있으나 부재를 증명하지 못함 ②전수시험은 단순 사례 외 불가능 ③조기시험은 후속 비용을 줄임 ④결함은 특정 부분에 군집 ⑤같은 시험은 새로운 결함 발견 효과가 떨어질 수 있음 ⑥시험은 맥락 의존 ⑦결함 제거만으로 사용자 목적을 만족하는 것은 아니라는 오류부재의 궤변입니다.
- 블랙박스/명세기반 기법은 내부 구현보다 입력·출력·규칙을 근거로 동등분할·경계값·결정표·상태전이를 설계합니다. 화이트박스/구조기반은 제어·데이터 흐름을 분석해 문장·분기·조건 등 구조의 실행을 점검합니다.
- 경험기반은 오류추정·탐색적 시험·체크리스트로 숙련자의 지식을 활용합니다. 명세에 빠진 위험을 찾을 수 있지만 사람 의존성과 재현성 관리가 필요하므로 기록과 다른 기법을 결합합니다.
- 어떤 기법도 혼자 충분하지 않습니다. 위험이 큰 요구의 명세 테스트, 복잡 분기의 구조 커버리지, 운영 이슈를 반영한 탐색을 조합하고 결과를 요구·위험에 추적합니다. 반복 회귀시험은 새 결함 발견 효과가 줄어도 기존 기능 보호라는 가치가 있습니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 명세기반 | 사용자 관찰 가능한 규칙 | 누락·잘못된 기능과 경계 오류 |
| 구조기반 | 코드/설계 내부 흐름 | 실행되지 않은 문장·분기 |
| 경험기반 | 도메인 경험·휴리스틱 | 예상 밖 상호작용과 사용 위험 |

### 적용 예제

**강사 창작 적용 예시: 로그인 잠금 기능 시험**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 5회 연속 실패 시 잠긴다는 요구가 있습니다.

1. 실패 4·5·6회와 성공 시 초기화를 명세기반으로 시험합니다.
2. 잠금·해제·예외 분기가 실행됐는지 구조기반으로 점검합니다.
3. 시간변경·여러 탭·동시 요청을 탐색하고 재현 절차를 기록합니다.

**결과·해석:** 요구·내부 구조·현장 위험을 서로 보완합니다.

**전제·주의:** 계정 잠금 정책의 적정성 자체는 보안 요구와 사용 맥락에서 별도로 판단합니다.

### 답안 골격과 혼동 방지

테스트 개념·7원리 → 화이트/블랙박스 비교 → 명세·구조·경험 기법의 조합 사례

- 100% 문장 커버리지로 무결점을 주장하지 않습니다.
- 테스트 마모는 회귀시험을 버리라는 뜻이 아닙니다.

### 내용을 가리고 회상

1. 오류부재의 궤변을 사례로 설명하십시오.
2. 블랙박스와 화이트박스의 테스트 근거는 무엇입니까?
3. 경험기반 시험의 결과를 어떻게 재현 가능하게 합니까?
