# 멀티클라우드와 클라우드 관리 플랫폼

## 서브노트

### 한눈에 이해

여러 공급자를 쓰는 사실과 그 환경을 통제할 수 있다는 사실은 다르므로 공통 관리와 예외를 정합니다.

### 정의와 핵심 원리

멀티클라우드는 둘 이상의 클라우드 제공자의 서비스를 활용하는 구성입니다. CMP는 서로 다른 환경의 자원·배포·비용·보안·관측을 통합 관리하는 플랫폼이며 모든 제공자 기능을 완전히 동일하게 만드는 도구는 아닙니다.

- 도입 목적은 서비스 적합성·규제·지역·협상력·집중 위험 완화 등으로 명시합니다. 업무 분할·활성 복제·DR 등 구조에 따라 인증 연계·전용 망·DNS·데이터 복제·일관성·장애 상관·출구 비용의 요구가 달라집니다. 단순 분산이 독립성을 보장하지 않습니다.
- CMP 필수 기능은 자원 발견·목록, 계정·권한·정책, 프로비저닝·IaC, 비용 배부·예산, 성능·로그 관측, 보안 상태·준수, 백업·수명 관리 등입니다. 공통 최소 기능만 사용할지 제공자 고유 기능을 허용할지 운영 정책을 정합니다.
- 선정은 지원 API·가시성·정책 실행력·연동·확장성·플랫폼 자체 가용성·이관성·총 비용을 실제 시나리오로 검증합니다. 통합 관리자의 권한 집중과 비밀 저장소는 큰 공격 표면이므로 분리·감사·비상 접속을 설계해야 합니다.

### 구조·비교·판단

| 구분 | 핵심 원리 | 적용·한계 |
| --- | --- | --- |
| 멀티클라우드 | 여러 제공자 활용 | 도구·계약·기술 중복 |
| 하이브리드 | 서로 다른 배포 환경 결합 | 온프레미스·클라우드 경계 |
| CMP | 관리와 정책 통합 | 제공자별 기능 차이·관리 권한 집중 |

### 적용 예제

**두 CSP의 운영 통제**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 웹 서비스는 클라우드 제공자 A, 분석은 제공자 B에서 운영합니다. 비용·권한에 공통 정책을 적용합니다.

1. 공통 태그와 업무 소유자·데이터 등급을 정합니다.
2. 계정 연합과 최소 권한을 구성하되 제공자별 권한 모델 차이를 기록합니다.
3. CMP에서 미태깅·과다 권한·예산 초과를 찾고 실제 조치를 검증합니다.
4. 공급자 장애·CMP 장애 시 독립 운영과 복구 절차를 시험합니다.

**결과·해석:** 화면 통합보다 자원 책임·정책 실행·복구 가능성을 성과로 평가합니다.

**전제·주의:** NIST 클라우드 정의를 일반 배경에 사용했습니다. CMP 개별 제품 원문과 멀티클라우드 세부 규격은 확인이 남아 있습니다.

### 답안 골격과 혼동 방지

도입 목적 → 구조와 요구사항 → CMP 기능 → 선정 기준 → 이관과 운영비

- 특정 제공자에 대한 종속은 사용하는 API, 데이터 이동 비용, 이관 가능성을 따로 확인합니다.
- 모든 데이터를 동기 복제하는 설계를 기본값으로 두지 않습니다.
