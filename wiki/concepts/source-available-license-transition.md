# 오픈소스에서 소스공개 라이선스로의 전환

## 서브노트

### 한눈에 이해

코드를 볼 수 있는 것과 제한 없이 사용·수정·재배포할 권리는 다릅니다. 라이선스 변경은 이용 방식·버전에 따라 영향을 판단합니다.

### 정의와 핵심 원리

MIT/BSD 같은 허용적 라이선스는 조건을 지키면 폭넓은 이용·변경·재배포를 허용합니다. SSPL·BSL 전환은 소스를 계속 공개하더라도 사용 분야나 서비스 제공 등에 제약을 두는 소스공개 방식으로, OSI 승인 오픈소스와 구분해야 합니다.

- 배경은 개발·유지보수 비용을 부담하는 기업의 수익 확보, 클라우드 사업자의 관리형 서비스 경쟁, 기여/가치 환원의 불균형 인식과 상용 서비스 차별화입니다. 이는 변경 기업의 사업상 판단이며 오픈소스 모델 전체의 실패로 단정할 근거는 아닙니다.
- SSPL은 프로그램을 서비스로 제공할 때 서비스 운영에 필요한 관련 소프트웨어까지 공개하도록 요구하는 성격이 핵심입니다. OSI는 사용 분야의 자유 등 오픈소스 정의와 불일치를 지적했습니다. 단순 GPL/AGPL과 같거나 모든 내부 사용에 자동 공개의무가 생긴다고 일반화하지 않습니다.
- BSL1.1은 비운영 이용과 복사·수정·배포를 허용하되 운영 사용은 추가 사용허락에 따르며 Change Date 또는 최초 배포4년 중 먼저 도래한 시점에 Change License로 전환하는 구조입니다. 제품·버전마다 추가허락과 날짜가 다를 수 있습니다. HashiCorp는 경쟁 제품/서비스의 제공을 제한하는 허락을 설명했습니다.
- 영향은 공급자의 사업 지속과 투자 여력, 이용자의 비용/법무 검토·벤더 종속·보안패치 선택, 커뮤니티 신뢰·기여·포크, 클라우드 생태계의 경쟁/상호운용입니다. 대응은 SBOM·버전/라이선스 기록→사용·수정·배포·SaaS 방식 분석→허락/계약 확인→상용 전환·기존 버전·포크/대체의 비용·보안·이행성 비교입니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 허용적 오픈소스 | MIT/BSD 조건 아래 폭넓은 권리 | 저작권·라이선스 고지 등 준수 |
| SSPL | 서비스 제공 시 넓은 공개요구 | OSI 승인 오픈소스로 부르지 않음 |
| BSL | 추가허락·시간 후 다른 라이선스 | 버전·운영 이용·변경일 확인 |

### 적용 예제

**강사 창작 적용 예시: 관리형 서비스 제공사의 전환 검토**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 인프라 도구의 새 버전을 고객 SaaS에 포함하려 합니다.

1. 구성요소·버전·원래 조건·새 추가 사용허락을 수집합니다.
2. 내부 이용인지 경쟁 서비스 제공인지 계약상 범위를 검토합니다.
3. 상용계약·대체/포크의 패치·호환·전환 비용을 비교하고 결정을 기록합니다.

**결과·해석:** 최신 소스가 공개됐다는 이유만으로 배포·운영 가능성을 판단하지 않습니다.

**전제·주의:** 창작 검토 절차입니다. 개별 라이선스 적용의 법률 판단은 실제 문구·계약·사용방식을 확인해야 합니다.

### 답안 골격과 혼동 방지

배경·정의 교정 → MIT/BSD·SSPL·BSL 비교 → 공급자/사용자/커뮤니티 영향·대응

- 소스공개를 폐쇄된 비공개 소스와 동일시하지 않습니다.
- 미래 릴리스 조건이 이미 받은 구버전 조건을 자동 소급 변경한다고 쓰지 않습니다.

### 내용을 가리고 회상

1. source-available과OSI 오픈소스의 차이는 무엇입니까?
2. BSL의 Change Date와 추가 사용허락은 각각 무엇입니까?
3. 포크 선택에서 보안 유지보수를 확인할 이유는 무엇입니까?

### 적용 기준과 근거

2023 전환 발표와 BSL1.1·OSI 공식 입장을 확인했습니다. 제품별2026 현행 라이선스·기존 계약·법적 해석은 개별 확인이 필요합니다.

**내용 검토 상태: 출처 확인**. 출처 확인은 공식 정답이나 학습 성취를 뜻하지 않습니다.

- [The SSPL is Not an Open Source License](https://opensource.org/blog/the-sspl-is-not-an-open-source-license) — Open Source Initiative Board; 2021-01-19; 확인 2026-11-05. 확인 범위: 본문 또는 해당 절을 실제 열람했습니다. 자체 요약만 저장하며 외부 원문 전체는 보관하지 않습니다.
- [Business Source License 1.1](https://mariadb.com/bsl11/) — MariaDB; 1.1 공개 라이선스 본문; 확인 2026-11-05. 확인 범위: 사용권·Additional Use Grant·Change Date/Change License·판본별 적용을 실제 열람했습니다. 개별 제품의 추가 사용허락을 일반 BSL의 일률 조건으로 해석하지 않습니다.
- [HashiCorp adopts Business Source License](https://www.hashicorp.com/en/blog/hashicorp-adopts-business-source-license) — HashiCorp; 2023-08-10; 확인 2026-11-05. 확인 범위: 라이선스 변경 주체의 상업적 동기와 추가 사용허락 설명을 열람. 기업 입장과 OSI의 오픈소스 정의 판단을 구분합니다.
- [Server Side Public License v1](https://www.mongodb.com/legal/licensing/server-side-public-license) — MongoDB; 2018-10-16; 확인 2026-11-05. 확인 범위: 공개 라이선스§13의 서비스 제공·Service Source Code 범위와 기본 허락을 직접 열람했습니다. 특정 제품/서비스의 계약상 법적 판단은 별도입니다.
