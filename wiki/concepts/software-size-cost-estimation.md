# 소프트웨어 규모·비용 산정

## 서브노트

### 한눈에 이해

크기·노력·기간·비용은 서로 연결되지만 같은 단위가 아닙니다. 기능 규모를 구하고 생산성과 단가·조건을 적용해야 비용이 됩니다.

### 정의와 핵심 원리

규모 산정은 개발할 소프트웨어의 양을 일정 기준으로 측정·추정하는 활동이며 비용 산정은 규모·생산성·인력·환경·위험·경비 등으로 필요한 대가를 추정하는 활동입니다.

- 규모는 LOC, 기능점수(FP), 유스케이스점수, 객체/화면·보고서점수, 스토리포인트 등으로 추정할 수 있습니다. LOC는 구현 언어·생성코드에 민감하고 초기 추정이 어렵습니다. FP는 사용자가 인식하는 기능·논리데이터를 측정해 언어 독립성이 있으나 경계·유형·복잡도 판단 역량이 필요합니다.
- FP는 측정 목적·범위·경계를 정하고 내부논리파일(ILF)·외부연계파일(EIF), 외부입력(EI)·외부출력(EO)·외부조회(EQ)를 식별해 규칙에 따라 규모를 계산합니다. 화면 개수와 FP를 일대일로 같게 세지 않고 사용자의 단위 프로세스와 데이터 유지 여부를 따집니다.
- 비용 추정은 전문가 판단/Delphi, 유사사례, 상향식 WBS, 모수모형(COCOMO 등), 기능점수 단가 방식 등을 비교합니다. 전문가·유사는 빠르나 편향/비교 가능성, 상향식은 상세하나 초기 누락, 모수모형은 일관되나 보정 데이터 의존성이 있습니다.
- 공공사업은 해당 판본 가이드와 예산/발주 기준으로 개발비·보정·이윤·직접경비 등을 산정합니다. 기능 요구의 불명확성, 비기능·전환·데이터·통합·시험 과업의 누락을 줄이고 산정 근거·가정·변경 이력을 공유하며 독립 검토와 실적 피드백으로 개선합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| LOC | 코드 양 | 언어/개발환경 영향·사후 측정 용이 |
| FP | 사용자 기능 규모 | 경계·논리파일·단위프로세스 판단 |
| 공수/스토리포인트 | 노력/팀 내 상대 크기 | 기능규모와 단가를 혼동하지 않음 |

### 적용 예제

**강사 창작 적용 예시: 고객조회와 매출보고 규모 판단**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 조회는 저장 데이터를 그대로, 보고는 합계·세금 계산을 출력합니다.

1. 애플리케이션 경계와 논리 데이터 소유를 정합니다.
2. 추가 계산 없는 조회와 파생 계산 보고를 EQ/EO 규칙으로 구분합니다.
3. 측정 근거와 보정·단가의 판본을 기록하고 누락 과업을 점검합니다.

**결과·해석:** 화면 수가 아닌 기능 처리의 차이로 규모를 설명합니다.

**전제·주의:** 공식 산정 규칙의 복잡도·단가·보정계수는 해당 판본 원문과 실제 요구로 계산해야 합니다.

### 답안 골격과 혼동 방지

규모/노력/비용 구분·필요성 → 규모 방식·비용 추정 방식 장단점 → FP 절차·공공 현실적 개선

- 스토리포인트를 조직 간 고정 원화 단가로 환산하지 않습니다.
- 근거 없는 임의 난이도 가산으로 누락 과업을 감추지 않습니다.

### 내용을 가리고 회상

3. 상향식 추정에서 누락을 줄일 기준은 무엇입니까?
