# 레거시 역공학·재공학·재사용과 3R 확인 사항

## 서브노트

### 한눈에 이해

역공학은 현재 구현의 의미를 알아내고, 재공학은 그 이해를 바탕으로 다시 쓸 수 있는 형태로 바꾸는 작업입니다.

### 정의와 핵심 원리

역공학은 구현에서 설계·구조·요구 등 높은 추상수준의 정보를 복원하는 분석이며, 재공학은 기존 시스템을 조사·변환하여 새 형태로 재구성하는 유지보수 개선 활동입니다.

- 역공학·재공학·재구조화는 서로 구분되는 개념이며, 재구조화는 재공학에서 활용할 수 있습니다. 133-1-11이 지칭한 3R의 구성과 출전은 추가 확인이 필요합니다. 재사용(Reuse)은 검증된 코드·설계·컴포넌트를 다른 개발에 활용하는 것으로, 인터페이스·요구 적합성·라이선스·품질을 확인해야 합니다. 재구조화와 재사용을 같은 활동으로 보지 않습니다.
- 재공학은 대상 자산·업무 가치·위험 평가→문서/코드/데이터 이해→구조·자료·인터페이스 개선 설계→변환·재구성→동등성·성능·회귀 검증→전환·운영 안정화 순으로 계획할 수 있습니다. 목표에 따라 자동 변환과 점진 대체를 조합합니다.
- 역공학은 호출/의존 분석, 데이터·규칙 추출, 실행 추적과 아키텍처 복원으로 문서 없는 레거시의 영향분석·이관·보안 검토를 돕습니다. 분석만 수행하는 경우 시스템의 외부 행동을 바꾸는 활동은 아닙니다.
- 재구조화는 같은 추상수준에서 코드·데이터 구조를 정리하는 변환이고, 재공학은 플랫폼 전환·데이터 이관·업무 개선까지 넓어질 수 있습니다. 라이선스·영업비밀·개인정보·호환 계약, 원본 보존과 회귀 증거를 고려합니다.

### 구조·비교·판단

| 구분 | 원리·특징 | 적용·판단 |
| --- | --- | --- |
| 역공학 | 구현→추상 모델 복원 | 이해·영향분석·이관 준비 |
| 재구조화 | 동일 수준에서 구조 변환 | 코드/자료 구조 개선 |
| 재공학 | 분석과 변환을 통한 재구성 | 유지보수성·플랫폼 수명 연장 |
| 재사용 | 검증한 코드·설계·컴포넌트를 다른 개발에 활용 | 요구·인터페이스·라이선스·품질 적합성 확인 |

### 적용 예제

**강사 창작 적용 예시: 문서 없는 배치 시스템 이전**

강사 생성 학습 예제입니다. 공식 기준답안이 아닙니다.

**조건:** 정산 배치의 코드는 있으나 업무 규칙 문서가 부족합니다.

1. 실행 로그와 호출 그래프, SQL을 분석해 입력·정산규칙·출력을 복원합니다.
2. 중복 모듈과 데이터 구조를 정리하고 새 플랫폼으로 단계적으로 변환합니다.
3. 같은 입력에 대한 금액·건수·예외 처리 결과를 구/신 시스템에서 비교합니다.

**결과·해석:** 현행 의미를 잃지 않으면서 전환 위험을 통제합니다.

**전제·주의:** 기존 동작의 오류를 바로잡는 경우에는 동등성 검증과 별도로 요구 변경을 명시해야 합니다.

### 답안 골격과 혼동 방지

3R 정의·관계 → 재공학 목적과 절차 → 역공학 활용·검증·법적 고려

- 역공학만으로 새 구현이 완성되는 것은 아닙니다.
- 재공학이 항상 전면 재작성보다 싸다고 단정하지 않습니다.

### 내용을 가리고 회상

1. 역공학 산출물을 세 가지 말하십시오.
2. 재구조화와 재공학의 범위는 어떻게 다릅니까?
3. 잘못된 기존 규칙은 동등성 검증에서 어떻게 처리합니까?
